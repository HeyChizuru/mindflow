# 课堂问答的 Agent 编排边界

## Context

课堂讨论采用用户主动提问的课程问答形式：系统结合问题、发送时的场景与相关对话，从三名固定教师中选择一位回复；教师可以按需读取课程内容、检索本课资料，并在信息不足时补充查询。首版不包含同轮多教师发言、教师间交接或任务委派。

这条链路需要组织上下文、教师选择、工具调用、工具结果后的继续判断与结束条件。仅记录三份角色提示词，不能说明谁拥有调度权、工具访问权，以及图运行状态与已保存聊天之间的关系。

[ADR-001](./adr-001.md) 已规定单体部署且不含独立 Agent Worker，[ADR-002](./adr-002.md) 已规定 PostgreSQL 的持久化权威，[ADR-003](./adr-003.md) 已规定模型与检索配置边界，[ADR-004](./adr-004.md) 已规定依赖方向和生成、讨论不共享编排状态。本 ADR 在这些约束内记录问答编排的选型与权限，不替代课堂讨论 spec 的功能承诺。

## Decision

- **采用 LangGraph 组织课堂问答。** 用显式状态与受控分支组织上下文准备、教师路由、按需工具调用和本轮结束。模型可以在允许范围内选择教师、检索问题和下一次只读工具调用；应用规定可到达的步骤、工具集合与终止边界。首版按每轮一位教师的契约执行，不因采用编排框架扩展为自主多教师协商。
- **问答编排运行在服务端，与课程生成独立。** 每轮使用明确的课堂、问题与发送时场景作为依据，切场不改写该轮身份。浏览器负责聊天交互与播放衔接，不持有工具访问的最终裁决权。生成流程和问答流程可以复用模型、检索与数据查询能力，但不共享图运行状态或相互驱动；不新增独立 Worker 或持久任务队列。
- **模型输出是待校验的决策，应用负责规则执行。** 教师选择必须属于固定角色集合；工具名称与参数、课堂归属、场景就绪情况、测验提交状态及可返回内容均由应用校验。课堂内容与 PDF 片段作为资料使用，不能改变系统权限。未提交测验的隐藏答案、完整解析与评分依据不能仅依靠提示词约束访问，应在上下文准备和工具返回内容中执行相同边界。
- **教师工具只读，业务保存由应用完成。** 教师可按需获取本课课程与场景内容、检索本课资料；不能借工具修改课程、播放位置、正式作答或成绩。消息保存、完成状态与引用关联由应用校验并写入；模型声称“已保存”或提供一个来源标识，不构成保存成功或引用归属的依据。模型及向量调用继续经过统一领域封装，LangGraph 不另起绕过 ADR-003 的提供商访问与密钥管理路径。
- **执行边界由应用强制落实。** 图步骤、工具循环、补充检索、外部调用与失败重试均有有限边界；达到边界或发生不可恢复错误时明确结束本轮，不依赖模型自愿停止。已有结果先恢复，失败按 spec 由用户显式重试，普通读取不启动新一轮执行。具体上限及重复请求、晚到结果的协调方式由后续实施方案确定，不将测验单元的执行期限直接复用为问答常量。
- **已保存聊天与图运行状态分开承担职责。** PostgreSQL 中已保存的问题、完整回复、教师身份、所属场景与引用是聊天恢复的事实来源。图运行状态用于组织本轮执行；会话摘要与筛选历史是生成上下文的衍生信息，不能覆盖原始消息、伪造完成状态或放宽资料访问权限。图运行结束或客户端收到文本，不等于完整回复已经保存成功。
- **是否引入持久化 checkpoint 留待方案设计。** 本 ADR 不预先选定 checkpointer、图状态存储结构或摘要持久化方式。若引入 checkpoint，其持久化仍须遵守 PostgreSQL 边界，并明确它与业务消息的一致性、恢复和密钥排除规则；不得由此形成另一套聊天事实来源，或在普通读取时自动续跑。是否采用 checkpoint 不改变首版只承诺恢复已保存聊天、不承诺图执行断点续跑的范围。

## Consequences

- 教师路由、工具选择与资料补查具有明确的运行归属，后续能分别检查模型选择是否合理、应用是否正确执行访问与结束规则。
- 引入 LangGraph 会增加图状态、模型决策校验、工具错误处理和调用次数管理的维护成本；采用框架本身不证明教师选择、引用或回答正确，仍须按课堂讨论 spec 验收。
- 按需检索允许课程解释直接使用已有上下文，需要资料时再获取；无知识库、配置缺失、检索失败与无相关结果仍按 ADR-003 和 spec 区分，不以框架默认行为改变产品规则。
- 聊天保存与回复生成跨越外部模型调用，需要在后续方案中明确同轮身份、重复请求、保存结果不明和晚到回复的处理，不能以进程内图状态替代持久化协调。
- 节点划分、工具定义、上下文预算、模型适配、执行上限数值及是否使用 checkpoint 属于后续方案；本 ADR 不提前确定接口、表结构或施工顺序。
- 若未来增加可写工具、跨课堂记忆、教师间交接、普通读取时自动续跑，或独立 Worker，需要重新评估本 ADR 与相关 spec；涉及部署或持久化权威变化时，还须复核 ADR-001、ADR-002。

## Alternatives considered

- **普通条件路由加直接模型调用。** 可以满足简单的教师选择，但本课还需要结合对话状态进行工具调用、观察结果和有界补查。采用该路线需要自行维护这些执行关系；本次选择由 LangGraph 统一表达，不作为主要编排方案。
- **固定的“检索一次，再生成回答”流程。** 适合检索路径固定的资料问答，但不能完整表达本次按需读取场景、选择检索问题与补查的目标，不作为所有问题的统一流程。
- **完全自主的 Supervisor 与多教师协商。** 会引入同轮任务分派、交接、结果汇总及额外执行成本，超出已确认的每轮一位教师范围，首版不采用。
- **只依赖提示词限制工具权限与停止条件。** 不能作为课堂归属、测验答案访问、正式数据写入或执行上限的最终裁决方式；这些规则由应用校验执行。
- **将图 checkpoint 或摘要直接作为聊天恢复来源。** 会混淆执行进度、衍生上下文与完整业务消息的职责，不采用；checkpoint 的引入不能替代已保存聊天记录。
