# 代码依赖方向

## Context

逻辑分布在浏览器和服务端，不是全部落在服务端。服务端提供可复用的底层能力（存储、模型、知识库等）。`app/api` 把这些能力组织成一次请求的流程。生成与课堂讨论不共用编排状态。

## Decision

- 依赖单向：类型定义不引用服务、校验或数据库；数据查询不处理 HTTP。
- 可复用的服务端能力放在领域模块。`app/api` 可以编排这些能力（调用顺序、本请求的步骤、错误映射），不要求 Route 变成空壳。
- 同一条规则若要在多处复用，放进被调用的服务，避免在多个 Route 里各写一份。
- 播放、草稿和交互状态可以留在浏览器，不强制下沉到服务端。
- 模型调用经对话与知识库模块，Route 不绕过封装直接请求第三方。未排期能力默认不暴露入口。

## Consequences

- 大纲 SSE 等 Route 里的流程组织可以保留；抽出的是可复用规则，不是把 API 清空。
- 鉴权等横切能力另开 ADR，不在单个 Route 里复制一套。

## Alternatives considered

- Route 禁止任何业务、全部下沉领域层：与「API 组织底层能力」不符，不作为硬规则。
- 全部逻辑放在浏览器：持久化与密钥边界做不到，拒绝。
