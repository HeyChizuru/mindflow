# 测验提交与评分并发

## Context

课堂测验允许学习者主动重做，但当前版本只恢复每道题最近一次成功保存的答案和批改结果，不提供历史尝试或独立学习档案。多个页面可能基于同一份记录提交；简答批改还会跨越数据库事务调用外部模型，遇到并发请求、客户端断开或服务进程重启时，必须能辨认当前答案、批改执行者和迟到结果。

ADR-002 已规定 PostgreSQL 是唯一持久化事实来源，ADR-003 规定模型配置来自当次请求，ADR-001 规定当前部署形态不含独立 Worker。本 ADR 将这些边界具体应用到课堂测验的提交与评分生命周期。

## Decision

- 每个场景中的每道题只保留一条当前提交记录。新提交首次创建记录；用户主动重做时，只有基于当前版本且新答案成功保存后才替换它。不追加历史尝试。
- PostgreSQL 中的当前记录是答案、批改状态和结果的权威来源。写入使用提交身份与预期版本作条件校验；同版本并发修改只有一个成功，其余请求必须读取最新记录后再操作。同一提交身份的相同请求可恢复已有结果，不同答案不得复用该身份。
- 逐题提交、选择题判分、简答批改与显式重试统一由 `POST /api/quiz-grade` 承担，不拆成前端依次调用的“保存答案”和“请求批改”。选择题答案与判分结果一同保存；简答先保存答案，再在数据库中取得本次批改执行权，随后才调用当次请求提供的模型配置。批改结果只能写回其所属的提交和执行身份，不能覆盖更新的记录。
- `GET /api/classroom` 等普通读取只恢复已保存状态，不触发批改。简答失败保留已保存答案；只有用户显式重试原提交或提交重做答案，才发起新的批改执行。当前实现使用 PostgreSQL 持久化执行状态和有界执行期限；具体时限与 Route 运行上限以本单元后端 task 为准，不在本 ADR 中固定为跨功能常量。

## Consequences

- 多页面竞争、重复请求和服务进程重启后，服务端仍可从同一条持久记录判断答案版本与批改执行状态；旧执行结果不能取代新答案。
- 当前模型不支持查询历史答案、尝试次数或按学习者区分记录。若产品需要这些能力，须重新讨论数据生命周期并设计相应迁移，不能把当前行静默改成历史记录。
- 并发正确性依赖数据库条件写入、事务和执行身份校验；浏览器状态或进程内互斥只能改善交互，不能替代数据库约束。
- 若未来改为独立队列／Worker、读取时自动续跑批改，或保存多次尝试，应重新评估本 ADR，并同时核对部署与数据存储决策。

## Alternatives considered

- 每次作答都追加一条历史记录：当前功能明确不提供历史尝试和学习统计，因此不采用；若产品范围改变，再设计历史模型。
- 只用浏览器或进程内锁协调提交：无法作为多请求和进程重启后的持久协调依据，与 PostgreSQL 权威数据边界不符，不采用。
- 由独立 Worker／队列异步批改，或在普通读取时自动重试：当前单体部署和本单元确认的一次请求提交／批改流程不需要该复杂度；失败恢复由用户显式触发，不采用。
