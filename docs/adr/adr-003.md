# 外部服务边界（LLM / RAG）

## Context

文本生成与向量化各自走用户自带的 OpenAI 兼容端点，可以不是同一提供商。创建课堂不调用模型。有 PDF 时检索是可选增强，没有知识库时讨论仍须能进行。

## Decision

- 不在服务端用环境变量兜底。对话与向量各自由当次请求携带 Key、端点与模型名。缺哪一套，只拒绝用到那一套的调用。
- Chat 与 Embedding 分头解析，互不代替。对话配置不能充当向量配置，反之亦然。模型调用经统一封装，Route 不直接请求第三方 URL。
- 仅在该课堂已有知识库时检索；否则返回空引用，不报错。检索使用向量配置，生成使用对话配置。
- 不做：服务端代管多用户 Key、联网搜索、多厂商配置中心。

## Consequences

- 无 PDF、未配置向量模型时，建课与大纲生成只凭对话配置即可完成，不检索、不报错。讨论在没有知识库时仍须能进行。
- 未配置对话模型时，生成失败。未配置向量模型时，只有入库失败；知识库已就绪但当次请求没有向量配置时，依赖检索的生成也失败。界面须先引导设置。
- 生产环境须分别拒绝指向内网或云元数据的端点；本地开发可连本机推理。
- 环境变量示例若仍写服务端 Key，是文档漂移，须与本决定对齐，不改变决定本身。
- 换成非 OpenAI 兼容协议时，替代本 ADR。

## Alternatives considered

- 服务端 `.env` 统一 Key：方便运维，但与「用户自带 Key、密钥不进仓库」冲突，拒绝。
- 对话与向量共用一套 Key 和端点、只拆模型名：无法使用不同提供商，拒绝。
