# 产品意图

## 一句话

MindFlow 面向自学者与培训场景：用户填写**必填的课程提示词**、**可选的昵称与背景**、**可选上传 PDF** 作为参考资料后，系统生成由幻灯片与测验组成的结构化互动课程；用户可在课堂中观看讲稿字幕、完成测验，并主动展开右侧聊天窗口，围绕当前课程与场景问答，由系统从三名固定教师 Agent 中选择一位回复。无 PDF 时由模型依据提示词生成内容；有 PDF 时在入库后，大纲与问答可结合文档检索。生成过程与结果持久保存在 PostgreSQL；**确认大纲前**为可恢复的**草稿课堂**，**确认大纲后**视为本课**定稿**。生成页只生成第 1 个场景（幻灯片内容与含讲稿的 actions），然后进入播放页；其余场景在播放页后台续生成。

## 给谁

- **自学者**：输入「我想学 XX」等需求，无教材也能生成可播放课程；有 PDF 时讨论可引用原文片段。
- **教师 / 培训者**：用提示词定教学目标与风格，可选上传讲义 PDF，生成带测验的课堂。
- **开发者（展示 / demo）**：需要一条可演示的全栈路径（生成、播放、讨论、可选 RAG），用于作品集或技术验证。

## 首个可交付功能集

配置模型（顶栏设置）→ **开始生成**（建立草稿课堂：课程需求 + 可选昵称与背景 + 可选 PDF）→ 若有 PDF 则在生成页完成入库 → 在生成页流式生成课程大纲 → 手改并**确认大纲（定稿）** → 仍在生成页只生成第 1 个场景（幻灯片内容 + 含 speech 讲稿的 actions，不合成语音）→ 进入播放页：按该场景的 actions 播放 slide / quiz（含简答批改），用户可展开右侧聊天，针对课程与当前场景提问，由系统选择教师回应（使用 PDF 资料时附带真实文档引用）→ 其余场景在播放页后台续生成 → 通过刷新或持有课堂 id 再次进入，仍可恢复草稿或已定稿课堂的已保存内容。

课堂问答由用户发起，不生成或执行 `discussion` 教学动作。三名固定教师分别负责概念讲解、理解与思路检查、应用实践；首版每轮由一名教师回复，支持按需获取课程信息、资料检索及会话记忆，不包含同轮教师交接或委派。展开聊天暂停正在进行的讲解，收起后由用户手动继续；具体契约见「课堂讨论」spec。

## 明确不做

**产品能力（当前版本不提供）**

- Pro 幻灯片编辑、TTS / ASR、AI 图 / 视频生成
- PDF 图片提取、模型视觉输入、白板专用能力（PDF 文本入库与检索继续保留）
- interactive / PBL 场景类型、联网搜索
- 课堂 zip / PPTX 导入导出、复杂 Roundtable UI
- 多 Provider 大型设置面板（MVP 使用精简设置弹窗）
- autonomous 模式、跨标签页编辑锁

**编排与 Agent 平台**

- OpenMAIC Pro Agent Runtime（如 pi-agent-core、持久化 Workbench Session）
- Agent 人设自动生成（`agent-profiles` 等）
- **M2+** 大纲编辑助手（Tool Chat 侧栏改大纲）
- **Phase 2** 冻结 Plan、Planner / Drafter / Critic / Director 评审闭环、`replan`、Plan 表格与 Round 评审 UI

**边界说明**

- 不在首个功能集中承诺「以后 Phase 2 / M2+ 会接」的能力；当前演示路径须完整走通，无需口头补洞。



## 页面

只有三个页面：

- **首页** `/`：填写课程需求并建立草稿课堂；「历史课堂」提供当前部署全部课堂的卡片列表、按进度再次进入、搜索、折叠、重命名与删除，包含未完成生成的课堂。详细规则见其 [spec](./features/历史课堂/spec.md)，已实施的范围、验证与限制见 [交付记录](./features/历史课堂/plan.md#交付记录2026-10-30)。
- **生成页** `/generation-preview/[id]`：入库进度、流式大纲、手改。确认大纲后只生成第 1 个场景：幻灯片内容，以及含 `speech` 讲稿的 actions。不在这一页续生成其余场景，也不做语音合成。
- **播放页** `/classroom/[id]`：按已生成场景的 actions（含 `speech`）播放讲稿、完成测验，用户可主动展开右侧聊天进行课程与场景问答。进入后在本页后台续生成其余场景。播放与测验、课堂讨论、后台续生成分别由对应功能单元交付；具体契约见各单元 spec。

## 主路径

1. 进入首页，填写课程需求（必填），可选填写昵称与背景，可选上传 PDF。
2. 点击**开始生成**：系统建立草稿课堂并进入生成页（此次不调用模型；有 PDF 时仅保存原件与元数据）。
3. 若上传了 PDF，在生成页完成文档入库并看见明确的处理进度。
4. 在生成页看见大纲流式生成；可在定稿前手改大纲标题、描述、要点，并调整顺序、增删场景。
5. 在生成页**确认大纲（定稿本课）**，并在同一页只生成第 1 个场景：幻灯片内容，以及含 `speech` 讲稿的 actions。播放依赖这些 actions，不是一张静态幻灯片。
6. 进入播放页：按第 1 个场景的 actions 播放 slide / quiz，并完成测验（含简答批改）。其余场景在播放页后台续生成。
7. 在播放页主动展开右侧聊天并提问，由系统结合问题及上下文选择讲解老师、思考教练或应用教练回复；每条问题以发送时的场景为依据。若回答使用本课 PDF 知识库资料，应展示真实文档引用；无 PDF 时仍可问答。收起聊天后手动继续讲解。
8. 刷新页面或再次打开课堂链接，仍可访问草稿与已定稿课堂的已持久化内容；失败时展示可理解的错误信息并允许重试。「历史课堂」补充首页直接查找与再次进入的入口，按该单元已确认的规格推进交付，不改变确认前大纲不持久化的边界。



## 怎样算成功

- 目标用户按上述主路径能**独立完成**从建课到播放、讨论的核心任务，演示时**无需**解释「这里以后会接」。
- **无附加 PDF** 与 **提示词 + 可选 PDF** 两种输入模式均可走通。
- 有 PDF 且入库成功时，课堂讨论应能展示引用来源；无 PDF 时仍可基于课程与提示词讨论，且不假装有文档引用。
- 重新进入后，已持久化的课堂、场景与聊天等数据仍可恢复（对齐「恢复测试」：刷新或再次进入不丢已保存进度）。
- 具体耗时、比例类指标在功能规格与验收证据中定义，不在本文展开。
