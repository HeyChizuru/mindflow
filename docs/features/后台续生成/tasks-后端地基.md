# 阶段一：后端地基

依据 [spec](./spec.md) 和 [plan 阶段一](./plan.md#阶段一后端地基)，实施用户已确认的后端 task。补齐播放页读取的生成依据，复用并验证单场景内容、动作生成及完整场景保存、恢复；本阶段不实现前端续生成调度或 UI。

## 当前基础与改动范围

- 现有课堂读取已返回课程需求、可选学习者信息、知识库情况、定稿大纲、完整场景、目录和全部就绪判断；缺少已保存的授课语言指令。
- 现有内容、动作接口已支持指定目标，动作接口负责组装、完整性校验及保存。场景唯一约束与并发恢复已有实现，按 B2～B4 验证，不重建接口或存储。
- 本阶段源码改动限定为 `lib/types/classroom.ts`、`lib/validators/classroom.ts`、`lib/services/classroom.ts`。不新增生产源码文件，不修改数据库结构、状态推进、播放、测验或模型设置流程。

## 实施任务

### B1 — 补齐课堂读取契约

- 在 `ClassroomReadResponse` 的 `ready` 分支中，为 `classroom` 增加必填的 `languageDirective: string | null`。
- 同步 `classroomReadResponseSchema`，字段必须存在，允许字符串或 `null`，不使用默认值替代缺失字段。
- `getClassroom` 从同一次只读事务读取的课堂定稿中返回原有语言指令，不生成、不规范化改写。
- 课程需求、可选学习者信息、知识库情况和大纲继续使用已有字段。调用方从紧邻上一场的已保存动作按顺序提取讲稿，学习者信息复用 `formatUserProfile`。
- 草稿、首场未就绪及错误响应保持原有形状；复用既有课堂读取，不新增专用接口或请求封装。

验收映射：BG-1、BG-3、BG-7 的读取与恢复数据基础。

### B2 — 验证通用单场景生成

- 验证第二场幻灯片与后续测验可使用现有接口生成；服务端拒绝跨课堂目标以及需求、大纲、语言和学习者信息与定稿不一致的输入。
- 内容接口仅返回内容，不保存半成品或调用动作接口。动作接口使用课程位置及前序讲稿，生成、校验并保存完整场景，返回的讲稿只来自本场并保持顺序。
- 请求某一目标只处理该目标，不自动生成前后场景、不修改播放位置；不增加首屏／后台标记，不把串行调度放到服务端。

验收映射：BG-3、BG-4；为 BG-2 的前端调度提供基础。

### B3 — 验证保存、恢复与完成判断

- 已保存目标再次请求内容接口沿用冲突响应，通过课堂读取恢复；动作接口遇到已有完整目标时直接返回保存结果，不重复调用模型。
- 验证真实数据库的同目标并发保存只保留先成功的完整结果，其他调用恢复该结果，不覆盖或产生第二条记录。
- 保存失败不报成功；丢弃成功响应后仍可通过读取恢复。读取失败返回错误，不伪装成目标缺失。
- 目录与 `allScenesReady` 按定稿及完整场景计算，覆盖仅首场、部分完成、全部完成和目录中间存在缺口。
- 不新增进度表或生成指针，不修改 `Stage.status`、`outlinesStatus` 或数据库结构。

验收映射：BG-4、BG-8、BG-10，以及 BG-6、BG-7 的结果核对基础。

### B4 — 验证模型与知识库边界

- 无知识库只要求当次请求的对话配置；知识库就绪时，内容生成需独立向量配置检索本课资料。动作请求保留现有配置契约。
- 缺配置、检索失败、模型失败或输出截断、内容无效、缺讲稿或动作目标失效时，不保存半成品；错误响应不泄露密钥或堆栈。
- 普通读取不要求模型配置，不触发生成、批改或位置写入。

验收映射：BG-4、BG-9，以及 BG-6 的后端错误基础。

## 验证方式与交付边界

- 使用专用验证课堂；受控验证调用真实 Route、服务、校验与 PostgreSQL，仅替换模型／检索返回值及需要注入的故障点。
- 真实 HTTP 验证复用现有本地服务，按 `mindflow-api-test` skill 通过 UTF-8 文件与 `curl.exe` 发送 JSON；对话配置由测试调用方读取并放入当次请求，不改变服务端配置规则，不保存到文档。
- 真实链路覆盖首场、第二场幻灯片、三类测验、逐场读回、重复请求和恢复；回归课堂读取、位置保存和选择题提交。
- 验证后清理本轮专用课堂和临时代码，不删除已有用户课堂，不新增测试框架，不运行 `pnpm build`。
- 运行三个改动文件的 ESLint、全仓 TypeScript 与差异空白检查；全仓存在既有错误时，对比改动前后诊断，分别报告原有问题与新增问题。
- 静态、受控、真实 HTTP／模型／数据库结果和未覆盖项分别记录。后端验证不代替自动触发、串行循环、页面失败重试、离页停止及不打断播放的阶段二验收。

### 受控 Route 与真实数据库验证

18 组检查全部通过。直接调用真实 Route、服务、生成解析、校验与 PostgreSQL；模型和检索输出受控，读取／保存异常通过临时故障注入验证，不将这些检查标为真实模型或真实检索成功。

- 读取与依据：草稿及首场未就绪响应形状、就绪响应完整依据、语言指令有值／为 `null`、缺失字段与错误类型被拒绝；读取不调用模型。

- 重复与恢复：已保存目标内容请求返回 409，动作请求恢复已有场景且不调用模型；忽略保存返回后仍能重新读回。真实数据库并发保存只保留同一目标的一份完整结果，竞争调用恢复同一 id 与内容。
- 错误隔离：篡改需求、大纲、语言、学习者信息及跨课堂目标被拒绝；缺对话配置、仅带向量配置、空内容、缺讲稿、失效动作目标、模型调用失败和截断输出不增加完整场景。
- 读写异常：注入保存失败返回 500，注入读取失败返回 `READ_FAILED`，不存在课堂返回 404，不把错误转成场景缺失。
- 完成与配置：全部目标就绪、只有首场、目录中间有缺口时的完成判断正确；有知识库时要求独立向量配置，检索摘录进入生成提示词，检索失败不保存目标。
- 回归：首场仍可通过通用接口生成并恢复，位置保存和单选／多选判分、答案读回保持可用。生成不推进课堂状态或改写播放位置。
