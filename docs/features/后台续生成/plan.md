# 后台续生成：实施计划

依据 [spec](./spec.md)，按 **后端地基 → 前后端打通 → UI 与交互细节完善 → 集中审查与 Bug 修复** 推进。每阶段进行针对性验证，第四阶段再集中检查跨模块问题并验收整个单元。

本 plan 只说明阶段目标、范围、依赖、交付顺序与验收映射，不提前展开具体文件、接口、表结构或操作步骤。进行到对应阶段且用户要求时，再结合当时代码编写该阶段 task。撰写 plan 不代表开始实现，也不改变 spec 的审查或交付状态。

## 现有基础与主要缺口

- 首屏单元已提供按指定定稿目标生成内容、生成动作、校验并保存完整场景的通用能力，以及重复请求和并发保存时恢复已有结果的基础。本单元复用这些能力，核对并补齐后续场景所需的实际缺口。
- 播放单元已提供课堂读取、定稿目录、完整场景、全部就绪判断及内容更新合并能力。续生成需要的完整生成依据尚未衔接，例如已保存的授课语言指令。
- 播放页尚未接入本单元的串行调度、失败重试、离页停止与生成状态展示。现存并行批量生成流程不符合本 spec，不直接作为续生成主流程。
- 当前播放引擎会随当前场景变化而重新建立；接入新增场景时，要保持未变化场景及当前播放状态，防止内容更新导致重播、暂停状态丢失或作答输入被清除。

以上为规划时的静态代码核对，不代表真实续生成链路已通过验收。实施时重新核对现有能力，已有符合 spec 的部分不重复建设。

## 阶段一：后端地基

目标：播放页能可靠取得续生成依据，现有单场景生成能力可以支撑后续场景的生成、完整保存与恢复。

依赖：本单元 spec 与阶段范围已确认；首屏生成及课堂读取的现有契约可作为复用基础。

范围：

- 补齐本课堂已保存需求、定稿大纲、授课语言与可选学习者信息的读取衔接，并区分草稿、首场未就绪、不存在、读取失败及已全部就绪。
- 核对通用内容与动作生成能力对后续场景的支持，包括定稿与归属校验、课程位置和前序讲稿，以及按需模型配置与知识库检索；只补实际缺口。
- 核对完整场景的校验、保存和读回，以及重复请求、并发保存、响应丢失后的恢复能力。内容或动作返回但未确认保存成功时，不计为就绪。
- 核对以定稿目标对应的完整场景判断生成进度和全部完成的能力，不以播放位置或页面计数代替保存事实。

阶段交付：后端具备支撑后续场景真实生成、保存与读回的能力；已有完整结果不被覆盖，失败与结果待确认可以区分，普通读取不触发生成。单场景生成的验证结果与尚待页面联调的部分分别记录。

验收映射：BG-1 的数据读取与前置状态部分、BG-3 的生成依据与服务端校验、BG-4、BG-8、BG-9 的服务端部分，以及 BG-6、BG-7、BG-10 所需的保存结果恢复与完成判断基础。

## 阶段二：前后端打通

目标：用户观看已有场景时，剩余场景能按顺序逐场生成、逐场可播放，失败与恢复形成可操作的闭环。

依赖：阶段一的读取、生成、保存与恢复契约已具备，首屏及播放的既有行为保持可用。

范围：

- 接通播放页进入后的读取与自动触发，从最早缺失场景开始串行生成，跳过已有完整场景。同一页面避免重复启动，播放暂停和切场不改变生成顺序。
- 由前端选场并依次请求内容和动作生成；使用紧邻上一场的已保存讲稿，按课堂知识库情况准备当次请求配置，不依赖上次页面内存。
- 每场确认完整保存后更新内容与目录，再处理下一个缺失场景；保留当前讲解、暂停状态、教学效果、答题输入及已存结果，不自动切场。
- 接通失败停止与手动重试。重试前核对保存结果，已有完整目标直接恢复并继续；读取失败不当作场景缺失，结果不明时先恢复事实再决定是否生成。
- 接通刷新与再次进入后的恢复、离页后的后续调度停止，以及切换课堂后旧请求结果的隔离。已发服务端请求可能完成保存，不将浏览器取消当作保存撤销。
- 提供基本的生成阶段、目标、数量、失败提示、重试和重读入口；全部场景就绪时停止调用。基本操作与反馈随真实流程交付，展示细化留到下一阶段。

阶段交付：在真实课堂上跑通从首场播放到其余场景逐场就绪的主路径；失败、重试、刷新和再次进入可恢复，新增内容不干扰已有播放与作答。只有首场及全部已就绪的课堂不再生成。

验收映射：BG-1～BG-10 的核心行为；同时回归「课堂播放与测验」CP-5、CP-12，核对切场限制与内容更新不打断当前学习。该阶段不以单次接口成功代替完整流程验证。

## 阶段三：UI 与交互细节完善

目标：续生成状态和恢复操作清楚可理解，与播放、测验界面协调，符合项目视觉与可访问性要求。

依赖：阶段二的真实生成、恢复及状态反馈已接通，页面状态能够对应实际保存结果。

范围：

- 完善已就绪数与总数、当前生成目标，以及「内容生成」「动作生成与保存」两个阶段的展示，清楚表达待生成、生成中、失败与全部完成。
- 完善失败场景、失败阶段和原因的文案，按真实状态提供手动重试或重新读取入口，避免用户误判保存结果。
- 处理续生成提示与播放提示、位置保存及测验反馈的共存，避免遮挡画布、字幕与作答操作，不因状态更新切场或重播。
- 核对深浅主题、窄屏、键盘操作和非颜色状态表达；生成完成提示与课程末页、作答完成提示保持各自语义。

阶段交付：主要生成状态与恢复操作可审阅、可操作，进度表达对应数据库中的完整场景，提示不阻塞观看或作答。展示样例只用于覆盖难以稳定出现的状态，不替代真实行为证据。

验收映射：BG-5、BG-6、BG-7、BG-9、BG-10 的界面反馈部分，以及 spec 非功能约束。

## 阶段四：集中审查与 Bug 修复

目标：系统检查续生成与原有课堂能力的交互，修复本单元问题并按 spec 验收。

依赖：前三阶段已交付，真实主路径和主要页面状态具备可核对结果。

范围：

- 对照 BG-1～BG-10 审查实现与验证证据，覆盖幻灯片、三类题目、有无知识库、缺配置、只有首场及全部已完成等情况。
- 集中核对内容或动作失败、检索与校验失败、保存失败、响应丢失和恢复读取失败；区分真实链路验证与受控异常验证。
- 检查重复触发、连续点击重试、多页面竞争、生成中刷新或离页、切换课堂及迟到响应，确认不覆盖已有完整结果、不重复计数、不污染其他课堂。
- 检查新增内容时的播放连续性、暂停状态、教学效果、未提交输入与已存测验结果；按受影响范围回归首屏生成、播放、切场及作答恢复。
- 修复发现的 Bug，并对修复涉及的行为做针对性回归；需要改变功能承诺或边界时先对齐文档，不借审查扩展功能。

阶段交付：形成 BG-1～BG-10 的验收结果、问题修复结果和未覆盖项记录。真实页面、模型调用及数据库读回证据分别可核对；静态检查或部分链路通过不替代全单元验收。

验收映射：BG-1～BG-10 及 spec 非功能约束，并记录首屏与课堂播放、测验相关行为的回归边界。

## 实施约束与任务展开

- 前端负责目标选择、跨请求顺序和本页面的续生成生命周期；后端负责本次请求的实际模型调用、检索、校验与完整场景保存。复用通用生成能力，不另起后端整课调度或前端单独保存步骤。
- PostgreSQL 是唯一持久化事实来源。按完整场景恢复，不新增半成品持久化、持久任务历史、独立队列或 Worker；不复用播放位置作为生成指针。
- 只支持已约定的 `slide / quiz`。不修改定稿，不重生成已就绪场景，不扩展真实 Agent 讨论、模型设置界面、媒体或语音能力。
- 读取和已有内容消费独立于生成模型可用性；模型配置来自当次请求，知识库按需检索，密钥不进入文档、课堂或场景记录。
- 每阶段都做与改动相称的检查和验证。遵守仓库测试约束，不默认运行 `pnpm build`，不为本单元堆积测试文件；临时测试代码用完删除。
- 进入相应阶段且用户要求时才编写 task，列清该阶段具体改动、实现步骤、验收映射与禁止范围；spec、plan 和阶段 task 对齐后再实施。
- 实际进度、验证结果与未覆盖项记入阶段 task 或交付记录。本 plan 说明路线，不充当完成证明；交付状态按真实验收证据更新。
