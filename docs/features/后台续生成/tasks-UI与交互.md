# 阶段三：UI 与交互细节

依据 spec、plan 阶段三及用户确认的阶段三、四方案。采用目录内显示：进度、目标和阶段放入左侧目录，主区域保留失败提醒和恢复操作。

## U1：目录与状态表达

- 修改 `components/stage/scene-sidebar.tsx`，透传可选生成状态和恢复回调，在目录标题下显示数据库目录计算的就绪数、目标及阶段；目标条目显示阶段或失败，其他缺失条目仍待就绪。
- 修改 `components/stage/classroom-status.tsx`，提供目录状态、主区域失败提醒和单一礼貌播报；复用 Alert、Button、Badge、Separator，不估计耗时或模型进度。
- 修改 `lib/hooks/use-i18n.ts` 补齐简短阶段、恢复和完成文案，完成不等于观看或测验完成。

验收映射：BG-5、BG-6、BG-9、BG-10。

## U2：布局与恢复操作

- 修改 `components/stage/classroom-view.tsx`，移除主区域常驻生成卡片，失败、播放和课程结束提示共用最高 30dvh 的滚动容器。
- 目录和主区域恢复入口使用相同回调，重试时先读取，运行时隐藏重复操作入口；目录折叠不隐藏主区域错误。
- 目录关闭时如焦点在内部则归还目录开关；为工具栏开关增加稳定标识，状态播报位于折叠目录之外，不抢焦点。
- 深浅主题使用已有语义色，处理长文本、窄屏、键盘和减少动态效果；不改变播放、作答、API 或持久化规则。

验收映射：BG-5～BG-7 及非功能约束。

## U3：验证与交付

- 核对 1440×900、390×844、844×390 两种主题下运行、失败、读取和完成，以及多个提示并存。
- 验证目录折叠与键盘焦点归还、恢复入口和状态非颜色表达；真实流程与受控展示分别记录。
- 运行改动范围 ESLint、定向类型和差异检查；不运行 build，临时代码用完删除。完成后进入阶段四并据实际问题写 task。
