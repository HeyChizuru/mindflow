# 后台续生成

2026-10-25：此前四阶段交付及 BG-1～BG-10 的验收证据见 [最终验收记录](./验收记录.md)，静态、受控和真实链路的边界分别记录。此后按已确认的课堂问答方向取消 `discussion` 动作生成；旧证据不覆盖该变更，新行为及本次用户确认见 [MVP 验收记录](../../MVP验收记录.md)。本单元交付状态为 verified，规格审查状态仍为 draft。

## 承诺

课堂已由「确认大纲并生成首屏」定稿并保存完整首场。用户进入播放页 `/classroom/[id]` 后，系统读取本课定稿大纲与已保存的完整场景；仍有未就绪场景且生成配置满足时，在播放页内自动续生成其余场景，用户可以同时观看已有内容。草稿或首场未就绪时不启动续生成，保留返回本课生成页的入口；课堂不存在或读取失败时明确提示，读取失败允许重试。全部场景已就绪时不再调用生成模型，包括只有首场的课堂。

续生成由播放页前端按定稿大纲顺序组织。同一页面一次只生成一个场景，从最早缺失的场景开始，跳过已保存的完整场景；本场保存成功或确认已有完整结果后，再处理下一个缺失场景。生成顺序不随播放位置、播放暂停或用户选择的已就绪场景改变，不要求用户先看完前一场。

生成依据为本课已保存的课程需求、已确认大纲、授课语言指令与可选学习者信息，不重新生成或改写定稿。每场动作生成使用定稿顺序中紧邻的上一场已保存讲稿，按该场讲稿顺序提供上下文；恢复续生成时同样从已保存场景取得，不依赖上次页面内存。未填写昵称、背景或授课语言指令时不编造相应内容。

前端选择目标大纲，先请求通用场景内容接口，再携带内容和前序讲稿请求动作接口。两个后端接口分别执行本次请求的实际生成，不决定下一场，不接收首屏 / 后台来源标记。内容接口返回中间内容，不保存半成品场景；动作接口生成动作，组装、校验并保存完整场景，保存成功或读到目标已有完整场景后才返回成功，前端不另发保存请求。服务端校验生成依据与本课堂定稿一致，目标属于该课堂，不允许跨课堂混用内容。

完整性沿用「确认大纲并生成首屏」的场景契约：幻灯片包含画布元素及其位置、样式与文案；单选和多选题包含题目、选项、正确答案与解析，简答题包含题目、参考解析与评分依据，不要求选项或预设答案；场景还须包含可按顺序播放的动作，其中包括讲稿。缺少对应必填内容、讲稿或动作校验失败时，不保存为已就绪场景。讲稿是字幕文字，不合成语音；不生成 `discussion` 动作，课堂问答由用户在播放页主动发起。

界面展示已就绪场景数与总场景数、当前生成目标，以及「内容生成」「动作生成与保存」两个阶段。就绪数包括首场，以数据库中的完整场景为依据；模型已返回内容或动作但尚未确认保存成功时，不增加就绪数。每场完整保存后即更新播放页内容与目录，无须等待整课完成。更新及失败提示不重播、暂停或切换当前场景，不清除作答输入与已存结果；新场景由用户按播放单元的规则主动选择。

任一场景生成、校验或保存失败后，本页面停止后续场景的生成，展示目标场景、失败阶段和可理解的原因，并提供手动重试入口，不自动循环重试。保留本课定稿及全部已保存场景，不回滚、不清空、不覆盖。重试前先读取已保存结果：目标已有完整场景时直接恢复并继续；仍缺失时可重新执行该场景的内容与动作生成，成功后继续后续场景。响应丢失或保存结果不明时，先核对数据库再决定是否重试；读取失败时不得把目标当作未保存而直接重新生成。

对话与向量配置各自包含 Key、端点与模型名，只来自当次请求，互不代替，不读取服务端环境变量兜底，不把密钥保存到课堂或场景。无知识库时只要求对话配置；知识库已就绪时，场景内容生成按现有规则使用向量配置检索本课资料，再用对话配置生成，不把文档全文送入提示词、不编造文档引用。缺配置、检索失败或模型不可用时，明确提示并允许在配置满足或故障恢复后手动重试，不阻塞已有内容的播放与其他可用课堂操作。模型设置界面由「配置模型」负责。

本单元的「后台」指播放页内与观看并行的异步流程。离开本课播放页、切换到其他课堂或关闭页面后，停止发起后续生成请求；已经发出的服务端请求可能继续完成并保存，不承诺浏览器取消即可撤销模型调用或数据库写入。旧页面返回结果不得更新其他课堂。刷新或凭课堂 id 再次进入时重新读取，配置满足则跳过已保存场景，从最早缺失处自动继续；本次页面内失败后，仍按手动重试规则处理。

持久恢复的对象是完整场景，不是尚未保存的模型输出、请求执行位置或任务历史。当前生成阶段与失败提示属于本次页面状态，不要求刷新后恢复，也不因页面已离开而把未保存场景标成正在生成。相同页面的重复触发或重复点击不得启动并行的续生成流程；多个页面可能同时调用模型，但同一课堂同一目标只保留一份完整场景，以首先成功保存的结果为准，其他调用恢复该结果，不覆盖已有内容。不承诺跨标签页模型只调用一次。

只有本课定稿大纲中的每个目标都已有完整场景，才显示「全部场景生成完成」并停止续生成。完成依据可从数据库恢复，不以播放位置、本地计数或某次请求结束代替。生成完成不代表到达课程末页、完成全部测验或掌握课程；相关提示由「课堂播放与测验」按其契约判断。

## 非目标

- 不在生成页续生成，不补生成或重生成首场；首场未就绪时由「确认大纲并生成首屏」负责。
- 不重新生成、编辑或排序大纲，不重生成、覆盖或编辑已保存完整场景与讲稿。
- 不实现播放引擎、切场与播放位置保存、测验判分或真实 Agent 讨论；只交付新增完整场景及续生成状态，不改写学习记录。
- 不提供独立 Worker、持久任务队列、定时调度或关闭浏览器后持续生成整课的保证，不改变单体 Next.js 部署形态。
- 不提供半成品场景持久化、模型输出断点恢复、持久任务历史或失败记录列表，不提供无限自动重试或跳过失败场景后继续生成的流程。
- 不提供跨标签页编辑锁或模型调用恰好一次的保证。
- 不提供模型设置界面、登录或首页历史列表；不代管用户密钥。
- 不解析 PDF、重新入库或向量化，不提取 PDF 图片、不使用视觉输入，不提供语音合成、语音识别、AI 图 / 视频、白板、interactive 或 PBL 场景。
- 不提供幻灯片编辑、导入导出、联网搜索、Tool Chat、Plan 蓝图或评审闭环。

## 验收

- BG-1 WHEN 用户进入播放页，THE SYSTEM SHALL 先读取本课堂定稿及完整场景；首场已就绪、仍有缺失场景且配置满足时自动续生成。草稿或首场未就绪时不启动续生成，并提供返回本课生成页的入口；课堂不存在或读取失败时明确提示，读取失败可重试，不以读取失败当作场景缺失。
- BG-2 WHEN 本页面启动或继续续生成，THE SYSTEM SHALL 按定稿顺序从最早缺失场景开始，一次只处理一个场景，跳过已有完整场景；当前目标保存成功或恢复到已有完整结果后才处理下一目标。切场、暂停播放或重复触发不改变生成顺序，也不在同一页面启动并行生成流程。
- BG-3 WHEN 生成后续场景，THE SYSTEM SHALL 使用本课已保存需求、定稿大纲、授课语言与可选学习者信息，由前端选场并依次请求内容和动作接口；动作生成携带定稿顺序中紧邻上一场的已保存讲稿。刷新恢复时同样取得该上下文；服务端拒绝目标不属于本课或依据与定稿不一致的请求，不改写定稿、不混用不同课堂内容。
- BG-4 WHEN 内容及动作生成完成，THE SYSTEM SHALL 按首屏相同契约校验对应幻灯片或题型内容、讲稿与动作，不生成 `discussion` 动作，由动作接口保存完整场景后才返回成功，前端不另发保存请求。只有内容、缺少必填项、动作无效或保存失败时不得标为就绪，不留下可播放的半成品场景。
- BG-5 WHEN 续生成推进、某场保存成功或失败，THE SYSTEM SHALL 展示已就绪数与总数、当前目标和生成阶段；每场完整保存后及时更新播放页内容与目录，无须整课完成。不打断或重置当前讲解，不自动切场，不清除作答输入或已存结果，已有场景继续可用。
- BG-6 WHEN 当前目标的生成、检索、校验或保存失败，THE SYSTEM SHALL 停止本页面后续生成，说明目标、失败阶段与原因，并允许手动重试，保留定稿和此前完整场景。重试前先核对已保存结果，已有完整目标直接恢复并继续，仍缺失时重试该目标，成功后继续；不自动循环重试，不跳过失败目标。
- BG-7 WHEN 用户刷新、离开或再次进入本课播放页，或某次生成响应丢失、保存结果不明，THE SYSTEM SHALL 以数据库中的完整场景恢复进度，不重新生成已保存场景。离页后停止发起后续请求，已发请求可能完成保存，旧页面结果不更新其他课堂；再次进入并成功读取且配置满足时，从最早缺失处自动继续。核对结果读取失败时先提示并允许重读，不直接重新生成；不要求恢复未保存输出、请求执行位置或上次失败提示。
- BG-8 WHEN 重复请求或多个页面同时生成同一目标，THE SYSTEM SHALL 在同一课堂同一目标下只保留一份完整结果，以首先成功保存的场景为准，其他调用读取恢复，不覆盖已有场景，不重复增加就绪数。该保证针对保存结果，不承诺多个页面只发起一次模型调用。
- BG-9 WHEN 续生成需要模型或检索，THE SYSTEM SHALL 仅使用当次请求分别提供的对话与向量配置。无知识库时不要求向量配置；知识库就绪时用向量配置检索本课再生成，不发送文档全文、不编造引用。缺配置或相关服务不可用时明确提示并允许手动重试，不影响已有场景读取与播放，不将密钥写入课堂或场景。
- BG-10 WHEN 定稿大纲中的全部目标均已有完整场景，THE SYSTEM SHALL 展示全部场景生成完成并停止生成；刷新或再次进入可恢复这一结果，不再调用生成模型。只有首场且已完整保存的课堂同样适用；仍有缺失或未确认保存的场景时不得宣称全部生成完成，生成完成不代替课程末页或作答完成判断。

## 系统不变量

- 本单元只补齐本课已定稿大纲中首场之后的缺失场景；不修改定稿，不覆盖已有完整场景。
- 生成顺序来自定稿大纲，与当前播放位置分离；同一页面一次只生成一个场景，失败停止后续生成。
- 前端负责选场与跨请求调用顺序；后端接口负责本次请求的实际生成，动作接口负责完整场景组装、校验与保存。通用接口不承担下一场调度。
- 场景类型只有 `slide` 与 `quiz`，内容、题型与动作完整性沿用首屏契约；内容返回不等于场景已保存。
- PostgreSQL 是定稿及完整场景的唯一持久化事实来源；浏览器存储只能作草稿或界面缓存，不作为生成成功、缺失或整课完成的依据。
- 就绪数量按本课定稿目标对应的完整场景计算，包括首场；重复响应、并发保存或跳过已有场景不重复计数。
- 恢复以完整场景为单位，不保证未保存输出、生成阶段、失败提示或执行历史跨刷新保留。
- 新场景与续生成状态更新不改变当前播放、作答输入、已存答案、得分或播放位置。
- 离开播放页停止后续调度，不保证撤销已发请求，不保证关闭浏览器后继续生成。
- 对话和向量配置互不代替，只来自当次请求；不读服务端环境变量兜底，不保存密钥到课堂或场景。
- 不写 Plan 蓝图，不另建第二套课堂内容存储。无登录，持有课堂 id 即可访问该课；服务端仍校验课堂归属与定稿依据。

## 非功能约束

- 生成过程与错误反馈不阻塞已有内容的观看和作答；重试入口可用键盘操作，状态不只靠颜色表达。
- 错误信息须可理解，不包含堆栈、密钥或敏感请求头，并提供相应重试或重读入口。
- 不以模型输出长度、等待时间或本地进度估算冒充已保存场景数，不承诺固定生成耗时。
