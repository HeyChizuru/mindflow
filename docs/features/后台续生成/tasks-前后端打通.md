# 阶段二：前后端打通

依据 [spec](./spec.md)、[plan 阶段二](./plan.md#阶段二前后端打通) 及用户确认的 F1～F4 方案。在播放页串行补齐定稿中的缺失场景，支持恢复与手动重试，保留当前讲解和作答；视觉细化留在阶段三。

## 文件与实施顺序

### F1 — 通用请求与独立控制器

- 修改 `lib/client/generate/stage-generation.ts`，提供通用内容／动作生成命名，保留首屏兼容导出。
- 新增 `lib/client/generate/background-generation.ts`，通过注入的课堂快照、读取、请求配置和状态回调组织续生成；不保存第二套课堂内容。
- 在 `lib/types/stage-generation.ts` 定义浏览器内的生成状态，区分待启动、读取、内容、动作与保存、失败和全部完成，保留目标、失败阶段和恢复入口。
- 修改 `lib/hooks/use-classroom.ts`，按知识库情况传入内容请求配置，动作与简答批改只取对话配置；沿用现有临时头来源。

验收映射：BG-3、BG-4、BG-9；首屏调用兼容。

### F2 — 串行生成与恢复

- 修改 `lib/client/classroom-session.ts`，承接控制器生命周期、最新读取与生成状态。首次有效读取后自动启动，只处理最早缺失的后续场景；动作上下文只取紧邻上一场的已保存讲稿。
- 同页一次一个循环，内容后请求动作，保存后重新读取课堂并更新目录，再处理下一目标。过期读取跟随最新读取，不覆盖最新内容；循环只消费已应用的有效快照。
- 生成请求失败后核对一次保存结果，目标已完整保存则恢复并继续；仍缺失则停止等待手动重试；读取失败时只提供重读入口。
- 重试先读数据库；普通刷新／重新可见不绕过失败状态触发模型。全部已就绪时直接完成，不调用模型。

验收映射：BG-1、BG-2、BG-6～BG-10。

### F3 — 生命周期与学习状态保护

- 使用运行身份及 AbortController 隔离重复启动、离页、切课与开发模式再次挂载；旧响应及旧循环的清理不得影响新运行。
- 保留现有场景对象复用、当前场景和播放运行编号，更新不重播、不自动切场；答题版本保护、草稿、重做及已存结果沿用现有逻辑。
- 不新增轮询、跨标签页锁、后端调度或数据库字段，多页竞争恢复后端唯一完整结果。

验收映射：BG-5、BG-7、BG-8，以及 CP-5、CP-12。

### F4 — 基础反馈与验证

- 修改 `components/edit/PlaybackChromeRoot.tsx`、`components/stage/classroom-view-types.ts`、`components/stage/classroom-view.tsx` 透传状态及恢复操作。
- 在 `components/stage/classroom-status.tsx` 复用 Alert／Button 增加独立生成提示，不覆盖播放、位置和测验提示；文案进入 `lib/hooks/use-i18n.ts`。
- 显示真实就绪数、总数、目标和两个生成阶段；失败显示阶段、原因及重试／重读按钮，运行中不重复操作。完成提示不替代课程末页。
- 受控检查覆盖成功、失败、竞争、刷新恢复、取消与迟到响应；浏览器检查播放、暂停、切场和作答状态保留。真实模型／HTTP／数据库验证与受控证据分别记录。
- 运行改动范围 ESLint、定向类型与差异检查，全仓结果对照阶段一既有错误。临时验证代码用完删除，不运行 `pnpm build`。

验收映射：BG-1～BG-10 的核心行为和非功能约束。

沿用现有后端接口与存储，不修改首屏范围或整课状态推进。现有服务证书问题仍属于真实 HTTP 验收限制；没有浏览器完整链路证据时不标为已验证。实施结果及未覆盖项在下方记录，不将受控数据等同真实模型与数据库成功。

## 交付记录

### 2026-10-23：F1～F4 实施

- F1：新增独立的 `BackgroundGeneration`，状态只在本次页面内保存；通用生成方法保留首屏兼容导出，内容按知识库情况组装请求头，动作和简答批改只取对话配置。
- F2：课堂有效读取后自动启动串行循环，每场保存后重新读取课堂。过期读取返回最新有效读取的结果，避免旧内容覆盖新目录；失败核对一次数据库结果，未保存或读取失败时停下并等待显式操作。
- F3：生成循环用运行身份与取消信号隔离。同页重复触发不启动第二个循环；旧请求返回及旧循环清理不影响新运行。沿用场景对象复用与答题版本保护，不调整播放位置或播放运行编号。
- F4：新增独立生成提示，与原有播放／位置／测验提示分别保留；进度来自有效课堂目录，文案进入现有 i18n。没有新增后端接口、存储表、轮询或模型设置流程。

### 静态与受控检查

- 10 个阶段二源码文件的 ESLint 通过；控制器、会话、请求封装、hook、共享类型及基础状态组件的定向 TypeScript 检查通过。
- 全仓 TypeScript 仍为阶段一记录的 37 条既有错误，涉及旧浏览器存储和缺失的 `shiki` 等依赖；未出现阶段二新增诊断。没有为清除这些问题扩大修改范围。
- 差异空白检查通过，未运行 `pnpm build`。临时验证脚本及类型配置用完删除。
- 18 组受控检查全部通过，使用真实客户端请求封装、运行时响应校验和课堂会话，替换 `fetch` 的响应；这些检查不作为真实模型或 PostgreSQL 成功的证据。

受控覆盖：

1. 串行生成第二场及后续场景，上一场讲稿按顺序传入，保存后刷新就绪数；首屏兼容导出引用同一实现。
2. 只有首场、全部已完成、草稿和首场未就绪不调用生成。
3. 内容／动作失败停止后续目标；普通刷新不自动重试；重复点击重试只启动一个循环。
4. 动作已保存但响应丢失时读取恢复；内容冲突时恢复其他页面保存的场景，不重复生成或计数。
5. 保存后读取失败提供重读入口；恢复读取持续失败时不把结果当作缺失重新生成。
6. 中间存在缺口时只补缺失场景，不重生成后面已保存目标。
7. 离页／再次启动隔离旧内容响应和旧循环清理；迟到动作响应不继续生成下一目标。
8. 过期读取无论成功或失败均跟随最新读取，不回滚最新目录或返回假缺失结果。
9. 内容更新保留当前场景对象、播放运行编号、未提交输入、重做草稿与已存记录；读取开始后的新提交不被旧读取覆盖。
10. 知识库相关配置只用于内容请求，动作与简答批改仅使用对话配置。

### 浏览器、真实 HTTP／模型／数据库联调

- 复用原有 3001 服务，通过内置浏览器打开专用课堂 `6bdb8dc5-6412-4f67-8a54-040588ecdf75`；仅首场测验为预置验证内容。播放页自动生成第二场幻灯片和第三场测验，实际经历 4 次真实模型调用及后端完整保存，目录依次从 1/3 更新到 2/3、3/3。
- 生成期间将首场暂停并填写未提交简答，同时提交单选题。生成完成后页面仍停留首场且保持暂停，简答输入完整保留，单选反馈为 2/2 分；没有自动切到新场景或显示到达课程末页。
- 主动进入新生成的第二场后返回首场，简答草稿与选择题重做草稿仍保留。页面刷新后恢复已保存场景和单选结果，并直接显示全部生成完成；未提交草稿按既有契约不跨刷新恢复。
- PostgreSQL 读回确认：三条完整场景，第三场包含单选、多选、简答三类题目；单选提交记录为 `completed`、得分 2。该专用课堂及其关联记录在验证后清理。
- 浏览器页面无本轮控制器错误。保留一张生成完成、首场仍暂停及重做输入保留的画面作为审阅附件。
- 本轮原有 HTTP 服务主路径成功，说明本次联调期间可用；未改变服务的 CA 或 TLS 配置，不能据此宣称阶段一观察到的证书信任问题已修复。
