# 课堂播放与测验：实施计划

依据 [spec](./spec.md)，按 **只读源码复用盘点 → 范围清理 → 后端适配 → 前端静态 → 前端行为适配与联调** 推进。以 OpenMAIC 源码为参照，尽可能复用符合本项目需求的能力。

本 plan 只说明阶段目标、范围、依赖和交付顺序，不提前确定具体改动文件、接口、表结构或操作步骤。当前需求与交付状态以 spec frontmatter 和各阶段任务／交付记录为准。

## 阶段一：只读源码复用盘点

目标：明确引入源码分别支撑哪些验收项、带入哪些依赖，以及需要保留、适配或排除的范围。

范围：

- 从课堂入口追踪播放外壳、播放引擎、动作执行、场景分发、幻灯片渲染和测验交互的实际依赖链；尚未接入的源码单独标记，不为补齐它们继续导入。
- 清单记录 MindFlow 路径、可核对的 OpenMAIC 来源、关联 CP、依赖文件、与本项目的冲突、结论及理由；来源不能确认时标为待核实。
- 结论分为“保留、适配、排除”。按职责判断，允许同一文件包含不同结论；缺失依赖先判断是否支撑验收，再确定是否需要补齐或替换。
- 区分本项目明确不做的能力、归其他单元的能力与必须保留的共享基础。不因文件命名或当前能否运行直接决定去留，不预设核心引擎只需小幅调整。

阶段交付：可审阅的复用清单、主路径依赖关系和待解决问题。每个 CP 均能找到相关能力或明确缺口；“排除”是盘点结论，不是已经删除。清单经用户审阅后，才据此展开清理或适配任务。

验收映射：CP-1～CP-13 的能力与依赖盘点。本阶段不完成任何运行验收，不修改代码或 spec。

## 阶段二：范围清理

目标：按已审阅清单收窄播放调用链，留下后续可适配的课堂播放与测验骨架。

依赖：阶段一清单与本阶段改动范围已对齐。

范围：

- 清理本项目明确不做的功能入口、执行分支及其专属依赖，保留幻灯片展示、动作执行和测验交互需要的共享能力。
- 解除本单元对真实讨论、后台续生成等其他单元运行能力的依赖，保留 spec 要求的讨论提示与后续场景消费边界。
- 对存储、音频、编辑等与必需能力混合的代码，区分待替换部分与可复用部分；完整的数据接入、字幕推进与交互改造留到后续阶段。

阶段交付：清理范围与依赖变更可核对，必需能力未因排除其他功能而被一并移除；原有缺失依赖、待适配问题与本阶段引入的问题分别说明。不以删除行数或页面暂时显示作为完成标准。

验收映射：围绕 CP-1～CP-13 收窄依赖，并落实 spec 非目标；此阶段不宣称播放、保存或批改已经完成。

## 阶段三：后端适配

目标：播放页所需的课堂读取、位置保存、测验判分及恢复能力符合 MindFlow 的数据与业务约束。

依赖：清理范围已稳定，盘点中影响后端的复用与替换边界已明确。

范围：

- 读取本课堂的定稿结构、完整场景、已保存播放位置与答题记录，区分草稿、内容未就绪、不存在及读取失败。
- 保存有效播放位置；支持单选、多选的服务端判分，以及简答答案保存、模型批改、结果保存与失败重试。
- 完成逐题提交、主动重做、重复提交、多个页面竞争提交与旧批改结果的处理；以最近一次成功保存的提交及其状态、结果为恢复依据。
- 落实课堂、场景、题目和选项的归属校验，拒绝客户端指定评分标准或得分；基础读取与选择题判分独立于模型和知识库可用。

阶段交付：后端能提供真实读取、保存、判分和恢复结果，并区分各类失败；保存成功才视为成功，批改失败不冒充零分或成功。并发、重做和恢复约束在本阶段考虑，不留到页面联调时补设计。

验收映射：CP-1、CP-5 的数据与位置部分，CP-6～CP-11 的服务端部分，以及 CP-12 的后续场景读取、CP-13 的归属与判分边界。

## 阶段四：前端静态

目标：复用适合的页面和渲染结构，确认播放与测验所需的展示和操作状态。

依赖：后端数据与状态边界已明确，必需渲染依赖的处理方向已确定。

范围：

- 准备目录、画布、字幕、播放控制、三类测验及反馈展示，沿用项目视觉与交互规范。
- 准备加载、不可播放、内容未就绪、场末与课程末页，以及保存失败、待批改、批改失败、重做和取消等状态。
- 检查深浅主题、窄屏、主要键盘操作和错误提示；样例内容只用于展示检查，不代替真实保存或判分结果。

阶段交付：主要页面和状态可审阅、可演示，符合 spec 的功能范围；静态展示不表示播放引擎、真实请求或持久化已接通。

验收映射：CP-1～CP-12 的页面展示与操作状态，以及 spec 非功能约束。真实行为在下一阶段验收。

## 阶段五：前端行为适配与联调

目标：在真实课堂数据上打通进入、播放、切场、作答、重做和恢复，按 spec 验收整个单元。

依赖：后端能力和前端静态状态已具备，影响主路径的必需依赖已处理。

按功能闭环逐步交付：

1. **进入与内容展示**：接通真实课堂读取与异常状态，展示完整幻灯片、题目和定稿目录。
2. **播放与切场恢复**：适配自动播放、字幕阅读节奏、暂停继续、下一段、重播和教学动作；切场后从头自动播放，场末停留，刷新恢复已保存位置。
3. **测验与答题恢复**：接通逐题提交、选择题反馈、简答批改、失败重试、主动重做与取消；核对最近一次提交、多个页面冲突及保存失败时的页面行为。
4. **内容更新与结束状态**：验证新场景就绪不打断当前播放或作答、未就绪和续生成失败不影响已有内容，以及课程末页的正确提示。

阶段交付：逐片核对真实页面与持久化读回结果，再按 CP-1～CP-13 验收完整功能。无模型配置时基础播放和选择题仍可用；示例数据、静态展示或单次请求成功不能代替完整验收。

后台续生成与课堂讨论尚未交付时，可用已保存完整场景验证消费与播放行为；真实续生成和 Agent 对话接入的跨单元结果另行记录，不以本单元完成代替整条产品主路径完成。

验收映射：CP-1～CP-13 及 spec 非功能约束。

## 实施约束与任务展开

- PostgreSQL 是唯一持久化事实来源；浏览器保留播放与交互状态，不承担课堂和答题记录的权威保存。
- 正式判分、归属校验和保存由服务端负责；简答模型调用使用项目统一封装和当次请求的对话配置。
- 复用代码须服从 spec，不为运行原项目而引入其完整编辑、音频、讨论、媒体或生成体系。
- 播放、真实讨论与后台续生成分别负责各自流程；本单元不生成或改写大纲、场景、讲稿，不承担其他单元的调度。
- 进行到对应阶段且用户要求时，才编写该阶段 task；结合已审阅盘点和当时代码列清具体文件、实现步骤、验收映射与禁止范围，不提前展开全部阶段。
- spec、plan 和当前阶段 task 对齐后再实施。若盘点发现需要调整需求或交付路线，先说明影响并对齐相应文档。
- 实际进度、检查结果和未覆盖项记录在对应 task 或交付说明中；本 plan 不充当完成记录。
