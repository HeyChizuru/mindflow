## 现有基础与缺口

本节保留规划时的静态核对，以下缺口已在四阶段实施中处理；当前实现和证据见末尾交付记录。

- 已有服务端建课和按 id 读取能力，课堂、定稿大纲、完整场景、播放位置、测验和聊天分别已有持久化与恢复契约；无需迁移旧课堂到浏览器历史或重新生成内容。
- 目前尚无首页所需的全量历史查询、跨全部记录的标题搜索、计数、轻量预览和重命名能力。列表阶段与可进入状态应复用已有定稿、首场和完整场景规则，不凭单个状态标签推断就绪。
- 已有课堂删除入口：先在数据库事务内删除关联资料与课堂，再删除 PDF 目录。现有流程在数据库删除成功、文件清理失败后，再次删除会因课堂不存在提前结束，不能直接满足部分清理反馈与重试要求。
- 数据库关联删除能作为复用基础，但不能单独证明所有在途入库、场景生成、聊天、批改和文件写入均不会留下或重建数据；需针对实际写入路径核对并补齐缺口。
- 首页现有布局以固定视口和建课区内部滚动为主。加入卡片网格后，需要重新安排首页的滚动与内容高度，保证建课、历史和窄屏操作都能到达。
- 已有幻灯片展示基础可供复用，但首页预览必须与播放状态隔离，不挂载讲解流程、不暴露测验答案，也不能把所有课堂的完整内容一次下载到首页。

以上是本轮静态文档与代码核对，不代表列表、管理、并发删除或浏览器效果已验证。实施时重新核对现有能力，符合 spec 的部分直接复用。

## 路线与阶段依赖

阶段一先提供可靠的读取与管理能力，并完成删除范围和在途写入的针对性检查；阶段二据此接通可操作的首页闭环；阶段三完善参考图对应的卡片、布局及交互；阶段四集中核对全部验收与跨模块回归。

采用**分批读取并提供「加载更多」入口**的展示方式；搜索由服务端覆盖全部记录，切换关键词时重新取得对应结果与数量。实施使用每批 9 条、创建时间与课堂 id 共同排序的游标读取，不改变全部课堂可到达的承诺。

## 阶段一：后端地基

当前状态：已完成，历史读取与管理、完整删除、真实文件占用和晚到写入检查通过。

目标：形成可供首页使用的历史摘要、搜索、再次进入判定、重命名和永久删除能力，数据范围与结果恢复符合已确认规格。

依赖：spec 已确认，本 plan 及阶段范围经用户确认；核对创建课堂、定稿与首场、课堂播放和相关数据生命周期的现有实现。

范围：

- 提供跨全部未删除课堂的历史读取、标题搜索、稳定排序与真实总数、匹配数量；支持分批取得记录，上线前创建的课堂也可直接读取。
- 以已保存定稿与完整场景生成轻量摘要，统一页数、阶段与首场预览口径；测验预览只提供允许展示的内容，不返回答案、解析或个人作答。
- 复用课堂读取与校验规则判断生成预览或播放落点，区分未定稿、首场未就绪、可播放、记录不存在及数据异常；点击时可重新核对当前状态。
- 提供符合 1～100 字符规则的重命名、持久化读回及失败或结果未知后的核对能力；只更新课堂名称。
- 补齐永久删除的完整关联范围、数据库与文件清理的结果区分、重复请求与部分清理失败后的核对和重试能力。课堂记录已删除时，仍能如实反馈并处理未完成的文件清理，不能把文件失败当成整课尚未删除。
- 对入库、生成、聊天、批改和位置保存核对课堂存在性、归属与晚到写入；必要的保护必须在服务端生效，删除成功后不得重建记录或文件，也不要求外部模型立即终止。
- 所有读取和管理独立于模型配置，沿用既有依赖方向、错误脱敏与受控内容规则。

阶段交付：后端读取与管理能力可被调用并读回核对；各持久化阶段可正确分类，删除关联数据、文件部分失败与在途写入已有针对性证据。此阶段不交付首页界面，不把已有删除入口等同于新规格已满足。

验收映射：HC-1～HC-5、HC-7～HC-11 的后端部分；为 HC-2 的安全预览与 HC-3、HC-4 的页面恢复提供事实依据。

## 阶段二：前后端打通

当前状态：已完成，真实列表、搜索、按进度进入与管理闭环已接通，未知结果先读回核对。

目标：在首页完成真实历史读取、搜索、折叠、再次进入、重命名与删除的基础闭环，不使用假数据或浏览器记录替代服务端事实。

依赖：阶段一的读取与管理能力可用；删除范围、部分清理恢复和在途写入保护通过针对性核对后，才开放首页删除操作。

范围：

- 接入初次进入与返回首页时的读取、分批加载、真实数量和各类加载、空态、失败重读状态；历史区域不阻塞建课。
- 接通覆盖全部课堂的标题搜索与默认收起的折叠区域；关键词改变、继续加载、重新读取与管理操作之间隔离旧响应，防止重复、遗漏或已删除卡片重新出现。
- 点击卡片时依据当前服务端事实进入生成预览或播放页，使用既有恢复流程；缺少模型配置时仍能读取已有内容，目标已删除或数据异常时明确反馈。
- 接通重命名的编辑、取消、校验、提交中、结果核对与重试；新名称同步参与搜索，保存后不再匹配时更新当前结果与数量。
- 接通永久删除的独立二次确认、取消、提交中、成功、部分文件清理和未知结果反馈，允许按实际结果核对与重试；不凭本地移除卡片宣称清理完成。
- 保证卡片导航与管理入口互不误触，操作始终以课堂身份定位；已有建课草稿、个人资料与模型设置不受管理操作影响。

阶段交付：首页真实数据与管理流程已连通，可按课堂阶段完成再次进入；基础确认和错误恢复可用。此阶段的界面只需支撑真实操作，卡片精修与完整视觉验证留在阶段三。

验收映射：HC-1、HC-3～HC-11 的前后端闭环，并初步核对 HC-2 的信息与 HC-12 的基本可操作性。

## 阶段三：视觉与交互完善

当前状态：已完成，参考卡片布局、静态预览、深浅主题与 390px 窄屏、键盘焦点已核对。

目标：按参考图形成清晰、可读的历史课堂区域，同时保留 MindFlow 品牌、主题和建课操作体验。

依赖：阶段二已能完成真实读取、进入与管理；预览来源、时间、页数和状态口径沿用已确认 spec。

范围：

- 完善建课区下方的历史标题、数量、搜索与折叠控制，以及上方预览、下方标题和辅助信息的卡片网格。
- 复用受控静态展示能力呈现首场缩略内容，隔离播放和课堂全局状态；测验预览不显示答案，无完整首场时使用明确阶段占位。
- 统一创建时间、未定稿、首场未就绪、「已生成 M / N 页」与「N 页」的排版和提示，不冒充学习时间或后台持续运行状态。

- 完善重命名、删除、部分清理反馈与重试的展示层级，处理键盘、焦点、触摸和弹窗关闭后的焦点恢复；危险操作不能只依赖悬停才可发现。
- 校对深浅主题、状态文字和入口可识别性，不复制参考图中范围外的能力。

阶段交付：历史区域的完整视觉和交互状态可在真实数据下审查，深浅主题与窄屏主要操作可用；不改变前两阶段已经确认的数据与恢复规则。

验收映射：HC-2、HC-6、HC-8、HC-11、HC-12，回归搜索、导航和管理入口的可操作性。

## 交付记录（2026-10-30）

### 实际改动

- 后续默认值调整：按用户「默认收起」的明确指令，首页历史区域初始收起，保留标题、总数与展开入口；同步 spec 的折叠承诺与 HC-6。此项为局部默认值调整，不新增 task。
- 新增历史课堂类型、校验与领域服务，以及列表读取、当前课堂摘要读取和重命名链路。服务端提供全局数量、搜索匹配数量、稳定游标分页与按持久化事实计算的阶段；异常旧数据仍保留可管理卡片，不伪装成新草稿。
- 列表只向首页返回摘要与完整首场的可展示内容，测验只返回标题，不传答案、解析、讲稿动作、其他场景、聊天或 PDF 全文。
- 重用既有删除入口，补为可重复核对和重试的删除：返回课堂记录已删除与文件是否清理完成的独立结果，课堂行已不存在时仍可重试文件清理。关联数据库记录在事务内清理，上传期间持有课堂行锁直到文件和文档元数据发布完成，避免删除后晚到上传重新留下文件。
- 首页新增历史区域、服务端搜索、折叠、加载更多、静态首场预览、按实时阶段跳转，以及独立重命名和永久删除弹窗；首页调整为整体滚动。预览使用独立只读场景上下文与空教学效果，不写课堂播放状态。
- 列表请求使用取消与序号隔离，搜索词改变时不显示上次关键词结果；管理完成后按最新关键词重新读取。重命名和删除结果不明时先核对，已删除卡片不被旧响应恢复。
- 删除未确认或文件未清理完时保留恢复入口；浏览器仅缓存课堂 id 与名称作为待核对提示，重试仍以服务端事实为准。缓存异常时本页仍可反馈与重试，不把缓存当成删除证明。
- 提交前复核补修：两个页面同时挂载后，分别记录不同课堂的待核对提示，原整数组缓存会互相覆盖。恢复提示改为按课堂身份独立缓存，并监听同源页面的缓存变化；兼容已有数组提示，只迁移恢复提示，不改变删除确认、服务端事实或清理范围。对应 HC-9、HC-11。

### 验收证据与映射

- **63 项真实 HTTP / 数据库 / 文件检查**：基础 24 项覆盖跨独立 HTTP 客户端与浏览器可读取的部署全量列表、16 条隔离课堂的分页、全局搜索、大小写与通配符字面匹配、各课堂阶段、无效数据和安全预览、重命名与重复删除；进阶 32 项覆盖关联场景、测验、聊天、入库记录、带向量分块及 PDF 清理，晚到插入与更新，真实 Windows 独占文件句柄导致的部分清理失败及重试、上传发布行锁与删除等待、实际 multipart PDF 建课；恢复 7 项核对草稿、首场未就绪、部分就绪、已保存作答、播放位置及聊天读回。对应 HC-1～HC-5、HC-7、HC-9～HC-11 的服务端与恢复部分。
- **9 项受控客户端边界检查**：覆盖保存身份或名称不一致、断连、非 JSON 响应、不存在课堂、文件清理未完成、删除身份不一致、无搜索结果及取消请求；未将这些模拟响应当作真实 HTTP 故障。对应 HC-7、HC-9、HC-11。
