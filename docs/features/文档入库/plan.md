# 文档入库主路径计划

## 目标与现状

让用户上传的 PDF 在草稿课堂生成大纲前完成入库，并在失败、刷新和断连时能够依据服务端状态恢复。验收承诺以 [spec](./spec.md) 的 DI-1～DI-10 为准。

规划时，创建课堂已保存 PDF 原件和文档摘要，已有入库 API、解析、切块、向量化和事务写入；生成页尚未调用入库，读取预览后直接启动大纲。其他功能曾调用真实 PDF 入库，但不能代替本功能的完整验收。`hasKnowledgeBase` 能说明已就绪，不能单独说明未就绪是正在处理、明确失败还是结果未知。

2026-10-28：用户确认文档并授权不展开 task 直接实施，后续授权启动服务、完成验收、更新状态和提交。三个阶段已完成：执行状态、10 分钟有效期、并发发布保护、自动入库门禁和生成页接线已落地，迁移已应用。真实 PDF / 模型 / HTTP / 浏览器链路及受控事务、过期和并发检查核对 DI-1～DI-10；更新为 `accepted / verified`。完整证据、清理及未覆盖的生产环境边界见 [验收记录](./验收记录.md)。未运行 build，全仓既有类型问题仍保留。

## 阶段一：服务端状态与并发边界

状态：已完成，证据见验收记录 DI-1～DI-5、DI-9。

- 核对现有入库、课堂读取、定稿与删除链路及 DI-1～DI-5，确定如何让调用方可靠区分已就绪、处理中、失败与无法确认；以服务端持久化状态为准，不把浏览器内状态当作事实。
- 设计并实现一次入库的归属、并发与恢复机制，覆盖刷新、多页面、重复请求、进程中断和晚到结果；确保只有有效执行能够发布结果，旧执行不能覆盖较新的成功结果。不能仅依赖前端防重复或事务内切块替换来证明这些性质。
- 保留原件、单课单文档、1024 维、事务完整性和当次向量配置边界；现有 DI-3 的显式重复入库契约仍需成立，不将页面自动恢复等同于主动重建入口。
- 阶段交付：可由调用方读取和恢复的可靠状态与并发保障，以及针对 DI-1～DI-5、DI-9 的验证证据。具体数据结构和接口在对应阶段展开，不能把方案尚未验证当成已完成。

## 阶段二：生成页主路径接线

状态：已完成，证据见验收记录 DI-6～DI-10。

- 依据服务端课堂与定稿状态编排：无 PDF 的草稿继续大纲；有 PDF 未就绪的草稿先入库；已就绪的草稿复用知识库；已定稿课堂沿用原恢复流程，不自动补入。
- 使用本次已保存的向量配置发起入库；处理期间展示真实阶段，失败时提供清晰提示、设置入口和显式重试。确认成功后更新状态并使用大纲原有的知识库检索路径。
- 读取、入库和大纲执行之间处理离页、刷新、过期响应和结果未知；不得误报成功、静默跳过 PDF 或让旧页面结果影响当前课堂。
- 阶段交付：DI-6～DI-10 的生成页行为及不带 PDF 的回归；不新增已定稿课堂补入或跳过 PDF 的入口。

## 阶段三：真实链路验收与收口

状态：已完成，本地开发范围验收通过，限制见验收记录。

- 对照 DI-1～DI-10，分别核对真实 PDF 的创建、入库、状态读回和生成页衔接；验证无 PDF、缺配置、解析文本不足、向量维度或服务失败、重试、刷新 / 断连、并发以及不同课堂隔离。
- 验证入库后大纲确实进入本课检索分支，并抽查后续场景生成与课堂问答的资料使用；区分检索发生、真实引用和课程质量，不把一次成功等同于所有提供商均兼容。
- 记录验证环境、受控故障与真实浏览器 / 数据库 / 模型证据及未覆盖项；全部验收有依据后才讨论更新交付状态。不得运行 `pnpm build`，不默认增加常驻测试文件。

## 范围和依赖

- 不修改创建课堂时只保存原件的职责，不改模型设置弹窗，不新增上传格式、PDF 图片提取或全文提示词。
- 不在本次加入模型身份匹配、自动或手动知识库重建；同维度不同模型可能影响检索且不一定报错，后续范围须单独对齐。
- 生成页门禁与大纲服务的无知识库能力分开：大纲服务既有契约保持，页面不自动绕过已上传 PDF。
- 需要涉及行为、数据保存或验收范围的新规则时先与用户确认；本计划不预设具体文件、接口、表结构或操作步骤。进入对应阶段且用户要求时，另写可审查的 task。
