# 文档入库验收记录

2026-10-28：用户确认 spec / plan，授权不展开 task 直接实施，并授权启动本地服务、完成验收、更新完成态和提交。DI-1～DI-10 在本地开发范围内核对通过，文档入库更新为 `accepted / verified`。本记录区分真实链路与受控故障，不代表所有模型提供商或生产部署都已验证。

## 交付结果

- 生成页先按服务端状态识别文档和定稿；有 PDF 的草稿先入库，确认就绪后再启动大纲。无 PDF 与已定稿恢复保持各自路径。
- 入库状态由 PostgreSQL 保存，提供无缓存读取。执行身份与 10 分钟有效期约束发布；过期结果归为未知，显式重试可以重新取得执行权。旧执行不能发布或把新执行标为失败。
- 生成页的自动请求使用 `if-unready` 门禁；领取执行后在同一事务内再次核对就绪状态，防止晚到的自动请求重新入库。原有主动重复入库 API 继续可用。
- 页数、全文、切块替换、知识库就绪与执行完成在同一事务提交。入库只调用向量模型，原件读取限制在该课堂目录内。
- 页面展示资料处理阶段、配置入口与显式重试；断连先核对，刷新和多页面等待服务端结果，不自动绕过 PDF，也不虚构百分比。

## 逐项验收

- **DI-1：通过。** 使用项目示例差旅报销制度 PDF，真实 HTTP 上传后，以独立向量请求头调用入库，返回 201、3 页、1281 个非空白字符、4 个切块；使用实际 BAAI/bge-m3，1024 维。数据库保存解析结果和完整切块；该请求不要求对话配置，不生成大纲。
- **DI-2：通过。** 入库后 GET 课堂报告就绪并带原文档摘要，不返回全文。真实数据库向量查询验证有资料课堂可命中、另一未入库课堂返回空结果；查询实现按课堂过滤。上传原件保留，解析全文仅在服务端持久化。
- **DI-3：通过。** 真实 HTTP 重复入库返回 201；受控数据库检查确认覆盖后切块数不累加、仍是一份文档。自动入口额外验证：知识库就绪后 `if-unready` 请求返回 409，事务回滚，不改变已完成执行；直接主动领取仍允许重新入库。
- **DI-4：通过。** 真实 HTTP 覆盖不存在课堂 404、无文档 400、缺向量配置 401、短文本 PDF 400、测试原件缺失 400。错误后课堂和文档元数据保留、未就绪课堂不变成就绪；短文本原件保留。非 1024 维与非成功执行由受控服务检查覆盖，失败不替换已有切块。原件丢失用本轮测试文件模拟，没有删除用户原件。
- **DI-5：通过。** 在真实数据库事务中，通过临时客户端代理在切块插入处注入异常，实际执行此前的文档更新和旧切块删除；核对事务回滚。已有知识库的切块 ID、内容、页数和全文保持原值；首次入库课堂仍未就绪、无切块、全文未写入。模拟注入证明事务边界，不等同于数据库进程崩溃测试。
- **DI-6：通过。** 浏览器新 PDF 草稿自动入库后进入大纲流；另一课堂从缺配置失败、显式重试入库后进入大纲。真实模型产出大纲并完成首场内容和讲稿动作保存；课堂问答实际查询资料，展示 sample.pdf 第 2 页来源且完整回复已保存。真实 HTTP 另覆盖入库后检索大纲成功结束。
- **DI-7：通过。** 浏览器清除临时向量配置后，无 PDF 课堂仍完成真实大纲生成。已入库课堂进入或重试时复用知识库；真实 HTTP 与最终数据库回归确认晚到的自动请求不重新发布切块。未启用任何跳过 PDF 入口。
- **DI-8：通过。** 浏览器缺配置时展示错误、设置和重试入口；保存测试设置后仍需显式重试，之后真实入库及大纲成功。短文本、原件缺失和模型连接失败的 HTTP 分支保留业务数据；页面捕获失败，不启动无资料大纲。直返错误可提供具体原因，刷新后已失败状态提供检查 PDF / 向量设置的恢复提示。
- **DI-9：通过。** 本机临时转发服务延迟真实向量响应 8 秒，浏览器在资料处理中刷新并在另一个页面打开同课，随后依据状态继续至大纲。真实数据库受控检查覆盖同时领取仅一个成功、执行过期读为未知、接替执行、旧执行发布拒绝、旧失败不能污染新执行，以及自动就绪门禁回滚。刷新覆盖客户端离页断开；未覆盖生产代理丢包、操作系统强杀或实际等待 10 分钟，过期由数据库时间夹具模拟。
- **DI-10：通过。** 将本轮已定稿且首场已保存的临时课堂设为知识库未就绪，保留 PDF，浏览器重新打开生成页直接恢复「第一场景已生成」。读取确认知识库仍为未就绪，未自动补入或重跑已确认大纲。

## 环境、检查与清理

- 环境为 Windows、Next.js 16.3.4、本地 3001 开发服务及 PostgreSQL / pgvector。真实模型使用当次请求的 deepseek-flash 和 BAAI/bge-m3，两套配置分别传递。首次沙箱网络限制导致 EACCES，允许网络访问后重跑成功，没有关闭 TLS 校验。
- 浏览器完整链路使用仅监听本机的临时模型转发服务，浏览器只填占位 Key；真实凭据只由临时转发进程从本地测试配置读取，不进入仓库、截图或业务记录。正式业务仍只接收请求配置，不新增环境变量兜底。转发路径曾有重复 `/v1` 的测试设施错误，修复后重跑成功，不计为正式产品缺陷。
- 定向 ESLint、Prisma schema 校验、生成 Client、迁移应用及迁移状态检查通过；全仓 TypeScript 检查仍有既有缺失依赖和旧导出错误，本次修改文件未出现在错误输出中。未运行 `pnpm build`，不宣称全仓类型检查通过。
- 清理并逐个读取确认 13 个 HTTP / 浏览器临时课堂不存在，上传目录不存在；再核对八张关联表均无这些课堂残留。最终并发回归另建一个临时课堂，并在结束时删除、核对执行记录级联清除。临时测试代码、PDF、配置和转发服务在收口时清理，不保留常驻测试文件。
- 本轮没有对原业务数据制作前后内容快照，因此不把测试数据清理核对描述成全库内容一致性证明。
