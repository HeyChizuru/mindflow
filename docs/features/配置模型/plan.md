## 规划时的基础与缺口

- 后端已从当次请求分别解析对话与向量配置，经统一模块调用模型，具有缺配置、端点规范化与生产环境端点访问校验；不需要另建一套模型调用体系。
- 生成页、课堂问答、简答批改和后台续生成仍使用客户端开发配置来源。需要统一替换来源，并核对一次业务执行内的配置一致性，而非逐个业务维护一份设置。
- 顶栏设置按钮仍为占位，首页和课堂已有入口，生成页尚需补齐相同入口。缺少正式配置存储、弹窗编辑与独立模型能力测试。
- 问答与简答批改已有问题或答案保存、异常反馈及显式恢复流程，不能因新增前端配置校验而跳过这些流程。
- 向量校验要求 1024 维，知识库未记录模型身份。本次只承接实际异常提示，不补身份记录、兼容性匹配或重新入库。
- PDF 入库 API 已有，主流程前端接线不在本次范围；向量测试与已有知识库检索接线不代表 PDF 全链路交付。
- 环境变量示例仍含服务端模型配置说明，与 ADR-003 不符；业务接线阶段同步消除相关使用说明的误导，不引入环境变量兜底。

以上保留规划时的静态代码核对。开发配置来源、弹窗、配置存储与测试、环境变量示例等缺口已在阶段一至三处理；PDF 入库接线与向量模型身份管理继续排除。当前运行证据与剩余联调以验收记录及下列阶段状态为准。

## 阶段一：配置与测试基础

当前状态：已完成。配置存储与异常、请求头、执行快照及模型测试路径具备首轮受控与真实能力证据；跨业务真实持久化验收已在阶段四补齐。

目标：形成可由弹窗和现有业务共同使用的两组独立配置能力，具备安全、有限的真实模型测试路径。

依赖：spec 及本阶段范围经用户确认；沿用现有模型解析、端点校验和模型调用边界。

范围：

- 建立配置的独立完整性与格式校验、当前浏览器保存与恢复、清除及存储异常反馈；区分编辑草稿、已保存配置与测试结果。
- 建立统一的业务配置读取与请求配置组装能力，允许按需取得对话或向量配置；缺配置不以开发常量、另一组配置或环境变量代替。
- 建立配置快照能力，支持单次大纲、场景、问答与批改执行，以及后台每个目标场景读取配置的边界。
- 复用统一服务端能力完成对话基础回复、工具与结构化决策、流式正文测试，以及向量生成和 1024 维检查；处理时间边界、错误脱敏和测试结果归属。
- 测试不写课堂业务数据、不查询或修改知识库，不引入新的模型厂商协议或兼容性管理。

阶段交付：配置基础与模型测试可独立验证，存储失败不虚报成功，测试与业务数据相互独立；尚不以底层通过代表业务接线完成。

验收映射：MC-2～MC-7 的基础能力、MC-8 的统一请求配置与密钥边界、MC-9 的快照基础。

## 阶段二：设置弹窗

当前状态：已完成。首页弹窗的编辑、保存、测试、恢复、清除、焦点、主题和窄屏操作复用首轮证据；生成页和课堂页的实际设置入口、缺配置恢复与配置变更已补齐浏览器联调。

目标：用户从首页、生成页或课堂播放页完成填写、测试、保存、恢复与清除。

依赖：阶段一提供配置存储、校验、快照与模型测试能力。

范围：

- 接通顶栏统一弹窗，提供两组字段、用途说明、密钥显示切换，以及“保存在当前浏览器”的明确说明。
- 接通草稿编辑、保存、关闭、按组清除和再次打开的行为，区分字段错误、本地存储错误、测试中及测试结果。
- 接通基于当前草稿的独立测试，字段变更后不沿用旧测试通过状态，晚到结果不覆盖另一份配置。
- 完成键盘、焦点、窄屏与深浅主题适配，保留当前页面及用户输入；不新增独立设置页面或其他高级设置。

阶段交付：弹窗配置流程与基础能力闭环，用户能保存并跨刷新恢复；记录真实模型测试和界面验证各自覆盖的范围。

验收映射：MC-1～MC-7、MC-12；MC-8～MC-11 的业务使用留到后续阶段。

## 阶段三：现有业务接线与异常提示

当前状态：已完成。正式链路不再导入开发配置，生成、后台续生成、问答、批改、知识库检索与异常恢复均有真实模型 / HTTP / 数据库证据；浏览器首场与问答执行快照已验证。

目标：本次范围内所有模型调用使用正式设置，用户可在配置问题出现后修改设置并显式恢复原操作。

依赖：前两阶段能力稳定，现有生成、问答、批改与恢复契约可复用。

范围：

- 接通流式大纲、大纲确认时的配置检查、首场内容与动作生成、后台续生成、课堂问答及内部调用、简答批改；替换客户端开发配置来源。
- 场景内容与动作使用同份执行快照，问答与批改在本次执行中保持配置一致；后台后续目标及显式重试读取最新保存值。
- 缺少或无效配置时说明对应组别，提供打开设置的入口，保存后仍由用户按原流程继续或重试，不因保存设置自动重新执行。
- 保留问答问题与简答答案的服务端保存、结果未知核对、幂等和归属校验；不把所有业务调用提前统一拦截，也不阻塞不需要模型或向量的操作。
- 向量调用、维度校验和检索异常只捕获提示，沿用原业务恢复方式，不新增身份匹配、自动降级或知识库重建。
- 同步直接相关文档中开发配置和服务端环境变量说明，使其与正式配置来源一致，保留历史验收记录的证据边界。

阶段交付：正式配置与本次业务主路径连通，配置变更和失败恢复行为一致；PDF 入库前端接线仍不开展。

验收映射：MC-8～MC-11，回归 MC-1～MC-4、MC-12 的跨页面行为及原业务的保存、恢复与隔离约束。

## 阶段四：集中审查与验收

当前状态：已完成本次范围验收。结合首轮 37 项受控、真实模型能力与弹窗验证，以及本轮 35 项真实 HTTP / 数据库检查和生成 / 课堂浏览器操作，核对 MC-1～MC-12 后更新为 `verified`。全仓 TypeScript 仍有既有 41 项错误；生产代理、真实移动设备与 PDF 入库接线不属于本次通过结论，详见验收记录。

目标：核对 MC-1～MC-12，修复跨模块问题，并记录可复核的交付证据与限制。

依赖：前三阶段已接通；验证按实际依赖区分受控检查、真实服务、浏览器与数据库读回。

范围：

- 核对仅对话、仅向量、配置缺失、配置错误、保存与清除失败、测试失败及旧测试晚到；确认不因某组未配置阻塞另一组可用操作。
- 用真实模型验证无知识库的大纲、场景内容与动作、后台续生成、问答和简答批改，并核对业务记录保存与已有结果恢复。
- 对已有知识库使用受控或现成数据核对向量配置与实际检索异常提示，记录数据来源；不借验收新增 PDF 入库前端流程或模型身份管理。
- 核对执行中修改和清除配置、下一执行使用新配置、用户显式重试，以及问答和批改结果未知时先核对记录；保存设置不自动重跑业务。
- 回归课堂观看、切场、历史读取、选择题判分与输入保留，检查窄屏、主题、键盘和焦点。
- 检查正式链路不再依赖开发配置、不回落环境变量、不泄露密钥；分别记录局部检查、真实模型、浏览器与持久化证据，不用单次连通测试代替整体验收。

阶段交付：本单元集中验收记录及修复结果。只有范围内验收确有证据时才更新交付状态，不将 PDF 入库或向量模型兼容性管理写成已交付。

验收映射：MC-1～MC-12。

## 实施边界

- 本次用户已明确授权按 spec / plan 实施且不展开 task；后续若变更使用流程、保存规则或验收范围，仍须先与用户对齐。
- 不改数据库结构，不执行迁移，不代管用户密钥；课堂数据仍以服务端持久化为准。
- 不扩展 PDF 入库前端、向量模型匹配和重建，不为测试方便改变已确认范围。
- 不默认运行 `pnpm build`，不堆叠测试文件；临时测试代码使用后清理。真实模型调用、服务启动、提交或推送按当次授权执行。
