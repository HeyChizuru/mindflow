- 顶栏打开统一弹窗，首页、生成页和课堂可用。对话与向量分别填写地址、Key 与模型名，按组保存、清除与测试；配置以明文保存在当前浏览器，编辑草稿不自动生效。

- 流式大纲、大纲确认、首场和后台场景内容与动作、课堂问答及内部调用、简答批改已替换为正式配置来源。正式业务不再导入含密钥的本地开发头文件；该本地文件保持原状，不加入版本控制。
- 每个场景内容与动作共享配置快照；后续目标场景与用户显式重试读取新设置。保存或清除设置不重建课堂控制器、不自动重跑任务。

- 大纲模型异常的日志和 SSE 不再直接输出第三方原始错误，避免其中携带请求配置。环境变量示例改为指引弹窗，并允许无真实密钥的 `.env.example` 纳入版本控制。

## 受控检查：37 项通过

这些检查使用临时脚本、内存存储、伪造的客户端响应和仅监听本机回环地址的模型夹具，不等同于真实数据库或真实业务模型效果验证。

第一组 29 项：

- 空配置、仅对话配置、两组不同配置、按需携带请求头、快照与新值读取、字段规范化。
- 空模型名、换行与控制字符、非 ASCII 模型名、带账号或查询参数的 URL、非 HTTP(S) 地址等输入拒绝。
- 本地读取、写入与清除失败、单组配置损坏、重新保存修复和独立清除，失败时不虚报成功、不向请求注入默认凭据。
- 实际后台生成控制器的两场连续调度：内容生成中修改设置，当前动作保持原配置、下一个目标读取新值；动作不携带向量凭据。
- 实际 HTTP 测试接口的文本、工具与 SSE 结果，1024 维向量成功、错误维度提示、认证错误脱敏、缺配置不回落环境变量、非法类型和跨来源请求拒绝。

第二组 8 项：使用真实问答与课堂客户端控制器、替换其 HTTP 响应，分别验证简答和聊天缺配置时仍请求保存接口，收到“已保存但模型未完成”后保留原记录，保存新配置不自动重试，显式恢复使用新配置及原提交 / 轮次身份。这里的“已保存”由受控响应提供，不作为真实数据库写入证据。

验收映射：MC-2～MC-4、MC-7 的配置与失败边界；MC-5、MC-6 的实际 HTTP 测试路径；MC-8～MC-11 的部分请求、快照与客户端恢复行为。
