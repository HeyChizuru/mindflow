# 配置模型

## 承诺

用户通过顶栏设置弹窗填写自己的 OpenAI 兼容模型配置，保存到当前浏览器；需要模型的现有业务从已保存设置取得当次请求配置，不再使用客户端写死的开发配置。对话模型与向量模型分别配置，可使用不同服务商。

### 入口与配置用途

首页、生成页和课堂播放页均可打开同一个模型设置弹窗，用户不需要离开当前页面修改设置。打开、编辑或关闭弹窗不重新创建课堂、刷新业务页面或主动重跑模型任务。

弹窗提供两组独立配置，每组均有 API 地址、API Key、模型名称。模型名称可手填，API Key 默认遮挡，支持主动显示与重新隐藏。

- 对话模型：用于流式大纲、场景内容与测验生成、讲稿动作生成、简答批改和课堂问答；问答内部的教师选择、历史整理及相关决策共用该配置。首版不为三名教师分别配置模型。
- 向量模型：用于 PDF 文本向量化和资料检索。弹窗说明其适用场景；无知识库的生成与问答、简答批改不要求向量配置。提供这组配置不代表本次交付 PDF 入库前端流程。

首版只支持两组当前配置，不提供服务商账户管理、模型收藏或多套配置切换，也不开放温度、输出长度等高级参数。

### 编辑、保存与清除

编辑内容是弹窗草稿，只有用户保存后才成为业务使用的配置；直接关闭不应用未保存修改。两组配置独立校验，允许只配置对话模型或只配置向量模型，另一组未配置不阻止保存。准备使用的一组须填写完整，字段格式错误时定位到对应字段；格式检查不等于服务可用性验证。

API 地址、Key 与模型名称保存在当前浏览器的 localStorage，刷新或重新进入后可恢复。弹窗明确说明“配置及 API Key 保存在当前浏览器”，不宣称本地存储已经加密，不承诺其他浏览器、设备或账号之间同步。API Key 不出现在普通提示、错误、日志、URL 或业务记录中；显示密钥限用户主动操作的输入框。

用户可以清除任一组已保存配置。清除生效后，该组不再用于新请求，不恢复开发配置或环境变量兜底，也不删除课堂、PDF、聊天或测验数据。浏览器拒绝写入或清除时明确提示失败，不显示已保存或已清除；本地配置无法读取或内容损坏时可提示并重新配置，不因此阻塞已保存课堂内容的读取。

模型连接偏好与课堂业务数据分开：本地存储只承载用户在当前浏览器提供的配置，不替代 PostgreSQL 中的课堂、聊天、测验和生成结果。

### 配置测试

对话配置与向量配置分别提供测试操作，使用该组当前填写内容，不要求先保存，也不因测试自动保存。界面说明测试会发起实际模型请求；请求通过项目服务端的统一模型能力执行，沿用已有端点校验，不由浏览器直连第三方。

- 对话测试验证基础文本回复、问答所需工具调用与结构化结果，以及流式正文接收；结果说明实际通过或失败的能力，不把端点可访问等同于全部业务可用。
- 向量测试实际生成向量并检查是否满足现有 1024 维要求；不读取、创建或重建任何课堂知识库。

测试具有有限执行时间，失败可再次手动测试。测试结果只对应参与测试的那份配置，修改字段后不能继续把旧结果当作当前配置通过；晚到结果不得覆盖另一份配置的测试状态。服务暂时不可用或能力测试失败，不阻止保存字段完整、格式有效的配置。测试通过不承诺所有课程、所有提示词或后续请求必然成功。

### 业务接线与生效边界

本次接通流式大纲、大纲确认时的配置检查、首场内容与动作生成、后台续生成、课堂问答及其内部模型调用、简答批改。对话与向量各自由当次请求携带自己的地址、Key 与模型名，互不代替，不读服务端环境变量兜底，不把开发常量作为默认值。

一次执行开始时取得配置快照，在执行中保存或清除设置不替换该次执行已经取得的配置；后续新执行及用户显式重试使用最新已保存配置。一次执行指一次大纲生成、一场场景的内容与动作生成、一轮问答或一次简答批改；后台续生成以每个目标场景为单位读取新配置，不因保存设置重启整个队列。

保存设置只更新配置，不自动重试失败任务、重新生成已保存内容或重新批改已有结果。原业务的结果核对、幂等、显式恢复、会话与课堂归属约束继续成立。

缺少或无效配置时，界面说明本次需要哪组配置，并提供打开设置的入口；用户保存后通过原业务入口继续或重试。只在实际需要的地方要求配置，不能因为向量配置缺失而禁止无知识库问答，也不能因为模型配置缺失而禁止建课、读取历史、观看已有内容、切场或选择题判分。

问答和简答提交保留原有保存边界：不能因为前端构造配置或校验失败，跳过原本应交给服务端的问题或答案保存流程。已经保存的问题和答案在模型失败后继续保留，未确认保存的结果仍按原业务规则核对；设置弹窗不接管这些记录的持久化。

### 向量异常的本次处理范围

继续沿用现有向量维度与调用校验。向量调用、维度检查或检索实际抛出异常时，只做异常捕获和可理解提示，说明本次资料查询未完成，允许用户修改配置后按原流程显式重试。不把服务异常伪装成无相关资料或有引用依据的成功回答。

本次不记录知识库所用模型身份、不比较新旧向量模型、不阻止用户保存另一向量模型，也不自动或手动重建知识库。同为 1024 维的不同模型可能不产生异常却影响检索，本次不承诺识别该情况，后续维护再处理。

## 非目标

- 不增加独立设置页面、登录、云端配置同步或服务端多用户密钥托管。
- 不接入非 OpenAI 兼容协议，不做多服务商配置中心、自动拉取模型列表或每名教师独立选模。
- 不新增 PDF 上传、解析进度、入库前端接线或重新入库流程；已有入库 API 的业务契约保持原状。
- 不新增向量模型身份字段、兼容性匹配、向量维度迁移或知识库重建。
- 不修改模型提示词、教师路由策略、课程生成策略、测验评分规则或既有数据归属与恢复规则。
- 不因配置保存自动恢复失败任务，不承诺外部服务可用性、固定耗时或所有模型能力通用。

## 验收

- MC-1 WHEN 用户在首页、生成页或课堂播放页打开设置，THE SYSTEM SHALL 展示同一模型设置弹窗及两组独立的地址、Key、模型名称输入，说明各自用途；模型名可手填，Key 默认遮挡并可主动显示，不跳转业务页面或启动模型任务。
- MC-2 WHEN 用户编辑、保存或关闭弹窗，THE SYSTEM SHALL 只在保存成功后应用修改；允许另一组保持未配置，准备使用的一组字段须完整且格式有效；直接关闭不应用草稿，测试失败不阻止保存格式有效的配置。
- MC-3 WHEN 用户保存后刷新或重新进入，THE SYSTEM SHALL 从当前浏览器恢复配置，明确其本机保存范围；本地读取异常、配置损坏或写入失败时给出可理解提示，不虚报保存成功，不影响已有业务数据读取。
- MC-4 WHEN 用户清除一组配置，THE SYSTEM SHALL 在本地清除成功后停止向新执行提供该组配置，不恢复开发或环境变量默认值，不删除或改写课堂、PDF、聊天与测验数据；清除失败须明确反馈。
- MC-5 WHEN 用户测试当前填写的对话配置，THE SYSTEM SHALL 经服务端实际检查基础回复、工具调用与结构化结果、流式正文接收，反馈各项结果并限制执行时间；不因测试保存配置或写入课堂业务数据，不承诺全部业务必然成功。
- MC-6 WHEN 用户测试当前填写的向量配置，THE SYSTEM SHALL 经服务端实际生成向量并检查现有 1024 维要求，反馈异常或通过；不触发 PDF 入库、知识库查询或重建。
- MC-7 WHEN 用户在测试后修改配置或旧测试晚到，THE SYSTEM SHALL 只将结果归属于被测试的配置，不将旧结果标成当前配置通过；允许手动重新测试，测试不自动保存草稿。
- MC-8 WHEN 本次范围内的生成、问答或简答批改需要模型，THE SYSTEM SHALL 统一从已保存设置取得当次执行配置，经现有请求契约传给后端；两组独立且按实际需要解析，不使用开发常量或环境变量兜底，不将 Key 写入日志、URL、错误或业务记录。
- MC-9 WHEN 用户在执行过程中保存或清除设置，THE SYSTEM SHALL 让已开始执行继续使用原配置快照，后续新执行或显式重试使用最新保存值；场景内容与动作使用同份快照，后台下一个目标场景可读取新配置，不因保存设置自动重跑任务或覆盖已存结果。
- MC-10 WHEN 本次需要的配置缺失、无效或模型调用失败，THE SYSTEM SHALL 说明对应配置或失败原因并可打开设置，保留问题、答案及原业务保存与恢复边界；保存配置后由用户显式继续或重试，不阻塞不需要该配置的其他操作。
- MC-11 WHEN 向量调用、维度校验或检索发生异常，THE SYSTEM SHALL 捕获并提示本次资料查询未完成，保留原业务数据与显式恢复入口；不新增模型身份匹配或知识库重建，不把异常当作检索成功或无命中，不承诺发现同维度不同模型的偏差。
- MC-12 WHEN 用户使用键盘、窄屏或深浅主题操作设置，THE SYSTEM SHALL 保持字段、状态与按钮清晰可用，错误不只靠颜色表达，打开和关闭时焦点可正确进入与返回；设置交互不清空课程草稿、答题输入或聊天输入。

## 系统不变量

- 配置由用户提供，浏览器保存；服务端只在当次请求中使用，不持久化密钥到业务记录或通过环境变量代替缺失配置。
- 测试是独立能力检查，不改变课堂、场景、聊天、测验或知识库。
- 配置是否存在、测试是否通过、业务是否完成是不同状态，不能互相替代。
- 设置变更不改变业务幂等、保存确认、归属隔离与显式重试规则。
- 向量异常只做捕获提示，本次不建立模型兼容性管理机制。
