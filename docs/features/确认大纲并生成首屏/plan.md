# 确认大纲并生成首屏：实施计划

依据 [spec](./spec.md)，分为「确认大纲」和「首屏生成」两个阶段。先完成确认大纲的完整流程并验收，再实施首屏生成。每个阶段均按 **后端 → 前端静态 → 联调** 推进。

本 plan 说明阶段目标、范围与交付顺序。具体文件、接口、数据结构、实现步骤和验证方法，在实施对应阶段时另写 task。

## 阶段一：确认大纲

目标：用户可以确认当前页面上的手改大纲，保存后定稿；刷新或重新进入仍能恢复已确认内容。

实施范围：

1. **后端**：完成确认前置校验、大纲与授课语言指令的原子写入、定稿内容读取；拒绝重复改写及定稿后重新生成大纲。
2. **前端静态**：准备确认入口、提交中、确认失败和定稿只读等状态。
3. **联调**：接通确认与恢复，验证保存的是页面手改结果；流未结束时禁止提交，定稿后关闭编辑与重新生成入口。

阶段验收：确认成功即可恢复并保持定稿；确认失败不留下半成品大纲，允许重试。此阶段不调用场景生成。

验收映射：CF-1、CF-5、CF-7，以及 CF-4 中的大纲与授课语言指令恢复部分。

## 阶段二：首屏生成

目标：基于已定稿课堂，在同一生成页只生成并保存第一场景，支持失败重试和刷新恢复。

实施范围：

1. **后端**：复用开源的内容与动作两个接口，分别完成实际模型调用与生成，并接入本项目的模型配置、可选知识库检索和完整性校验。内容接口只返回内容；动作接口生成动作后组装、校验并保存完整场景，保存成功才返回成功结果。两个接口均处理请求指定的场景，不承担首场选场或跨请求调度，不另增前端保存步骤。
2. **前端静态**：准备内容生成、动作生成、成功、失败重试等状态。
3. **联调**：由生成页前端准备请求、选择第一条已确认大纲，依次调用内容接口与动作接口，接通阶段状态、失败重试与刷新恢复。以前端收到已保存场景或恢复到已有场景作为成功依据；保存失败不显示成功，失败不回滚定稿、不生成其余场景。进入教室的跳转由前端控制，播放页的路径与实现仍由「课堂播放与测验」单元定义。

阶段验收：第一场景内容与含讲稿的动作完整且可恢复；失败后保留已确认大纲，只重试第一场景。最终按 spec 的 CF-1～CF-7 验收完整功能。

验收映射：CF-2、CF-3、CF-4、CF-6，以及 CF-7 中的首屏重试限制。

## 实施约束

- 大纲与授课语言指令保存在课堂上，完整场景及动作保存在场景表；PostgreSQL 为持久化来源。
- 开源代码按 spec 适配，只支持 `slide` 与 `quiz`；不接入播放、批改、讨论执行、语音合成或后续场景生成。
- 首屏的两步流程由生成页前端串联，选场与调用顺序不下沉到后端；两个后端接口执行各自请求内的实际生成，动作接口还负责组装与保存。这符合 ADR-004 对 Route 组织本次请求内能力的约定，不要求接口变成空壳。
- 内容和动作接口供首屏与后续生成复用，不区分调用流程；目标由对应调用方决定。动作接口按传入的全部大纲计算课程位置，接收前序讲稿作为连贯性上下文。本阶段不实现后台续生成的触发、调度或完成状态管理。
- 两阶段的划分是交付顺序；最终用户流程仍遵循 spec，确认定稿后在同一生成页生成首屏。
