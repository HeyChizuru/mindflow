# 阶段二：首屏生成——前端适配

依据 [spec](./spec.md) 与 [plan 阶段二](./plan.md#阶段二首屏生成)。阶段二前端实现与首屏生成主链路已完成，完成按钮已预接播放页 URL；目标页面尚未落地，验收边界及后续依赖见文末。

## 实现思路

在现有生成页上继续适配 `reference/openmaic-generation-preview/` 的样式。大纲编辑器和进度卡片已经迁入，`StepVisualizer` 也已保留内容与动作动画，直接复用这些基础。

页面流程为：确认大纲后收起编辑器，回到居中的进度卡片，依次展示「首场内容生成 → 讲解动作生成 → 第一场景已生成」。失败时保留定稿，提供重试首屏入口。

## 前端静态

- [x] **补齐步骤与页面切换。** 在生成页 `types.ts` 补齐「大纲、首场内容、讲解动作」三个步骤；在 `page.tsx` 中准备确认后回到进度卡片的展示，步骤指示随当前阶段变化。用本地状态演示流程，不接真实生成请求。
- [x] **适配生成中的样式。** 复用 `components/visualizers.tsx` 中现有内容与动作动画，保持参考页面的布局、背景和过渡效果。内容阶段兼容幻灯片与测验，动作阶段提示正在生成讲稿与教学动作；动画只表示等待，不展示虚构的实际进度。
- [x] **准备完成与失败界面。** 完成时显示「第一场景已生成」；失败时说明大纲已定稿，提供「重试首屏生成」，本地演示从内容阶段重新开始。定稿后的大纲保持只读，不恢复编辑或重新生成大纲。
- [x] **适配文案与主题。** 文案集中放在 `lib/hooks/use-i18n.ts`，按钮沿用当前品牌配色和共享 Button；检查深浅主题及窄屏下的展示。

静态阶段只调整当前生成页需要的展示代码，参考目录保持原样。静态演示与现有真实请求流程分开，不改变已接通的大纲链路；不接入场景保存、刷新恢复、语音或后续场景生成。「进入教室」先展示禁用按钮，实际跳转留到联调。

静态交付以能查看生成中、完成、失败并演示重试为准，不代表真实生成与持久化已验收。

### 实施步骤

- [x] **复用静态展示。** 提取共享进度组件并接入真实页面；正式课堂不展示本地示例、「演示下一步」或「模拟失败」按钮。阶段由实际请求结果推进，不能由动画或计时器推进。
- [x] **准备真实生成依据。** 读取现有课堂接口中的需求与学习者信息，结合服务端返回的定稿大纲、语言指令组装输入；画像复用 `formatUserProfile`，没有昵称和背景时不编造画像。沿用现有开发模型头，不读 localStorage：确认与内容请求按知识库状态携带对话和可选向量配置，动作请求只带对话配置。
- [x] **串联第一场景的两次请求。** 确认成功后锁定编辑，选择服务端定稿的第一条大纲，先调用 `scene-content`，再把返回内容传给 `scene-actions`，首场 `previousSpeeches` 明确传 `[]`。请求方法复用现有 schema，并核对响应的课堂、目标与类型；动作接口返回已保存完整场景后才显示完成。内容成功不算完成，前端不另发保存请求，不生成其他场景。
- [x] **接通刷新恢复与重试。** 页面先读取生成预览：草稿继续现有大纲流程；定稿且已有 `firstScene` 时直接显示完成，不调用模型；定稿但无首屏时准备输入并开始两步生成。生成失败先重读预览，若已保存则恢复成功，否则保留定稿并展示重试；重试也先读取，仍无首屏才从内容阶段重新开始。读取本身失败时先允许重试读取，不盲目重新生成。
- [x] **保留确认门禁并防止重复请求。** 确认失败保留手改内容；确认响应丢失或另一页面抢先确认时，重读定稿再进入上述流程。生成中禁用重复操作，重复内容请求返回 409 时先读取已有结果；不使用无限自动重试。离开页面或切换课堂时中止客户端请求并忽略过时回调，防止旧结果覆盖当前课堂。
- [x] **预接进入教室跳转。** 首屏完成后保留完成界面和只读大纲；点击「进入教室」按课堂 ID 跳转到 `/classroom/{id}`。本阶段只接通 URL，不新增播放页；目标路由实现和实际落地验证留给「课堂播放与测验」。

## 最终验收

以真实页面操作和必要的手动 HTTP 核对为主，不预设新增测试文件。结果回填本 task；只勾选实际完成的项。

- [ ] **确认与门禁（CF-1、CF-5、CF-7）。** 流未结束不能确认；确认保存的是手改后的内容。确认失败保留手改且可重试，缺对话配置或知识库就绪但缺向量配置时仍是草稿；定稿后不能编辑或重跑大纲流。页面不便直接覆盖的配置错误用手动 HTTP 核对。
- [x] **真实生成（CF-2、CF-3）。** 覆盖幻灯片，以及单选、多选、简答测验作为首场；再覆盖有知识库的课堂。核对请求顺序、两套配置的分工、阶段提示和返回的完整场景；内容成功时不提前显示完成，动作成功后可读取相同首屏，本流程不新增第二场景。
- [ ] **失败、重试与恢复（CF-4、CF-6）。** 覆盖内容失败、动作失败、保存失败和保存成功但响应丢失；失败后保持定稿，重试只处理首场。刷新已完成课堂恢复同一场景且不调用模型；刷新定稿但无首屏的课堂可重新执行两步。需要故障条件但未能实际验证的项单独记为未覆盖。
- [ ] **重复操作与旧请求（CF-6、CF-7）。** 检查连续点击、两个页面竞争、生成中刷新或离开；已有首屏不被覆盖，旧课堂回调不能写入新页面，读取失败不误报生成成功。
- [ ] **页面与交付检查。** 检查真实状态下的深浅主题、窄屏、只读大纲和错误文案；对改动文件运行 ESLint，并运行 TypeScript 检查。记录关键 HTTP 状态、场景 ID 和恢复结果，清理临时验收课堂；静态预览通过不能代替真实生成验收。播放页路由尚未实现，实际跳转验收留待目标页面交付。

实际交付与未覆盖项见文末记录；后端 task 中仍未覆盖的异常用例不因前端实现完成自动视为通过。
