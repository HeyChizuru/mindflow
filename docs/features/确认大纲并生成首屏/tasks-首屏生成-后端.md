# 阶段二：首屏生成——后端适配

依据 [spec](./spec.md) 与 [plan 阶段二](./plan.md#阶段二首屏生成)。本 task 只展开后端适配；前端静态与页面联调另行安排。首屏流程由生成页前端选择第一条大纲并依次请求内容、动作接口；后端接口各自完成实际模型调用，动作接口还负责组装、校验并保存完整场景。本阶段以确认大纲已实现为前提，将开源的两个接口适配为 MindFlow 可复用的单场景生成能力，并完成本单元需要的场景保存与首屏恢复。选场、跨请求调用顺序及后台调度不放进通用生成接口，前端不另发场景保存请求。

## 职责边界与当前实施基线

- **首屏前端**选择第一份定稿大纲、组装请求，先请求内容接口，再携带内容请求动作接口；前序讲稿显式传空数组。首场流程主要由前端串联。后续场景由后台续生成的调用方按自身流程选择和调用；本 task 不实现后台流程，也不提前修改前端页面。
- **内容接口**校验本次请求、调用本项目模型及按需检索能力，实际生成并返回内容，不保存半成品 Scene，不自动调用动作接口。
- **动作接口**根据传入的大纲、内容与前序讲稿实际调用模型生成动作，组装并校验完整场景，由后端在完整性检查通过后保存，保存成功才返回成功结果；已有完整目标场景时按幂等契约返回。前端不另行决定保存时机或调用独立场景保存接口。
- **通用生成边界**是只处理请求中的目标场景。动作接口可以计算课程位置，但不识别首屏 / 后台来源，不决定下一场，也不自动补生成前序场景；后端有本次请求内的生成、组装和保存流程，不编排两次 HTTP 请求。
- **数据库校验与存储**验证课堂定稿、请求依据与目标归属，动作接口复用现有存储能力保存本次目标。这是输入约束和持久化职责，不是替调用方选择大纲；请求与定稿不一致时拒绝，不静默替换请求。
- **首屏恢复**仍由本单元的生成页读取接口提供，只读取第一场景。首屏专用读取 helper 可以保留在该流程中，不能成为两个通用接口的依赖。

截至 B6 后端验收记录形成时：B1～B5 后端实现已完成，B6 的幻灯片、三种测验、知识库生成、并发保存、断连恢复及指定其他目标生成已通过手动 HTTP 验证。用户当时允许「手动 HTTP 验收，不写脚本、不构建」；该轮复用 3001 上已有开发服务，没有编写测试脚本，没有运行 lint、类型检查或构建。模型连接存在间歇性的 `SELF_SIGNED_CERT_IN_CHAIN`，完整两步重试与其余受控故障覆盖未记为通过。详细证据和未覆盖项见 B6 及最新交付记录；前端联调状态以对应前端 task 为准，当前 feature 状态见 spec frontmatter 和文档索引。

以上职责与 ADR-004 一致：前端组织跨请求流程，Route 可以组织本请求中的模型、检索、校验与存储，不能据此将后端生成接口简化成只转发参数的空壳。页面跳转由前端控制，后端不决定进入教室；播放页实现仍属于「课堂播放与测验」。

## 调用边界与接口契约

保留 `POST /api/generate/scene-content` 与 `POST /api/generate/scene-actions` 作为指定场景的通用生成接口，由首屏流程和后续生成流程复用。首屏由生成页前端依次调用这两个接口，调用方决定传哪份大纲，接口负责本次请求的实际生成，动作接口还负责完整场景保存。服务端不通过 HTTP 相互调用，不新增统一首屏生成接口，也不为此流程增加前端单独保存的接口；接口不接收首屏 / 后台来源标记。

1. 生成页调用既有确认接口，提交页面上的大纲与语言指令；确认前的配置检查与原子写入保持原有契约。
2. 确认成功后，生成页前端选择定稿中的第一份大纲，组装并发送 `scene-content` 请求：`{ stageId, outline, allOutlines, requirement, languageDirective?, userProfile? }`。`outline` 是已选中的完整大纲，`allOutlines` 是完整定稿；接口校验归属及输入契约后实际调用模型生成该目标内容，返回 `{ success: true, content, effectiveOutline }`，不另选、默认或改写大纲。目标 ID 使用 `outline.id`，不把 `{ stageId, outlineId }` 作为请求组装的替代入口。
3. 内容请求成功后，前端将内容结果、同一份目标大纲、全部大纲及前序讲稿传给 `scene-actions`：`{ stageId, outline, allOutlines, content, previousSpeeches, requirement, languageDirective?, userProfile? }`。接口校验后实际调用模型生成动作、组装并保存该目标场景，保存成功才返回 `{ success: true, scene, previousSpeeches }`。前端不再发一次保存请求。请求中的 `previousSpeeches` 用于承接前序讲解；响应中的同名字段是本次场景的讲稿，供调用方准备后续请求，两者不能混淆。
4. 两个请求各自携带本次实际使用的模型头。内容接口需要对话配置，有已就绪知识库时还需要向量配置；动作接口不检索，只需要对话配置。调用方从已保存的课堂需求、定稿、语言指令和画像组装请求，不重新编辑定稿；接口校验课堂定稿状态、目标归属、请求结构和生成依据的一致性。`allOutlines / previousSpeeches` 是生成输入，不由接口替换成第一条或固定空数组。不接收 `interactiveMode`、媒体生成配置、自定义 Agent 列表或调用流程标记。
5. 中间内容只在两次请求之间传递，不持久化、不创建占位 Scene。客户端传回的内容属于待校验输入，不视为已保存结果。本阶段不增加内容签名、生成会话或服务端中间缓存。
6. 首屏未保存时，由前端发起失败重试并重新调用这两个接口；刷新后可从定稿重新开始。首屏已保存时恢复已有场景，不重新生成或覆盖。前端以动作接口返回的已保存场景或读取恢复的已有场景为成功依据，不能把内容成功当成首屏完成。页面自动触发、阶段提示、重试按钮及成功后进入教室的跳转由后续前端联调负责，播放页实现由对应单元定义。
7. 后台调用方按其顺序选择尚未完成的大纲，并准备前序场景讲稿；首屏调用方传第一份大纲与空前序讲稿。`scene-actions` 根据传入的 `allOutlines` 与 `outline.id` 计算实际页码、总页数和标题上下文，目标不在列表时拒绝请求，不回退到第一页；使用收到的 `previousSpeeches`，不在接口中查询上一场景来代替该字段、自动选择下一场或补生成前序场景。不增加后台调度或前序场景必须完成的门槛。
8. 幂等、已有结果检查和并发唯一约束均针对本次 `(stageId, outlineId)`；首屏已存在不能阻止其他目标场景生成。本单元的 `generation-preview` 仍只恢复第一场景，不因此改成整课读取或调度入口。
9. `outlineId` 指 `outline.id`，只用于已有结果查询、唯一约束和 Scene 关联，不是额外的请求选场参数。`outline` 必须与 `allOutlines` 中对应项一致，`allOutlines` 的内容和顺序、课程需求及语言指令必须与该课堂定稿一致；画像有值时使用基于保存字段的共用格式化规则。空语言指令允许省略或传 null，但不得被编造的默认值替代。输入不一致时按请求错误拒绝，存量数据本身损坏时按读取错误处理。
10. 调用方负责从真实的前序场景结果整理请求 `previousSpeeches`，首屏显式传 `[]`；接口校验为讲稿字符串数组并保留顺序，非空数组中的每项必须是非空文本，不查询上一场景来覆盖它。响应 `previousSpeeches` 只提取当前返回场景中的 speech 文本，用于下一次请求准备。

以下按条目记录实施状态；源码恢复、清理或数据校验完成不代表场景已持久化。动作接口只有保存成功或读取到已有完整 Scene 时才能返回成功场景，不能把 `CreateSceneInput` 当作已保存的 Scene。运行验证见 B6。

## B2 — 通用请求契约、输入校验与模型上下文

验收映射：CF-2、CF-3、CF-7；回归 CF-1、CF-5。

- [x] 在 `lib/types/stage-generation.ts` 与 `lib/validators/stage-generation.ts` 定义上述内容 / 动作请求 DTO 和严格校验，作为 B3 / B4 的共同输入基础。复用已有大纲 schema，校验课堂 ID、非空需求、完整大纲、可空语言指令及可选画像；动作请求还包含待校验的 `content` 和 `previousSpeeches`。不接收来源标记、自报页码及已排除功能的参数，不用类型断言替代运行时校验。
- [x] 将前端调用方的请求准备与生成接口分开。首屏读取能力只能用于本单元的请求准备或恢复，不成为通用接口选择目标的前置步骤；接口使用调用方传入的 `outline`，按 `stageId` 校验定稿及目标归属，并按 `outline.id` 检查该目标已有结果，不从数据库自行挑第一条或下一条。通用读取 / 校验能力只核对本次明确传入的目标。
- [x] 在共用服务中核对请求依据与保存数据：按现有 schema 校验存量定稿，再比较目标大纲、全部大纲及顺序、需求、语言指令与画像格式化结果，避免客户端草稿或改写内容成为新的事实来源。对象字段书写顺序与空语言指令的 null / 缺省表达不造成误判；不一致时拒绝请求，不替换为数据库中的另一场。数据库读取 / 存量校验失败与请求参数错误分开处理。
- [x] 基于保留的 `buildGenerationInputContext` 等工具实现通用模型与生成上下文准备。输入使用请求中的需求、目标大纲、全部大纲与前序讲稿，页码按目标在 `allOutlines` 中的位置计算，并按需注入知识库摘录。调用方准备画像且无画像时省略，语言指令为空时不编造或回写默认值，保留目标 `languageNote`。不重建已删除的首屏专用生成类型或 helper，首屏或后台的选场规则不得下沉到公共能力。
