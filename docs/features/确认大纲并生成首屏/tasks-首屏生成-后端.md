# 阶段二：首屏生成——后端适配

依据 [spec](./spec.md) 与 [plan 阶段二](./plan.md#阶段二首屏生成)。本 task 只展开后端适配；前端静态与页面联调另行安排。本阶段以确认大纲已实现为前提，保留开源的两个生成接口，在现有源码上接入 MindFlow 的数据与服务。

## 现有基础与缺口

- `app/api/stages/[id]/confirm-outlines/route.ts` 已在写入前校验对话配置，并在知识库就绪时校验向量配置；`lib/services/stage-generation.ts` 已提供确认与定稿读取。继续复用，不重新实现确认流程。
- `app/api/generate/scene-content/route.ts`、`scene-actions/route.ts` 及 `lib/generation/` 是迁入的开源代码，保留了内容生成、动作生成与场景组装流程，但仍依赖原项目的类型、模型解析与 Store，尚未接入本项目的场景存储。无关分支的清理与恢复情况见交付记录。
- `lib/types/outline.ts`、`scene.ts`、`action.ts` 及对应 validators 已定义本项目的 `slide / quiz`、画布、题目与动作契约，适配以这些定义为准。
- `prisma/schema.prisma` 已有 Scene 表及 `(stageId, outlineId)` 唯一约束；`lib/db/queries/scenes.ts` 已有插入、按大纲读取和按课堂读取方法。复用现有表与查询，不另建存储。
- `GET /api/stages/{id}/generation-preview` 当前恢复大纲与语言指令，尚未返回首屏；开源场景组装器的 ID、时间格式及大纲关联也需适配。
- 开源测验 user prompt 的示例与本项目答案格式不一致；动作生成在解析失败时会回退到通用讲稿。需要同时处理提示词、解析和完整性判定。

## 调用边界与接口契约

保留 `POST /api/generate/scene-content` 与 `POST /api/generate/scene-actions`。两个接口由生成页依次调用，服务端不通过 HTTP 相互调用，也不新增统一首屏生成接口。

1. 生成页调用既有确认接口，提交页面上的大纲与语言指令；确认前的配置检查与原子写入保持原有契约。
2. 确认成功后，生成页调用 `scene-content`，请求体为 `{ stageId }`。接口读取定稿，生成并校验第一场景的内容，返回 `{ success: true, content, effectiveOutline }`；`effectiveOutline` 是数据库中的第一条大纲，不重新生成或改写。
3. 生成页将上一步返回的 `content` 传给 `scene-actions`，请求体为 `{ stageId, content }`。接口重新读取定稿，校验内容与第一条大纲类型一致，生成动作、组装并保存完整场景，返回 `{ success: true, scene, previousSpeeches }`。`previousSpeeches` 从返回场景的 speech 动作按顺序提取，保留开源响应形状。
4. 两个请求各自携带本次所需的模型头。课程需求、全部大纲、语言指令、学习者信息均由服务端读取；不接受客户端另传这些字段作为生成依据。不接收 `interactiveMode`、媒体生成配置或自定义 Agent 列表。
5. 中间内容只在两次请求之间传递，不持久化、不创建占位 Scene。客户端传回的内容属于待校验输入，不视为已保存结果。本阶段不增加内容签名、生成会话或服务端中间缓存。
6. 首屏未保存时，失败重试重新调用这两个接口；刷新后可从定稿重新开始。首屏已保存时恢复已有场景，不重新生成或覆盖。页面自动触发、阶段提示与重试按钮由后续前端联调负责。

以下按条目记录实施状态；源码恢复或清理完成不代表接口已经可用，运行验证见 B6。
