# 课堂讨论：实施计划

依据 [spec](./spec.md)，按 **清理旧讨论路径与访问边界 → 建立聊天保存与恢复能力 → 接入 LangGraph 问答链路 → 打通前后端 → 会话管理（阶段四补充）→ 细化前端 UI → 整体验收与修复** 推进。聊天保存恢复与 Agent 编排作为两个独立的后端阶段，分别验证；两阶段后端均完成后，先用基础聊天界面接通真实问答、保存和恢复，再补齐会话生命周期，最后细化展示与交互。

本 plan 只说明阶段目标、范围、依赖、交付顺序与验收映射，不提前展开具体文件、接口、表结构、图节点或施工步骤。进行到对应阶段且用户要求时，再结合当时代码编写该阶段 task。撰写 plan 不代表开始实现，不自动改变 spec、ADR 或交付状态。

## 当前进度与会话管理缺口

2026-10-26：阶段一至四已按原范围实施，证据与限制见各阶段 task；其范围为每课堂一份聊天历史。保留原阶段编号与历史交付记录，本次独立增加“阶段四补充：会话管理”，不将新增数据生命周期归入阶段五视觉细化，也不将旧验收视作新契约已通过。阶段四补充、阶段五及阶段六均未实施。

2026-10-27：用户已确认旧记录归入各课堂“历史会话”、刷新保持选择、普通进入恢复本课堂最近使用会话，以及无会话或删除当前会话后的空态规则；已据此展开 [会话管理 task](./tasks-会话管理.md)，待审查后实施，未展开阶段五、六 task。

- 已有问题保存、执行领取、显式重试、完整回复保存、相关历史选择、临时摘要，以及基础聊天与播放联调能力；新阶段复用这些基础，不重建前端 Agent 循环或另一套问答编排。
- 当前持久化和前端控制器按课堂组织聊天，尚无独立会话；同课堂其他聊天仍会进入历史选择。需要建立固定课堂绑定与会话内的保存、读取、恢复、记忆和执行归属。
- 当前缺少跨课堂会话列表、新建、选择与删除；需处理打开旧会话时的课堂切换、删除与在途执行的竞争，以及旧记录迁移。迁移、默认选择与删除后空态已确认，按 spec 与本阶段 task 实施，不额外推导自动新建或跨课堂默认选择规则。

## 原规划时的基础与主要缺口

- 已有课堂读取、场景播放、暂停继续、测验提交与结果恢复能力，可以作为聊天接入的基础；问答需要保持播放、作答与后台续生成各自的状态和职责。
- 已有统一模型调用、当次请求配置解析和按课堂隔离的 PDF 检索能力；LangGraph 已列入项目依赖，课堂问答的实际编排链路尚待建立。接入时优先复用模型封装，核对结构化路由、工具调用与现有模型接入的兼容性。
- 当前仍有 `discussion` 动作的生成与播放路径，须按新契约取消，并兼容已有场景。不能直接删除旧动作的读取支持而导致已保存课堂失效。
- 完整课堂数据包含测验答案与解析，不能原样用作教师上下文或工具返回内容；上下文准备、历史选择与资料检索都须遵守测验提交状态边界。
- 现有检索只提供截短片段与有限来源信息，须补足适合问答的资料及可校验的引用来源；检索失败、无相关资料与有依据回答需要分别处理。
- 聊天持久化、同轮身份与完成状态、失败恢复，以及右侧聊天与场景上下文的衔接尚待交付。现有角色或 Director 提示词不等于本 spec 的问答能力已经实现。

以上保留为阶段一至四规划时的静态核对，不代表当前仍缺少已交付能力，也不代替实际验证证据。以下阶段一至四保留原实施范围；新增会话语义由阶段四补充承接。继续实施时重新核对已有能力，只补实际缺口。

## 阶段一：清理旧讨论路径与访问边界

目标：取消由教学动作触发的讨论，为真实问答建立统一的课程读取和资料访问边界，保持已有课堂可用。

依赖：本单元 spec、阶段范围与 ADR-007 经审查确认；结合相关生成和播放 spec 核对现有实现及历史验证基线。

范围：

- 取消首场与后续场景的新 `discussion` 动作生成；旧场景中已有该动作不展示话题、不打开聊天、不调用 Agent，也不据此强制暂停，其他有效讲稿和动作仍能继续。
- 明确教师可取得的课程、场景、测验和相关历史范围，以已保存课堂事实及提交状态准备上下文；当前场景读取、其他场景读取与后续工具访问遵守同一规则。
- 保持生成、播放、测验与问答职责独立，核对取消旧动作对已有场景校验、读取、切场和重播的影响，不借清理删除其他有效教学能力或改写已有课程。

阶段交付：新生成内容不再包含讨论动作，旧课堂仍可读取与播放；问答所需的数据访问边界可复用、可核对，未提交测验的隐藏依据不作为普通教师上下文提供。

验收映射：CD-13；CD-4、CD-8、CD-12 的访问边界基础。同步核验相关单元 CF-2、BG-4、CP-4 的变更，保留历史证据与新契约验证的区别。

## 阶段二：建立聊天保存与恢复能力

目标：先建立独立于模型的聊天持久化与恢复基础，确保问题、完整回复、所属场景及保存状态可信，为后续 Agent 编排提供保存和重试依据。

依赖：阶段一完成；生成与播放的相关新契约及课堂内容读取能力已核验，问答可复用明确的数据访问边界。

范围：

- 建立问题、完整回复、教师身份、发送时场景及引用的持久保存与读取恢复能力，区分问题未保存、已保存但问答未完成、完整回复已保存等情况。普通读取不调用模型，不自动重跑未完成问答。
- 建立同轮身份与执行归属，处理重复触发、显式重试、保存结果不明和晚到结果；已有完整结果直接恢复，同一轮不重复追加问题或已完成回复。外部模型调用不依赖长时间占用数据库事务。
- 校验聊天记录、所属场景及保存内容的课堂归属，明确完整回复与部分输出的区别，不将未保存结果标为已完成；记录与恢复不依赖模型服务可用，不保存模型密钥。
- 为后续编排提供问题保存、回复写回、失败记录与显式重试的衔接能力；本阶段核对保存和恢复行为，真实教师路由、工具调用与回答质量留到下一阶段验证。

阶段交付：问题与完整回复可保存、可读回，刷新恢复所需的持久结果明确；重复触发和重试不重复追加，晚到结果不会挂错问题或场景。保存结果不明时可读取核对，历史读取独立于模型服务。本阶段通过不代表真实 Agent 问答已打通。

验收映射：CD-2 的场景绑定、CD-6 的引用保存基础、CD-9、CD-10 的持久化与重试部分，以及 CD-11、CD-12 的读取可用性、密钥排除、归属与晚到结果隔离部分。

## 阶段三：接入 LangGraph 问答链路

目标：在聊天保存与恢复基础上，完成真实教师路由、按需工具调用、资料引用和会话记忆，形成可供页面接入的完整问答后端。

依赖：阶段二完成；聊天保存、读回、同轮身份、失败恢复与结果写回规则已验证，阶段一的数据访问边界保持有效。

范围：

- 通过 LangGraph 组织上下文准备、固定教师路由、按需只读工具调用与有界结束；每轮由一位教师回复，应用校验模型决策和工具访问，不扩展教师间交接、委派或多教师协商。
- 接通本课场景与资料的按需获取、检索问题调整和补查，校验实际使用的引用并随完整回复保存。无知识库仍可问答，需要检索才要求向量配置；无相关依据、缺配置、检索失败和模型能力不支持分别反馈。
- 提供相关历史选择与必要的会话摘要能力，让不同教师能衔接前文、处理指代和用户反馈；原始记录仍是事实来源。遵守未提交测验的提示边界，不虚构用户画像、评分结果或已经掌握的结论。
- 落实工具、模型调用、补查与重试的执行边界；统一模型调用继续使用当次请求配置，排除密钥持久化。问答失败不影响已有课堂内容的读取与其他可用操作。
- 将实际问答执行接到阶段二的保存恢复能力，验证路由、工具、检索、生成或回复保存失败时保留已保存问题，重试恢复已有结果，晚到执行不能覆盖其他问题或更新的执行结果。

阶段交付：后端能够真实完成“保存问题 → 准备上下文并路由 → 教师按需获取信息并回答 → 校验并保存完整回复 → 再次读取恢复”的闭环；无 PDF 与有 PDF 路径、主要失败与重试行为均有对应验证。模型生成完成与完整回复已保存可以明确区分。

验收映射：CD-3～CD-8 的 Agent 与上下文行为、CD-10～CD-12 的实际执行部分，并结合阶段二核对 CD-2～CD-12 的服务端闭环。后端验证不能替代下一阶段的场景切换、聊天展示、播放衔接与浏览器恢复验证。

## 阶段四：打通前后端

目标：使用基础聊天界面接入已完成的后端，让用户在真实课堂中完成问答、查看引用、失败重试与保存恢复，再进入 UI 细化。

依赖：阶段二、三的后端能力均已完成，实际模型、工具调用、保存、读取与错误反馈具备可用结果。

范围：

- 接入右侧聊天的展开、收起、输入、发送和历史读取，展示用户消息、教师身份、问题所属场景与真实引用；提供基本的等待、失败、重试及保存状态反馈。
- 展开时暂停正在进行的讲解并保留画面与字幕，收起后由用户手动继续；开关聊天和读取历史不自动发送问题、不重播当前场景。
- 发送时绑定当前场景，切场不改写已发送问题的依据；下一条问题使用新场景。同课堂保留连续历史，旧请求结果不得挂到新问题、其他场景或其他课堂。
- 接通问题未保存、已保存但问答失败、回复保存失败和结果不明时的恢复操作；收起与切场不清空已保存记录，刷新后读取恢复，不自动续跑未完成执行。
- 核对后台续生成与课堂内容刷新期间的问答连续性，保持聊天、播放和作答状态相互独立；基础操作随真实链路交付，不等待视觉细化后才接入后端。

阶段交付：用户可在真实课堂发问、收到所选教师的回复与引用，并完成切场、收起、刷新、重试和再次进入的恢复；主要状态可理解、可操作，真实保存结果可核对。

验收映射：CD-1～CD-12 的页面闭环及 CD-14 的基本操作部分；回归播放、切场、测验输入与结果恢复，以及后台续生成不干扰当前学习的相关契约。

## 阶段四补充：会话管理

目标：在已打通的问答基础上交付新建、选择、删除会话，让每个会话固定关联创建时的课堂，聊天记忆和执行结果按会话隔离。

依赖：阶段一至四原范围完成；会话管理的功能规则已由用户确认，本阶段 task 经审查后才能实施。旧记录按课堂归入“历史会话”；刷新保持当前选择，普通进入恢复本课堂最近使用会话，无会话及删除当前会话后保持空态，由用户主动新建。

范围：

- 先补服务端会话生命周期与持久化归属，再接页面的列表、新建、选择和删除确认；会话信息及聊天仍以 PostgreSQL 为事实来源，不将浏览器缓存作为唯一目录或所有权依据。
- 新会话固定关联创建时正在显示的课堂；同课堂允许多个会话，新会话不继承其他会话的聊天。相关历史选择与临时摘要仅使用当前会话，课程资料及正式测验状态继续按原课堂访问规则读取，不复制为会话独立的测验记录。
- 将提交、领取执行、重试、完整回复保存、来源验证和普通恢复统一约束到会话与关联课堂；保持已有同轮幂等、保存结果不明先核对、完整回复保存后返回，以及当前请求配置的规则。
- 列表展示所属课堂并可选择其他课堂会话；打开旧会话时联动切回其关联课堂。课堂读取或切换失败不得在不一致上下文中发问，旧请求和旧读取不得污染新选会话；不借会话导航重新生成回答或改造播放、作答及后台续生成的职责。
- 删除采用二次确认与永久删除，不提供回收站；只删除目标会话及聊天、引用关联和执行记录，保留课堂、场景、PDF 与正式测验数据。服务端保证删除成功后，在途保存、失败回写、旧提交或重试不能恢复已删除会话与消息；前端同步防止晚到读取重新展示记录。
- 将每课堂原聊天归入一个“历史会话”，保留问题、回复、引用及执行状态，无原记录的课堂不因迁移创建空会话；不重新调用模型迁移答案，不自动续跑未完成执行。明确新旧契约的验证边界，不改写既有 task 的交付证据。
- 交付刷新保留选择、普通进入恢复本课堂最近使用会话的行为；明确未选择状态在刷新后保持，无会话不自动创建。删除当前会话后保留课堂画面和空态，不自动切换其他会话；删除非当前会话不改变当前聊天。

阶段交付：用户可基于当前课堂创建独立会话，在不同课堂会话间选择并恢复历史，确认后永久删除目标会话；同课堂和跨课堂会话的记忆、记录、恢复与晚到响应均不混用。创建、切换与删除失败有可理解反馈；基础键盘与窄屏操作可用，不等待阶段五才交付可操作入口。

验收映射：CD-15～CD-17；CD-2、CD-7、CD-9、CD-10、CD-12、CD-14 的会话适配。结合 CD-1、CD-4～CD-8、CD-11 回归课堂导航、工具与测验边界、引用和配置规则。证据须覆盖同课堂双会话记忆隔离、跨课堂新建与选择、历史恢复、旧数据兼容、删除取消 / 失败 / 未知结果、生成或保存中删除，以及删除后的重复请求与晚到读取，不能只验证前端列表消失。

## 阶段五：细化前端 UI

目标：在已打通的真实状态与交互基础上完善右侧聊天的布局、消息呈现与反馈，满足项目视觉和可访问性要求。

依赖：阶段四及阶段四补充完成；真实问答、会话生命周期、保存恢复、播放衔接与主要异常状态已接通。

范围：

- 完善聊天展开与收起、课程画面与聊天区域的布局关系，保持当前课程及场景可辨认，不遮挡必要的播放和作答入口。
- 细化用户与教师消息、教师职责身份、所属场景和引用展示，清楚表达回复与资料依据的关联。
- 细化会话列表、所属课堂、当前选择、新建与删除确认的呈现，保持跨课堂导航和永久删除范围可辨认，不在 UI 阶段追加数据生命周期规则。
- 完善历史读取、等待回复、未保存、问答失败、结果待确认与重试的文案和交互反馈，避免把部分输出或未保存内容表现为完整成功。
- 核对窄屏、深浅主题、键盘与焦点操作，状态不只依赖颜色表达。展示样例用于补足难以稳定复现的界面状态，不替代真实链路验证。

阶段交付：右侧聊天在真实内容与主要异常状态下可读、可操作，与播放和测验界面协调；UI 调整不改变已经确认的问答、保存和恢复规则。

验收映射：CD-1、CD-2、CD-3、CD-6、CD-9～CD-11、CD-15～CD-17 的展示与交互部分，CD-14 及 spec 非功能约束。

## 阶段六：整体验收与修复

目标：集中核对 CD-1～CD-17 的实现和证据，修复跨模块问题，确认会话管理、完整课堂问答路径与既有课堂能力可以共同工作。

依赖：阶段一至五及阶段四补充完成，真实主路径、主要异常和界面状态均有可审查结果。

范围：

- 用代表性连续对话核对概念解释、理解检查、应用实践、指代澄清与反馈后调整讲法，分别检查教师选择、工具使用、上下文衔接和回答是否回应当前问题。
- 覆盖有无知识库、无需检索、补查、无相关资料、引用归属、缺配置和模型能力不支持等路径；核对未提交测验的提示边界及提交后反馈讨论。
- 集中检查重复发送、连续重试、并发请求、响应丢失、保存失败、执行达到边界、生成中切场或离页，以及其他课堂的晚到响应，确认记录不重复、归属不混用、失败不冒充成功。
- 验证收起、切场、刷新与再次进入后的历史恢复，并回归取消讨论动作后的首场和后续场景生成、旧课堂播放、重播、作答恢复与后台续生成。
- 集中核对会话创建时的课堂绑定、同课堂记忆隔离、跨课堂选择及导航失败、既有聊天迁移和会话删除；确认生成中删除、重复提交、旧读取和保存结果不明不能复活已删除会话，且课堂资料、测验与其他会话不受删除影响。
- 修复发现的问题并针对变更回归；分别记录静态检查、受控异常、真实模型、浏览器交互与数据库读回证据，保留未覆盖项和实际限制。

阶段交付：形成 CD-1～CD-17 的验收结果、修复结果和未覆盖项记录；相关生成与播放契约的变更有对应回归证据。按证据更新交付状态，不以接口成功、静态界面或后端单独通过代替全单元验收。

验收映射：CD-1～CD-17 及 spec 非功能约束；受影响的首屏生成、后台续生成、播放与测验行为按各自契约回归。

## 实施约束与任务展开

- 当前 spec 为 draft，ADR-007 为 proposed；本 plan 不代替审查确认。相关生成与播放 spec 也已变更，正式实施与集成前需核对依赖就绪情况，旧验收不能直接证明新契约已交付。
- PostgreSQL 是已保存聊天的唯一持久化事实来源；恢复已有完整回复不重新调用模型。图状态、会话摘要和浏览器缓存不替代业务记录。
- 首版以恢复已保存聊天为范围，优先按每轮从已保存事实准备上下文推进。执行协调方式在阶段二 task 中明确；是否使用持久化 checkpoint、摘要如何保存在阶段三 task 中依 ADR-007 评估，不由 plan 提前固定，不扩展断点续跑承诺。
- 聊天保存与恢复、LangGraph 问答链路保留为独立阶段；两阶段后端完成后先打通前后端，再补齐会话管理，最后细化 UI。阶段四与其补充阶段必须具备各自基本状态与恢复操作，阶段五不新增问答流程、数据生命周期或验收范围。
- 会话管理不改变无登录、课堂事实读取、只读工具和问答编排边界，不引入跨会话学习档案；选定会话不是用户认证。已确认的迁移、默认选择与空态规则以 spec 为准，若施工发现需改变产品规则，先对齐并更新文档，不借实现自行补充。
- 每阶段只在用户要求时展开该阶段 task，说明具体改动、实施思路和验收映射；不提前生成全阶段施工清单。
- 验证按实际改动选择，不默认运行 `pnpm build` 或堆叠测试文件；若临时编写测试代码，按项目规范使用后清理。需要真实模型、数据库或浏览器验证的行为，不能用静态检查替代。
