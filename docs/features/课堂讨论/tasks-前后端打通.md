# 阶段四：打通前后端

依据 [spec](./spec.md)、[plan 阶段四](./plan.md#阶段四打通前后端)、[阶段二保存恢复](./tasks-聊天保存与恢复.md) 和 [阶段三后端交付](./tasks-LangGraph问答链路.md#交付记录)。本文件只展开第四阶段的接线与基础交互；G1～G5 已按用户授权实施，实际证据与限制见末尾交付记录。不提前展开第五阶段 UI task，不改变 spec、ADR 或全单元交付状态。

## 实施前基础与缺口

- 阶段三已提供普通 JSON 问答接口：POST 保存或恢复问题、领取执行、运行问答并保存完整回复；GET 独立读取，不要求模型配置。已有真实模型 14 项、真实数据库上的受控故障 41 项证据，但未经过监听端口和浏览器联调。
- 页面路径为 `app/classroom/[id]/page.tsx → components/stage.tsx → PlaybackChromeRoot → ClassroomView`。目前没有聊天入口、消息列表、聊天请求封装或会话状态，不能把后端完成视为用户已经可以提问。
- `PlaybackChromeRoot` 持有播放引擎、字幕和教学效果；引擎已有保留计时进度与效果的 pause / resume。课堂刷新通过 `ClassroomSession` 复用未变化的场景对象；聊天不应破坏这个机制。
- `ClassroomSession` 已承担课堂读取、播放位置、测验与后台续生成。聊天采用独立的页面内控制器，复用其生命周期与过期响应保护思路，不再把所有状态加入该类，也不搬入参考项目的前端 Agent 循环。
- 当前请求头来自既有临时配置工厂，正式模型设置页尚未交付。本阶段通过注入现有工厂接线，不增加设置流程、服务端环境变量兜底或密钥持久化，不把本地忽略的配置文件及密钥纳入交付。

## 目标与边界

用户可在真实可播放课堂展开右侧聊天，发送绑定当前场景的问题，看到服务端选择的教师、完整回复和真实来源，并能处理失败、读取核对、显式重试和刷新恢复。

- 基础面板、等待与保存反馈、恢复操作、键盘可用性和窄屏基本布局本阶段交付；不是只做一个能调用 POST 的输入框。
- 使用阶段三已确认的“完整保存后返回”契约，不引入 SSE、流式文本、工具执行进度或浏览器侧模型调用。没有对应后端事件时，不展示推测的教师身份、检索进度或保存百分比。
- 不新增聊天表、服务端状态、checkpoint、队列、轮询、多会话、手动选教师或 PDF 阅读器。既有问答路由、工具、摘要和数据库执行归属保持在服务端。
- 不更改 spec / plan 的承诺，不顺带实现模型设置、重构播放 / 测验，或修复全仓既有类型问题。若发现必须改变接口、保存语义或学习流程，先说明并对齐，再修订 task。

## 请求、状态与恢复约定

以下为本 task 经用户授权实施的接线方案；浏览器的 waiting / unsaved / unknown 等是交互状态，不新增数据库状态。

### 提交身份与配置

- 首次发送时固定 `{ stageId, sceneId, requestId, question }`，question 使用与服务端一致的去首尾空白规则，requestId 在本次提交前生成一次。重复点击和确认未保存后的重试复用原身份、原问题和原场景，不用重试时的当前场景替换。
- 仅明确的新问题创建新的 requestId。临时提交与当前编辑输入分开管理；问题未保存时保留原输入和重试依据，迟到失败不覆盖用户后来输入的内容。未发送 / 未保存内容不承诺跨刷新恢复。
- 发送与显式继续 / 重试时取得当次配置快照；有库可携带现有向量配置，但不在前端强制要求它存在。缺配置也应允许后端按现有契约保存问题并返回真实状态，不能在请求前误拦截已有结果恢复。
- 只提交规定的身份与问题字段，不上传整个课堂、测验隐藏字段、历史、教师、回复或来源。所有模型、工具、记忆和完成写回仍由 POST 处理。
- 成功与错误响应都校验外壳和记录：课堂、原场景、requestId 或 turnId 必须匹配本次操作。不能因 HTTP 200 或 success 为 true 就把 pending / processing / failed 显示为回答完成。

### 按服务端状态提供操作

- **completed：** 展示已保存的完整回复、教师和来源；读取或重复提交恢复同一记录，不再生成。只有此状态可标记完整回复已保存。
- **pending：** 问题已保存，尚未开始执行。提供用户显式继续入口，使用该记录的原始 submit 载荷和 requestId 再次 POST；不能调用要求 expectedExecutionId 的 retry 分支。
- **processing 且未过期：** 展示问题已保存、问答处理中；原 POST 仍在途则等待其响应，否则提供读取当前记录。不发第二个执行请求，不因本地等待超时宣称数据库已失败。
- **failed 或 processing 已过期：** 保留问题并提供显式重试。先读取本轮最新记录，再以 `{ action: "retry", stageId, turnId, sceneId, expectedExecutionId }` 提交；若已完成则直接恢复，若有有效执行则只展示，不重试。
- **questionSaved 为 false：** 提示问题未保存，保留输入 / 原提交，允许用户按原身份重试。身份冲突不能作为普通未保存问题无限重发，应先读取核对并说明冲突。
- **SAVE_UNKNOWN、网络中断、响应无法校验或 questionSaved 为 null：** 提示结果待确认，已知 turnId 按轮次读取，否则按 stageId + requestId 查找。读取失败保持未知，不把空列表、超时或取消当成已回滚；原请求仍在途时尤其不能用一次未查到记录认定未保存。核对后恢复已有记录；可明确重新提交时仍沿用原身份，不自动生成。
- **回复保存结果不明：** 即使 questionSaved 为 true，也不能把本轮显示为完整成功。先 GET 核对；仍 processing 时保持待确认 / 等待，已失败或过期后才允许显式重试，不承诺恢复未落库文本。
- 当前请求中的具体配置、工具、能力和超限原因按安全错误码展示；刷新后只能从持久记录恢复失败大类，不编造数据库未保存的详细原因。来源为空不自动等同“检索无命中”，以后端回答与失败响应为准。

### 历史、并发与生命周期

- 聊天首次展开读取该课堂完整已存历史；再次展开和用户点击读取只发 GET。刷新后的未完成记录保持原状态，任何读取都不调用 POST，不自动续跑。读取失败保留已显示记录和输入，不能显示为“没有历史”。
- 同课堂历史按服务端 `(createdAt, id)` 顺序组织，每轮以 turnId / requestId 去重；本地待确认提交与读回记录合并，不能追加成两个问题。显示场景标题从该轮 sceneId 对应的课堂目录取得，不从当前活动场景推导；目录暂缺时保留身份并显示可辨认的回退标识。
- 控制器按课堂存活，不随面板收起、切场或后台内容刷新重建。同页收起 / 切场不主动取消已有问答请求，结果仍合并回原问题；离页 / 切课时中止页面请求并隔离晚到结果，不承诺中止即数据库回滚或离页后必然完成。
- 用页面 epoch、读取序号和每轮写入修订保护异步合并；同轮在途操作防重复，旧 GET / POST / finally 不覆盖较新的执行或已完成结果。多个在途轮次各自维护状态，不把某轮返回文本写入全局“最后一条回复”。
- 连续追问消费服务端已保存历史；不在前端把未完成轮次拼成已完成对话。并发时沿用阶段三固定历史快照，显式重试按新的领取时间取快照，页面不作相反承诺。
- 本阶段不新增轮询；正常 POST 返回完整结果，其他页面执行或丢失响应通过用户读取核对。executionExpired 以最新服务端读取为准，本地计时只提示重新核对，不授予执行权。

## 基础界面与播放衔接

- 入口由用户主动操作，仅可播放课堂提供发送能力。展开时只对正在播放的引擎调用 pause，保留当前画面、字幕、教学效果和播放运行编号；收起不调用 resume / replay，不因读取历史重建引擎。用户仍可通过已有播放控制手动继续。
- 开关聊天不加入播放 effect 的重建依赖。切场仍遵守既有播放规则，下一条问题取新场景；不额外规定“面板开着就禁止播放”，也不借接线改造切场自动开始行为。
- 桌面在课程区域右侧提供受约束宽度的面板；窄屏采用可收起的同页布局，确保关闭、输入、发送、读取、重试和查看来源可用，不能永久遮挡课程和播放 / 作答入口。细致视觉、动画和完整布局打磨留在第五阶段。
- 消息按轮次显示用户问题、发送时场景、实际教师和回复；等待与失败独立展示，不预置一位教师冒充已完成路由。输入支持多行，先使用明确的发送按钮，保留 Enter 换行与中文输入法组合输入，不新增容易误触发的快捷发送规则。
- 回复和来源先以 React 文本安全展示，保留换行与长文本滚动，不把模型 HTML / 代码作为可执行内容；不为 Markdown / 高亮额外引入依赖。来源按本轮 sources 顺序对应引用编号，至少显示文档名、可用页码和 excerpt；无页码不伪造，无来源不生成占位引用。不承诺打开尚不存在的 PDF 预览地址。
- 使用现有主题 token、图标按钮和可访问名称；面板开关有展开状态，打开后输入可聚焦，关闭后焦点可返回入口。状态同时有文字，不只靠颜色；异步状态变化不抢焦点。输入与引用区域的键盘操作不能触发课堂全局播放 / 切场快捷键。
- 聊天错误独立于课堂、位置保存、测验和后台生成提示，不用全局遮罩阻塞观看；聊天刷新不调用 session.replay / selectScene，不清空作答草稿或改变续生成目标顺序。

## 完成标准与验证

- **真实浏览器与数据库：** 在实际 HTTP 服务上展开、发送、接收、核对完整落库、收起、切场、刷新和再次进入。验证三种教师身份、连续追问、无 PDF、有 PDF 引用、来源展开和无命中反馈；历史恢复即使缺模型 / 向量配置也不调用模型。阶段三的直接 Route 测试不能替代本项。
- **播放和课堂回归：** 正在讲解时展开能暂停并保留字幕 / 效果，收起仍暂停，手动继续不从头重播；当前场景结束、原本暂停和全屏时也可使用。生成中切场、返回、读取历史不清空测验草稿或结果、不重置当前引擎、不调整后台续生成顺序；旧 discussion 不打开面板或发送问题。
- **真实失败和恢复入口：** 无配置时问题保留，补充当次配置后可显式继续；执行失败可重试、完成后再次读取直接恢复。需要资料但缺向量配置时显示查询未完成，而不是无命中。未提交测验提示、已提交 / 待批改讨论不写正式测验结果；语义边界复用后端，页面不得传隐藏数据绕开它。
- **受控异常：** 覆盖问题确认未保存、保存未知、回复保存未知、网络 / 非 JSON 响应、读取失败、有效和过期 processing、执行冲突、重复点击、两个轮次交错返回、旧读取覆盖新提交、切场 / 切课晚到及离页取消。先核对再显式操作；通过数据库计数与记录身份确认不重复追加、不覆盖 completed。故障注入和真实提供商 / 数据库故障分开记录。
- **基础可访问性与安全：** 桌面 / 窄屏、深浅主题下入口和主要操作可用，长问题 / 回复 / 文件名不溢出，键盘焦点不丢失，中文输入不误发送，聊天键盘操作不触发播放快捷键；HTML / 脚本文本不执行。第五阶段仍负责完整视觉细化，本阶段不能用“以后优化 UI”跳过基本可操作性。
