# 阶段二：建立聊天保存与恢复能力

依据 [spec](./spec.md)、[plan 阶段二](./plan.md#阶段二建立聊天保存与恢复能力)、[阶段一交付记录](./tasks-旧讨论清理与访问边界.md#交付记录) 和 [ADR-007 草案](../../adr/adr-007.md)。本文件只展开第二阶段，E1～E6 已按用户授权实施；实际交付及验证边界见末尾记录，规格审查状态不变。

## 目标与实施边界

以一轮问答为持久化单元，可靠保存用户问题、发送时场景及可选的完整教师回复，让重复请求、显式重试、保存结果不明和晚到结果都能以 PostgreSQL 中的记录判断与恢复。

- 阶段一已提供教师只读上下文与课堂／场景归属校验，定向和受控验证通过；真实模型、数据库和浏览器证据的边界仍见阶段一记录，不将其改写为整链路已验证。
- 当前 spec 为 draft、delivery 为 in_progress，ADR-007 为 proposed。实施遵守已确认的功能范围，不自行标记 accepted 或 verified。
- 本阶段不接 LangGraph、教师模型、向量检索、摘要或图 checkpoint，不做右侧聊天及播放接线，不改正式作答、评分、场景生成或播放位置。
- 问题接收与历史读取可独立验证；真实问答执行在第三阶段接入同一请求流程。不会向浏览器开放教师回复写入、执行领取或任意状态修改接口，也不生成占位教师回复充当成功。

## 本阶段的数据与状态约定

- 新增 `ChatTurn`，一轮保存一条用户问题和至多一份完整教师回复，关联课堂与发送时场景；不新增多会话表、消息编辑／删除入口或历史执行列表。重试保留原问题和场景，不追加新的用户消息。
- 以课堂及请求身份识别重复提交：同一身份、相同问题与场景恢复已有记录；同一身份携带不同问题或场景则拒绝。问题比较使用接收时去除首尾空白后的文本，不改写内部文字；不同请求身份的相同文字仍是新的提问。
- 状态为 `pending`、`processing`、`failed`、`completed`。首次问题保存后为 pending；仅领取成功的执行进入 processing。completed 必须同时具有非空完整回复、固定教师身份及引用列表，其他状态不能夹带看似完成的回复或上一次执行结果。
- 每次领取有独立执行身份和有限有效期，使用数据库条件更新确认执行权；本阶段有效期初值为 **180 秒**，作为聊天独立实现常量，不复用测验常量或等同于 Route 的运行上限。第三阶段接入真实模型时核对整轮预算，调整须同步本 task 和相关验证记录。
- 只有当前执行身份、仍在有效期内且状态为 processing 的执行可以完成或失败写回。用户显式重试失败／已过期执行时，基于最新执行身份领取新的执行权；旧执行即使迟到也不能覆盖它。有效期内的执行不被重复请求夺取，已完成记录直接恢复。
- 读取过期 execution 时可计算 `executionExpired`，但不修改数据库、不自动领取、不调用模型。崩溃、离页或刷新后的恢复依据仍是已保存记录，不保证进程继续运行或图断点续跑。
- 回复正文、教师身份与引用在同一次完成写入中保存；引用保存来源身份及展示快照，读取历史不依赖模型或向量服务。密钥、请求头、模型配置、部分输出和推理过程不进入聊天记录。

## 文件范围

以下路径相对仓库根目录。除生成的 Prisma Client 外，新增业务实现集中在所列文件，不为了分层再拆多套接口或存储。

**新增：**

- `prisma/migrations/<实施时生成的时间戳>_add_chat_turns/migration.sql`：聊天记录、唯一性、状态一致性、课堂及场景归属约束和查询索引；只做增量迁移，不重置数据库或改写已有课堂与成绩。
- `lib/types/chat.ts`：一轮记录、提交身份、执行身份、状态、来源快照、读写结果与错误类型；集中定义三名固定教师的稳定标识及职责名称，不生成人设。
- `lib/validators/chat.ts`：问题接收、历史读取和内部执行／写回的校验，严格限定允许字段，防止客户端注入教师回复、状态或模型配置。
- `lib/db/queries/chat.ts`：按课堂查询、幂等接收问题、条件领取执行、当前执行的完成／失败写回；数据查询不处理 HTTP，不调用模型。
- `lib/services/chat.ts`：组织问题接收、归属校验、恢复、执行协调、引用校验与错误映射；内部执行和回复写回能力只供服务端使用。
- `app/api/chat/route.ts`：本阶段提供历史读取与问题接收，不开放回复写入或执行状态控制。第三阶段在此接入实际问答，不要求前端另发保存回复请求。

**修改／复用：**

- `prisma/schema.prisma`：新增 `ChatTurn` 与 Stage、Scene 关联；利用现有场景复合唯一约束保证不能挂到其他课堂，按根实体关系处理课堂删除，不新增独立聊天删除流程。
- `lib/db/queries/chunks.ts`：补充按课堂和明确 chunk 身份读取来源的只读能力，联查文档归属、文档名、页码与片段；不改变现有向量检索语义或提前接工具循环。
- `lib/services/teaching-context.ts`、`lib/services/classroom.ts` 及已有课堂／场景查询：复用场景就绪、定稿和归属规则，按实际缺口做最小只读复用，不将客户端完整场景当作保存依据。
- `docs/index.md`、本 task：维护入口和实施记录；本阶段不自动展开阶段三 task，不手改 Prisma 生成文件。

## 请求入口与内部能力

- `GET /api/chat`：按课堂读取已保存轮次，也可按本课堂的轮次或请求身份核对保存结果；校验参数唯一性和归属，稳定按问题接收顺序排列，同时间点有稳定次序。无记录返回空列表，课堂不存在与读取失败分别反馈，不需要模型配置、不触发任何执行。
- `POST /api/chat`：本阶段接收课堂、发送时场景、请求身份和问题文本，仅在实际保存或恢复已有记录后返回其保存状态。pending 表示问题已保存待执行，不标为教师已回答。现阶段不开放尚无实际执行者的 HTTP 重试操作；第三阶段在同一入口接入提交／重试和图执行，沿用本阶段服务能力。
- `claim / retry / complete / fail` 为服务端内部能力。前端不能上传 teacher、reply、sources、execution 或 status 来伪造完成；第三阶段的图执行通过服务层领取和写回，不直接任意更新数据库。
- 错误至少能区分无效请求、课堂／目标不存在、未就绪、身份冲突、执行仍有效、读取失败、未保存及保存结果待确认。响应清楚表达问题是否已保存、已知轮次身份和可恢复记录；不返回堆栈、密钥或原始请求头。

## 实施顺序

- [x] **E1 — 建立聊天持久化结构与校验。** 增加 `ChatTurn`，集中保存问题、课堂／场景、请求身份、可选完整回复、教师身份、引用、状态、当前执行和必要时间。用数据库唯一性、外键及状态约束补足服务校验；pending 不带旧执行或结果，processing 的执行身份与时间完整，failed 保留问题及可理解的失败类别，completed 的完整回复与教师／引用齐备。生成增量迁移和 Prisma Client，保留已有数据。映射：CD-2、CD-6、CD-9、CD-12 的存储基础。

- [x] **E2 — 接收问题与读取恢复。** 使用已保存课堂与场景核验发送目标，在短事务内幂等保存问题；唯一性冲突后核对身份对应的内容，相同则恢复，不同则报冲突，不按问题文字去重。提供课堂历史及单轮保存结果读取，记录按问题接收顺序稳定返回，不随回复完成或重试重排；普通读取不改变状态、执行或播放位置。失败时区分未保存与结果不明，不清空既有历史。映射：CD-2、CD-9、CD-10、CD-11、CD-12 的接收与恢复部分。

- [x] **E3 — 实现执行归属与显式重试。** 以数据库条件更新／短事务领取 pending 的执行权；重复领取有效执行不产生第二个拥有者。重试失败或已过期执行时，核对调用方持有的最新轮次与执行身份，再生成新执行身份及期限；两个重试竞争只有一个成功，其他恢复最新状态。过期由数据库时间判断，读取不自动改状态。执行过程不占用长期事务，不复制测验单元的表、历史或自动恢复机制。映射：CD-10、CD-11、CD-12 的协调基础。

- [x] **E4 — 实现完整回复、来源与失败写回。** 内部写回核对当前课堂、轮次、场景、执行身份和有效期。完整回复、固定教师身份与实际来源快照原子保存，重复完成恢复已保存结果且不覆盖；旧／过期执行无权回写。来源按本课 chunk 和文档归属读取并组装，不信任传入的文件名、页码或片段作为事实；允许无资料回答保存空引用，非法或跨课来源拒绝。失败保留问题，不能留下半完成回复或虚构成功；写回结果不明时先核对数据库。映射：CD-6、CD-9、CD-10、CD-12 的回复保存部分。

- [x] **E5 — 接通读取与问题接收入口。** 接入上述 GET／POST，严格拒绝客户端的教师回复与执行控制字段，普通读取和问题保存不要求对话／向量配置，不调用模型。响应使用本阶段类型与校验，状态对应数据库事实；保留原课堂读取、位置保存、测验与生成入口行为。明确 pending 的阶段含义，第三阶段接图后沿用同一业务入口，不让前端额外请求保存回复。映射：CD-2、CD-9、CD-10、CD-11、CD-12 的 HTTP 基础。

- [x] **E6 — 验证真实保存、竞争与恢复。** 在独立标识的临时课堂和场景中，核对迁移、保存、读回、并发提交与领取、失效重试、旧执行晚到、引用归属和异常恢复。实际数据库验证与受控失败注入分别记录，清理仅限本轮临时数据和验证代码；回填完成项、实际文件、检查结果与未覆盖项，不宣称 LangGraph、教师问答或浏览器联调已完成。映射：本 task 全部验收范围。

## 验证与完成标准

以下为本阶段的验证要求；已执行项目与证据边界见交付记录。

- **增量与关联。** 检查并应用本阶段新增迁移，生成 Client；旧课堂、场景及测验记录仍可访问。用真实 PostgreSQL 验证请求身份唯一、跨课堂场景关联拒绝、各状态必填／空值约束，不用内存替身代替数据库约束证据。
- **幂等与排序。** 并发相同请求只形成一轮，相同身份不同内容或场景拒绝；不同身份相同问题允许保存。重复读取、回复完成和重试不改变问题的历史顺序，已完成回复不重复追加。
- **执行与重试。** 并发领取及并发重试只有一个拥有者；有效执行不被重复领取；失败和过期允许显式重试，读取过期记录不续跑。旧执行完成、旧失败回调和过期写回不能覆盖当前记录，已完成记录只恢复、不重跑。
- **回复与来源。** 完整回复及来源原子保存，不能出现“completed 但没有完整内容”。覆盖无引用、合法本课引用、跨课／不存在的 chunk、伪造元数据，以及完成写入失败和响应丢失后的读回。保存归属正确不代表引用支持回答，后者仍由第三阶段验证。
- **读取与权限。** 无模型配置也能保存问题和读取记录；新进程重新读取能恢复已保存内容，GET 不领取、不写回、不改播放位置。浏览器伪造回复、教师身份、执行或状态字段须拒绝；错误及持久记录中无密钥和请求头。
- **异常与隔离。** 覆盖非法身份、未就绪场景、其他课堂记录、数据库读取失败、保存失败和结果待确认；失败不清空用户问题或其他历史，不改正式作答和成绩。不把分页、额外会话管理或历史执行列表加进本阶段。
- **静态与回归。** 对实际修改文件做定向 ESLint、TypeScript 与差异检查；实施前阅读安装版本的相关 Next.js Route 指南。回归阶段一教师上下文与旧动作兼容，原有全仓错误如实标注，不为整仓通过扩展修改。
- **清理与证据。** 临时验证使用明确的课堂、场景及来源标识，完成后只清理这些自建数据；不删除真实课堂或重置数据库。临时测试脚本使用后删除，不默认运行 `pnpm build`、安装依赖或启动服务。运行环境未具备的项目保留待验证，不改成通过。

### 实际改动与入口

- 新增 `20261025090000_add_chat_turns` 迁移及上述五个业务文件；修改 `prisma/schema.prisma` 和 `lib/db/queries/chunks.ts`。复用现有课堂／场景就绪校验，无需改动原课堂、测验、生成或教师上下文服务。

- `POST /api/chat` 仅接收 `{ stageId, sceneId, requestId, question }`，返回 `{ success: true, questionSaved: true, record }`；问题仅去除首尾空白。首次状态为 pending，不代表已回答；同身份恢复原记录，冲突带回已有记录。
- 服务层提供 `claimChatExecution`、`retryChatExecution`、`completeChatExecution`、`failChatExecution`，未开放对应 HTTP 控制入口。重试核对 `expectedExecutionId`；内部完成仅接收固定 `teacherId`、完整 `reply` 和 `chunkIds`，来源展示字段全部由本课数据库联查组装。读取来源不使用向量服务。
- 错误返回安全的 `code / error / questionSaved / turnId / record`。首次核对失败、保存后确认失败分别保留未知状态；写入报错后先读回，不把未保存回复报告为成功。执行权与期限通过持锁后的数据库时间及条件更新校验，事务不跨越未来模型调用。
