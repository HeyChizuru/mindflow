## 发现与修正

- **CD-REVIEW-1：教师缺少未完成批改状态。** `prepareChatContext` 已准备 `pendingGrading`，保护检查也使用它，但 `graph.ts` 没有将该字段放进教师的 `referenceContext`；工具更新后的状态也未明确传给后续教师调用。场景被准入筛选限制时，教师尤其缺少说明当前成绩状态的依据。本轮补齐初始上下文和工具返回后的状态传递，只含原有题目标识、场景及状态，不增加隐藏答案或评分依据。受控断言先复现失败，修复后初始与工具续答两个断言均通过；实际模型随后正确区分已完成单选的 2/2 分与简答 `failed / result: null` 的无成绩状态。
- **CD-REVIEW-2：教师最终回复协议不够醒目。** 实际提供商多次直接返回普通文本，严格 SSE 路径因此返回 `MODEL_UNSUPPORTED`，问题仍保存但没有完整回复。中英文教师提示词补充显式协议，强调正常解释、应用、澄清、拒绝透露答案及未完成批改说明均应通过 `final_answer` 返回，不要求用户指定内部工具。修改后，原先失败的自然语言应用问题和测验边界问题经显式重试完成。图和 SSE 仍拒绝不合规输出，没有增加透明模型重试或伪装流式的文本降级；这些样例不构成成功率保证。

实际修改仅涉及 `lib/chat/graph.ts`、`lib/prompts/templates/chat-teacher/system.md`、`system.zh-CN.md`，以及本验收记录、spec、plan 和文档索引。各阶段 task 保留原交付时间和证据，不追溯改写成最新全单元验收。

### PostgreSQL 与图链路

**25 项检查通过：** 使用真实 PostgreSQL、实际聊天 / 会话服务与图，模型决策为受控依赖。覆盖并发同身份问题只保存一条、身份冲突和错课堂拒绝、单一执行领取、伪造引用与旧执行拒写、完成事务提交回执丢失后的读取核对、完成去重、已完成不再领取、同课堂会话记忆隔离、重试更换执行及旧执行不能完成。

删除竞争通过实际 PostgreSQL 父会话行锁协调：删除提交后，等待中的完成写回被拒绝；会话及聊天不复活，课堂与其他会话仍在。回执丢失由临时进程在真实事务提交后注入异常，不能称为数据库崩溃或真实网络丢包。

图检查覆盖普通正文增量、受保护正文不提前外发、初始与工具续答的批改状态传递、保护拒绝，以及资料工具 / 检索次数和取消的硬边界。未改变正式测验记录。

### 真实 HTTP、模型、PDF 与数据库读回

- 在 3001 服务上，三个自建课堂完成 **12 条实际模型完整回复**并入库，涵盖三位教师、自然语言应用问题、连续追问换讲法、同课堂独立会话、无 PDF、普通 PDF 流式、受保护 PDF 问答、测验提示和未完成批改说明。受控写入的“另一会话问题”不计入实际模型回复。
- 实际使用 `deepseek-flash` 和现有向量配置，通过当次请求头传入；应用没有增加环境变量兜底。自然问答曾多次因未返回最终工具失败，资料路径也曾达到执行上限，均保留原问题、无完整结果，并通过用户式显式操作恢复；不将这些尝试计作首轮成功。
- PDF 为本轮自建的一页英文测试文件，包含唯一事实：MF-CD-27 协议预热 **137 秒**。实际完成文件上传、解析、真实 1024 维向量入库和 PostgreSQL 检索；普通与受保护回复的来源文档、页码 1、片段和完整正文经读回核对。不是手工插入正文 / 向量的资料夹具，也不代表任意 PDF 解析质量已验证。
- 普通路径在完整 `answer` 之前取得 `delta`；受保护路径没有提前 `delta`，经校验后返回完整正文，再由前端逐字显示。来源只有在完成后与记录一起确认。
- **7 项补充 HTTP 检查通过：** 已完成 SSE 无配置恢复且没有 start、缺对话配置仍保存 pending、拒绝客户端注入教师、错课堂会话拒绝、原问题显式继续完成、缺向量配置明确 `TOOL_CONFIG_MISSING`、继续后原请求仍只有一条记录。缺向量配置的失败记录没有伪装成无相关资料。
- 简答通过正式接口保存后因缺模型配置批改失败，`result` 为空；这验证的是已保存但未完成批改的状态，不称为 pending 或成功判分。修复后的真实回复没有虚构简答得分，也没有改写单选成绩或简答状态。
