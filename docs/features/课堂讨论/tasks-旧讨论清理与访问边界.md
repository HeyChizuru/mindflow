# 阶段一：清理旧讨论路径与访问边界

依据 [spec](./spec.md)、[plan 阶段一](./plan.md#阶段一清理旧讨论路径与访问边界) 和 [ADR-007 草案](../../adr/adr-007.md)。本文件只展开第一阶段，所有任务尚未实施；编写 task 不代表开始修改代码，不改变 spec、ADR 或交付状态。

## 目标与边界

取消首场及后台续生成中的新 `discussion` 动作，旧动作读取保持兼容、播放时跳过；建立教师专用的只读课程上下文，按课堂归属与测验提交状态控制可取得的内容，为后续聊天与工具调用提供基础。

- 当前 spec 为 draft、ADR-007 为 proposed；正式实现前核对审查状态和本阶段范围，不自行标记 accepted。
- 保留原有讲稿、聚焦、激光、组件动作、暂停继续、下一段、重播、切场、场景恢复、正式测验及后台续生成职责。
- 本阶段不建立聊天表、聊天接口、模型路由或 LangGraph 图，不调用教师工具或向量检索，不接右侧聊天 UI；聊天展开后的暂停衔接留到阶段四。
- 不修改已有场景数据，不执行迁移，不删除历史 plan/tasks/验收记录；不扩展为整仓未使用文件、英文模板或开源残留清理。

## 当前代码依据

- `lib/prompts/loader.ts` 实际加载 `system.zh-CN.md` / `user.zh-CN.md`，本阶段只调整当前 `slide-actions` 与 `quiz-actions` 的四份模板。
- `parseActionsFromStructuredOutput` 当前使用可接受 `discussion` 的共享校验；`createSceneSchema` 与 `sceneSchema` 也共用动作约束。需要区分新生成／新保存与旧记录读取，不能直接从公共读校验中删掉旧动作。
- `generateSceneActions` 被首场与后续场景复用；其 `processActions` 仍给讨论动作补选 Agent。统一修改该链路，不为首场与后台各建一份规则。
- `PlaybackEngine` 仍维护讨论延时、触发与等待继续，播放外壳、字幕、视图类型和静态预览仍消费讨论状态，须一起解除。
- 课堂完整读取包含题目 `answer`、`analysis`、`commentPrompt` 和讲稿／组件状态等内容；多处 schema 允许额外 JSON 字段。只删除几个已知字段不足以建立教师读取边界，应按允许字段重新组装上下文。

## 文件范围

以下为实施时的预计范围，路径相对仓库根目录；不要求每个引用文件都产生 diff。若需要扩大到新的业务职责，先说明与本 task 的关系。

- `lib/services/teaching-context.ts`：只读加载与上下文投影，复用已保存课堂、定稿、场景及测验记录；当前场景与其他已就绪场景共用归属和可见性规则，不暴露 HTTP 入口。

**调整现有文件：**

- `lib/types/action.ts`、`lib/validators/actions.ts`、`lib/validators/scenes.ts`：保留旧动作的领域类型与读取兼容；为新生成和新场景保存建立不接受 `discussion` 的约束。
- `lib/generation/action-parser.ts`、`lib/generation/scene-generator.ts`：新动作输出使用新约束，移除讨论 Agent 补选分支，保留其他动作顺序、完整性和目标校验。
- `lib/prompts/templates/slide-actions/{system,user}.zh-CN.md`、`lib/prompts/templates/quiz-actions/{system,user}.zh-CN.md`：移除讨论动作的指令、示例和引导，保留教师单一讲稿与支持的教学动作。
- `lib/playback/engine.ts`、`lib/playback/types.ts`、`lib/playback/derived-state.ts`：旧动作跳过，解除讨论计时、触发回调和等待状态；保留正常讲解的计时与生命周期。

- `components/canvas/canvas-toolbar.tsx`、`app/classroom/static-preview/preview.tsx`：移除讨论专属状态及预览项，保留既有播放操作与其他页面预览。

**复用／核对，按需做最小调整：**

- `lib/services/classroom.ts`、`lib/db/queries/{stages,scenes,quiz}.ts`、`lib/types/{scene,classroom,outline}.ts`：复用读取、归属及完整性校验；必要时只补只读查询的复用能力，不改位置保存、正式作答与评分生命周期。
- `lib/action/engine.ts`、`lib/playback/index.ts`、`lib/hooks/use-i18n.ts`：仅核对受影响类型、导出及讨论专属文案的消费者，按实际引用做最小修正，不删除其他教学动作或公共翻译。

## 实施顺序

- [ ] **D1 — 分开新动作约束与旧场景读取。** 新模型动作解析、新场景组装和新写入均拒绝 `discussion`；已保存场景继续经兼容读校验恢复。模型仍输出旧动作时明确返回动作校验失败，不静默删掉该项后伪装完整生成成功。保留讲稿必填、动作 ID 唯一、目标归属和其他合法动作校验；不改旧记录、不重新生成已有完整场景。映射：CD-13，关联 CF-2、BG-4。

- [ ] **D2 — 收掉实际生成提示与讨论 Agent 补选。** 调整当前四份中文动作模板，移除讨论示例、频率规则及“用讨论动作承接学生发言”的指令；保留正常讲稿、聚焦、激光与组件动作要求。清理 `processActions` 中仅为讨论动作选择 Agent 的逻辑，不借此重写其他生成上下文、教师画像、Director 或未接入模板。核对首场与后台仍走同一动作生成规则。映射：CD-13，关联 CF-2、BG-4。

- [ ] **D3 — 旧动作直接跳过，解除播放与展示接线。** 播放遇到旧 `discussion` 时按保存顺序继续到下一个合法动作，不等待讨论延时、不产生话题回调、不暂停。末尾旧动作正常进入本场结束，连续旧动作不得导致递归溢出或卡住。移除仅服务讨论的计时、触发、继续入口及页面展示状态，静态预览同步调整；保留用户主动暂停、继续、下一段、重播、切场与旧播放清理行为。映射：CD-13，关联 CP-3、CP-4、CP-5。

- [ ] **D4 — 建立教师专用的只读上下文。** 新服务根据服务端读取的课堂、定稿与场景准备课程需求、可选学习者信息、授课语言、课程结构及所需场景信息；拒绝无效身份、不属于本课、尚未就绪或与定稿不一致的目标，区分读取失败与内容不存在。当前场景与其他场景共用同一入口规则。按允许字段组装返回值，避免透传额外 JSON、原始完整课堂对象、PDF 全文、存储路径或模型配置；不修改已有播放读取契约，不调用模型、不发起写入。映射：CD-4、CD-12 的基础部分。

- [ ] **D5 — 按已保存提交状态投影测验内容。** 无已保存提交时只提供题目、题型、必要选项等答疑信息，不返回标准答案、完整解析或隐藏评分依据。按题逐一判断，不能因同场一题已提交就放开其他题。已有提交时可提供该题已保存答案及可用反馈；未完成批改不构造分数、成功状态或评语，不将原始 `commentPrompt` 作为普通工具返回内容。测验场景不原样透传讲稿与动作、组件状态／标注或额外字段，防止通过旁路带出隐藏内容；投影不修改原始场景与提交。映射：CD-8、CD-12 的课程读取基础。

- [ ] **D6 — 集中核对并回填交付记录。** 验证新动作拒绝、旧动作读取和跳过、正常播放连续性、不同题型和提交状态的上下文，以及跨课堂与未就绪目标拒绝。记录后续历史选择、资料工具和模型回答仍需验证的边界；回填实际改动文件、完成项、检查结果及未覆盖项，不以本阶段完成宣称聊天或 Agent 问答已交付。映射：CD-4、CD-8、CD-12、CD-13 的本阶段部分。

## 验证与完成标准

以下为获准实施后的验证要求，本次编写 task 不执行这些运行验证。

- **生成与旧记录兼容。** 用受控完整动作输出核对：包含 `discussion` 的新输出／新写入失败，合法讲稿与其余动作仍保序通过；包含旧动作的已存场景仍能读取，已有完整场景仍按原规则恢复。实际模型生成与数据库读回证据另行记录，受控解析通过不能代替真实生成。
- **旧动作播放。** 覆盖“讲稿 → 旧讨论 → 讲稿”、末尾旧讨论、连续旧讨论，以及暂停继续、下一段、重播和切场；确认无话题、无强制暂停、无残留讨论定时器，其他教学效果与场末停留保持原行为。引擎验证与浏览器验证分别记录。
- **教师上下文。** 覆盖 slide、单选、多选、简答；同场部分提交；无提交、待批改、批改中、失败和已完成记录。检查必要课程内容可读、未提交题隐藏字段及额外 JSON 不外泄，未完成批改无虚构结果，输入对象与数据库记录不被投影修改。
- **只读与隔离。** 核对不同课堂的场景和提交不能混用，草稿、首场未就绪、目标未就绪、非法身份和读取异常可区分；当前与其他场景使用相同访问规则，无模型、向量调用或正式数据写入。
- **静态检查。** 对实际修改的实现文件做定向 ESLint 和 TypeScript 检查，审阅 diff 与 `git diff --check`；若存在基线错误，说明与本次改动的关系及验证范围，不为整仓通过扩大修改。实现前按 AGENTS.md 阅读安装版本的相关 Next.js 指南。
- **证据边界。** 本阶段落实的是新旧动作边界和课程上下文的字段级访问规则。历史消息与摘要尚未接入，资料正文也可能在语义上包含解题内容；阶段二、三必须在实际历史选择、检索工具与模型回答中继续执行和验证 CD-8，不能仅凭删除字段宣称完整防答案泄漏已验收。

不默认运行 `pnpm build`、新增长期测试文件或启动服务；必要的临时验证代码使用后清理。需要实际模型、数据库或浏览器的验证在运行条件具备后执行，未执行的部分如实记录，不改成已通过。
