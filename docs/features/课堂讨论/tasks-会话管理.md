# 阶段四补充：会话管理

依据 [spec](./spec.md)、[plan 本阶段](./plan.md#阶段四补充会话管理)、[阶段二保存恢复](./tasks-聊天保存与恢复.md)、[阶段三后端](./tasks-LangGraph问答链路.md) 和 [阶段四联调交付](./tasks-前后端打通.md#交付记录)。用户已确认功能规则并授权实施，H1～H5 已完成本阶段范围的实现与验证，证据及边界见[交付记录](#交付记录)。不展开阶段五 UI 或阶段六 task，不将本阶段交付等同于整个课堂讨论验收完成。

## 实施前基础与缺口

- `ChatTurn` 已保存问题、执行身份、完整回复、教师和引用，但没有会话归属；幂等键目前为 `(stageId, requestId)`。`readChatTurns` 和 `readAnswerHistory` 均按课堂读取，同课堂新会话不能直接复用现查询而声称记忆独立。
- `lib/services/chat.ts` 已用短事务、行锁和条件更新协调领取、重试与写回；`lib/chat/answer.ts` 负责完整保存后返回，LangGraph 负责有界问答。增加会话身份与存在性校验，不另写一套执行循环。
- `ClassroomChat` / hook 按 stageId 创建，已具备稳定提交身份、未知结果核对和过期响应保护；现有消息与面板可复用，尚无会话列表、创建、删除或 URL 选择状态。
- `/classroom/[id]` 当前以 stageId 为 Stage 的 key；同课堂换会话应只切聊天，不把 sessionId 加进该 key，也不改变播放、测验及后台续生成的控制器归属。已有前四阶段证据不覆盖本阶段。

## 已确认规则与范围

- 新建会话固定关联创建时显示的课堂，同课堂可有多个会话；新会话不继承其他会话的历史或摘要。课堂资料和正式测验状态仍属于课堂，不复制成会话独有数据。
- 列表可选择其他课堂的会话，展示所属课堂；打开时切回关联课堂，不使用原页面的场景发问。
- 各课堂已有聊天归入一个“历史会话”，保留原记录及执行状态；没有旧聊天的课堂不创建空历史会话，不重新生成或自动续跑。
- 刷新保持当前选择；普通进入课堂且无明确选择时，恢复本课堂最近使用的会话。没有会话则显示空态，必须用户主动新建；读取失败不当作无会话。
- 二次确认后永久删除会话及聊天、引用关联和执行记录，不删除课堂、场景、PDF 或正式测验。删除当前会话后保留课堂并回到未选择空态；删除非当前会话不改变当前聊天。空态刷新后仍不自动选中其他会话。
- 保持无登录、当次请求配置、只读工具、临时摘要及完整回复保存后返回；不引入私有账号、跨会话学习档案、SSE、轮询、checkpoint、任务队列、模型设置或提供商适配。复杂排版和视觉细化仍在阶段五。

## 数据与迁移约定

- ChatSession 保存服务端生成的 UUID、固定 stageId、是否历史会话及创建 / 最近使用时间；列表返回足够辨认会话和所属课堂的元数据，不为列表加载全部聊天、不用模型生成标题、不保存密钥。最近使用按创建、用户主动打开或新问题首次保存更新，模型晚到回复、重试及普通 GET 不改变它；相同时间以稳定身份排序。无登录下不是每个用户独立的最近使用记录。
- ChatTurn 的 `(sessionId, stageId)` 外键指向会话，原 `(sceneId, stageId)` 场景外键保留；同轮去重采用 `(sessionId, requestId)`，历史索引按会话与 `(createdAt, id)`。不能只在界面过滤、允许数据库出现错配记录。
- 增量迁移先创建会话结构，为确有旧聊天的各课堂各建一个历史会话，再回填 sessionId、验证归属并施加 NOT NULL / 外键 / 唯一约束。原 turnId、requestId、场景、文本、来源、状态、执行身份、时间及顺序不改写；过期与否仍由数据库时间推导，不在迁移时宣称执行失败。
- 迁移前后按课堂记录数及原字段快照核对，包含未完成轮次。先在临时数据库或隔离测试库演练，确认无丢失后再执行批准的开发库迁移；禁止用 db:push、重建表或重置数据库代替增量迁移。
- 升级时停止旧版聊天写入，再应用迁移 / 生成 Client 并启动新服务，避免旧实例继续写无 sessionId 的记录。新请求必须显式携带 sessionId，缺少时安全拒绝，不偷偷创建默认会话或把新问题归入历史会话；本 task 不承诺旧客户端在线滚动兼容。

## 服务端接口与执行约定

- `GET /api/chat-sessions` 返回跨课堂可选列表，可按 stageId 筛选本课堂默认候选；`GET /api/chat-sessions/[id]` 核对特定会话是否存在及其真实关联课堂。读取严格无模型、无创建、无最近使用时间更新，不把读取错误返回成空列表。
- `POST /api/chat-sessions` 仅接收当前课堂身份，校验课堂可用后创建并返回服务端新分配的 sessionId；不接受调用方指定旧 sessionId，也不通过 upsert 恢复不存在的会话。前端禁止重复点击和透明自动重发；创建响应丢失先提示待核对并读取列表，不把未知当作失败后自动创建第二个会话。
- `POST /api/chat-sessions/[id]/open` 校验关联课堂并记录用户主动打开；不读取模型配置、不发问、不改播放位置。自动默认选择和刷新恢复仅 GET，不因读取把列表不断重排。
- `DELETE /api/chat-sessions/[id]` 以原会话及关联课堂为目标，在事务中永久删除父会话并级联其轮次；删除不存在的目标可幂等返回已不存在，不接受“删除课堂”语义。响应丢失先按原身份读取核对：已不存在则完成本地清理，仍存在可显式重试，读取失败保持未知。
- 现有 `GET /api/chat`、提交问题、pending 继续和 retry 均增加 sessionId；服务端同时核验会话、课堂、场景、轮次和执行身份。已完成仍直接恢复，不要求模型配置；会话不存在与“会话存在但没有这条消息”须可区分，不能把会话不存在当作允许重发的空历史。
- 所有消息修改事务先锁定并验证会话父行，再核对 / 锁定轮次，与删除串行协调；提交需要调用现有 `getLockedPlayableScene` 时，先完成其课堂 / 场景锁定，再进入会话和轮次锁定，禁止反向申请课堂锁。涉及课堂删除的级联一并核对锁顺序，模型 / 向量调用期间不持锁。写回先完成时，随后删除也会清除该结果；删除先完成时，迟到的 submit / claim / retry / complete / fail 均不能插入或重建会话。数据库外键与条件更新兜底，不仅靠 AbortController。
- 未知写入的补读同样携带原 sessionId。确认会话不存在时返回明确不可用状态，不回传此前缓存的完整记录作为可恢复成功，不自动创建、不重试模型；暂时读失败仍为未知，不推断已经删除。错误码、响应校验和文案一起适配，不泄露密钥或堆栈。
- `readAnswerHistory` 在数据库查询中限定当前 sessionId，保留现有“此前接收且在本轮领取时已经完成”的快照边界；筛选、临时摘要与原文展开都只消费这一集合。课程 / PDF 仍按关联课堂安全读取，未提交测验保护覆盖历史和工具；不在前端提交整份历史或隐藏测验字段。

## 前端选择与异步约定

- 使用 `/classroom/[stageId]?chatSession=<uuid>` 保存选中身份，`chatSession=none` 明确表示未选择，参数缺省才按本课堂最近使用会话恢复。URL 只记录选择，不作为会话存在性、课堂归属或用户权限的证明；重复 / 非法参数明确报错，指向已删除会话时清理选择并提示，不默默打开另一个会话。
- 当前选择解析并读回成功后，用 replace 补齐 URL，保证刷新仍选同一会话；空态也明确写入 none，不因刷新而自动选中其他会话。无活动会话时展示列表 / 新建入口，不允许发送或暗中创建。按安装版 Next.js 指南处理 useSearchParams 的 Suspense 边界，不以查询参数变化重挂 Stage。
- 跨课堂选择先取得服务端会话与目标课堂的有效信息，再导航到关联课堂并携带 sessionId 和面板展开意图；失败保留可理解错误，不把目标会话与原课堂画面混用。地址只从校验后的 UUID 拼接，不使用模型文本或任意外部 URL。页面内及浏览器前进 / 后退都重新核对目标，不对旧链接恢复已删除数据。
- 分离列表生命周期与消息生命周期；消息、草稿和未确认提交按会话分区，不沿用一个全局 items / draft。切会话使旧操作失效并按页面生命周期中止请求，回到原会话先读取已保存状态，不自动续跑；未保存内容仍不承诺跨课堂离页或刷新恢复。收起聊天与同会话切场继续沿用原阶段四规则。
- 继续使用 epoch、列表读取序号、每会话修订与删除操作标识；旧 GET / POST / error / finally 不覆盖新选择或删除结果。删除中阻止目标会话的新发送和重试，删除未知时保留待核对状态；只有确认删除成功 / 已不存在才从列表移除并清理其本地消息和输入。
- 删除成功提升相应读取版本，过滤在删除前发出的列表 / 消息响应；删除 A 期间若用户已选 B，A 的完成回调不得清空 B。删除非当前会话不清空当前聊天；另一页面删除通过下次读取明确反馈，不新增跨标签同步或轮询承诺。
- 同课堂换会话和删除只影响聊天状态，不调用 replay / selectScene 或重置测验输入；打开聊天仍暂停并保留字幕，关闭不自动恢复。跨课堂离页沿用原生命周期及已保存播放位置，不承诺跨课堂保留未保存的测验草稿。
- 复用现有 Popover 二次确认模式，写清永久删除目标与范围；创建 / 删除待处理防重复，读取失败与空态分开。列表、新建、选择和确认可用键盘及窄屏操作，删除按钮有名称及 Tooltip，状态不只靠颜色；不执行模型 HTML，不进行全局 UI 改造。

## 完成标准与验证

- **迁移与约束：** 在演练库覆盖多个课堂及 pending / processing / failed / completed 旧轮次，比较迁移前后原字段与数量、每课堂历史会话数量；验证跨课堂 session / scene 错配插入被拒绝。迁移后读取不调用模型、不更换执行身份、不改历史顺序，无记录课堂不产生空会话。
- **真实数据库并发：** 覆盖问题插入、领取、完成 / 失败写回与删除两种先后顺序，以及删除响应丢失后的核对；删除后使用原 sessionId 的提交、重试和写回均不复活记录。分别核对目标消息为零、其他会话记录与课堂 / 场景 / PDF / 测验未被删除，不以 HTTP 成功或列表消失代替数据库证据。
- **真实模型与记忆：** 同课堂 A / B 两会话先在 A 建立专用例子，再对 A 连续追问、在 B 提相同指代，结合查询候选与模型输入检查 B 未取得 A 聊天；跨教师延续仅限本会话。用足够长的自建对话实际触发摘要并检查来源会话，单靠“模型没复述”不能证明隔离。回归无 PDF、有 PDF 的实际引用，以及未提交测验保护；原阶段三证据不替代新 sessionId 链路。
- **真实浏览器流程：** 同课堂新建两个会话、切到另一课堂再新建、从列表打开旧课堂会话；刷新保留选择，普通进入恢复本课堂最近使用会话，无记录显示空态不自动 POST 创建。删除当前会话后课堂不变且刷新仍空态，删除非当前会话不影响当前聊天，取消确认不删除。
