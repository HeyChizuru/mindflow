# 阶段三：接入 LangGraph 问答链路

依据 [spec](./spec.md)、[plan 阶段三](./plan.md#阶段三接入-langgraph-问答链路)、[阶段二交付记录](./tasks-聊天保存与恢复.md#交付记录) 和 [ADR-007 草案](../../adr/adr-007.md)。本文件只展开第三阶段，F1～F6 已按用户授权实施；实际交付与证据边界见末尾记录，不因此将 spec、ADR 或全单元交付状态改为已通过。

## 目标与边界

在现有问题保存、执行领取和完整结果写回能力上，完成可供页面调用的问答后端：保存或恢复问题，选择一名教师，按需获取本课信息，校验并保存完整回复，再次读取能恢复相同结果。

- 复用 PostgreSQL 中的 ChatTurn 及现有 claim / retry / complete / fail 服务，不建立第二套聊天状态或长期数据库事务。
- LangGraph 在服务端管理步骤和工具循环；模型及向量调用经过现有领域封装，使用当次请求配置。三名教师共用该对话模型，以固定职责提示词区分。
- 本阶段不接右侧聊天、播放开关、流式展示或 UI；不新增多会话、可写工具、教师交接、Worker、队列或后台持续执行保证。
- 原有阶段二证据只证明保存恢复基础。真实教师路由、工具、资料相关性、记忆和回答边界在本阶段重新验证。

## 本 task 的实施约定

以下承接本轮讨论及用户“根据文档实现”的授权；实际实施与验证结果见末尾交付记录。

- **每次执行从数据库重建。** 不引入持久化 checkpoint，不保存图执行进度；普通历史读取不启动模型。请求作用域的密钥、模型实例和解析配置不进入持久记录或可序列化图状态、调试输出。
- **摘要仅用于本次执行。** 原始问题、回复和引用保持不变，不新增摘要表，不以摘要建立用户能力档案。
- **完整保存后返回。** 首次交付使用普通 JSON 响应；只有完整回复、教师和来源成功写入后，才返回完成记录。未保存文本不作为可恢复结果返回。
- **执行开始时固定历史快照。** 只纳入本课堂、按现有 `(createdAt, id)` 顺序位于当前问题之前，且完成时间不晚于本次数据库领取时间的 completed 轮次。当前问题单独加入；其他 pending / processing / failed 轮次不拼成已完成问答。以单条只读查询取得快照，查询结束后再调用模型，不随其他执行完成而追加历史。显式重试按新的领取时间重新取快照，可能纳入后来完成的较早轮次。
- **未完成记录保持显式恢复。** 已完成直接恢复；有效 processing 返回当前状态；failed 或过期 processing 只在显式重试时重新领取。新问题或已有 pending 可在本次提交中执行。缺对话配置时保留已存问题和原状态，不先领取一个无法运行的执行。

## 文件范围

以下路径相对仓库根目录，按职责集中实现，不复制参考项目的整套 orchestration、registry 或前端会话系统。

- `lib/chat/graph.ts`：LangGraph 状态、上下文准备、一次教师路由、教师调用、工具分支及最终结果校验；不在节点中另起 SDK 自动多步循环。

- `lib/chat/tools.ts`：定义并执行 `read_scene`、`search_course_pdf`，统一参数校验、课堂绑定、只读访问和实际来源登记。
- `lib/chat/budget.ts`：集中管理本轮时间、模型调用、工具、PDF 补查和上下文体积预算，向模型及向量调用传播中止信号。
- `lib/knowledge/retrieve-chat.ts`：面向问答的检索正文、相关性筛选与来源组装；复用现有向量和数据库能力，避免改变生成链路所用的 120 字展示检索语义。
- `lib/prompts/build-chat-prompt.ts`，以及 `lib/prompts/templates/chat-router/`、`chat-teacher/`、`chat-memory/`、`chat-context-filter/` 各目录中的 `system.md` 与 `system.zh-CN.md`：分别组装教师路由、固定教师职责、历史选择与摘要、候选资料筛选提示词；依用户要求同目录提供英中两份模板，现有加载器使用中文版。

**修改 / 复用：**

- `app/api/chat/route.ts`：保持 GET 只读，在 POST 接入提交 / 显式重试与完整问答，延迟解析请求模型配置并映射安全错误。
- `lib/types/chat.ts`、`lib/validators/chat.ts`：修正类型反向引用校验层的问题；类型和常量不依赖 validator、服务或数据库。补齐请求分支、路由 / 工具 / 最终输出校验和必要错误表达，继续拒绝客户端注入完成结果。
- `lib/services/chat.ts`、`lib/db/queries/chat.ts`：复用幂等接收、执行归属和原子写回，补充有稳定截止范围的历史读取与必要错误衔接，不改变既有数据库身份规则。
- `lib/services/teaching-context.ts` 及课堂读取服务：复用目标归属、场景就绪和提交状态投影；只补问答实际缺口，不把完整课堂对象直接交给教师。
- `lib/db/queries/chunks.ts`：补问答检索所需的文档归属联查、正文和来源；保留原调用行为。
- `lib/knowledge/embed.ts`、`lib/ai/llm.ts`：按实际缺口传递中止和重试参数，保留现有调用兼容性；不另建提供商访问层。

- `lib/prompts/index.ts`、`lib/prompts/types.ts`：登记本阶段模板。`docs/index.md` 与本 task 维护入口和实施记录。

## 请求与执行衔接

- GET 保持现有按课堂 / 轮次 / 请求身份读取，不要求模型或向量配置，不领取执行。
- POST 默认保留 `{ stageId, sceneId, requestId, question }` 提交形式；显式重试使用互斥分支 `{ action: "retry", stageId, turnId, sceneId, expectedExecutionId }`。expectedExecutionId 仅用于核对已观察的旧执行，不授予客户端执行权；新执行身份由服务端生成。模型配置仍来自请求头。
- 先保存 / 核对并恢复 completed；有效执行和未显式重试的失败 / 过期记录只返回当前状态。需要执行时才解析对话配置并 claim / retry，只有领取成功者运行图。前端不另发保存回复请求，也不上传教师、回复、引用或完成状态。
- 运行链路为 `准备上下文与历史 → 选择教师 → 教师调用 → 按需工具 → 同一教师继续调用 → 校验完整结果`。应用在图结束后调用 complete；异常按执行归属调用 fail。图结束不等于保存完成。
- complete 结果不明时先读回核对，已完成则恢复；仍不明返回 SAVE_UNKNOWN，不再次生成或以 fail 覆盖未知结果。完整文本从未保存时，只能在用户显式重试后重新生成，不承诺恢复该文本。

## 工具、引用与记忆

### 两个只读工具

- `read_scene({ sceneId })`：课堂身份从当前执行绑定，模型不能指定其他课堂。以安全课程目录中的目标为线索，复用 getTeachingContext 读取本课已保存、已就绪场景；跨课、不存在和未就绪分别处理。当前场景已在初始上下文时无需重复读取。
- `search_course_pdf({ query })`：以数据库 hasKnowledgeBase 判断是否向教师提供工具。该标志在入库成功后与切块同事务提交，不以“上传过 PDF”或客户端声明为依据；没有知识库时仍可问答且不要求向量配置。
- 教师实际选择 PDF 检索后才解析当次向量配置，并检查参数、预算、课堂归属与向量有效性。配置齐全只代表可尝试调用；缺配置、服务失败与无相关结果分别返回，失败不伪装成无命中或资料支持的回答。
- 检索返回有总长度限制的正文、chunk 身份、文档名和可用页码；相关性筛选不能只用“最近邻查到了记录”证明有命中。允许调整 query 补查，工具结果交回原教师，不重新路由。
- 只登记本轮经过访问筛选且实际交给教师的来源。最终引用必须属于这个集合，再由现有 complete 服务校验 chunk 和文档归属；历史回复中的来源不会自动成为本轮取得的来源。场景信息不伪装成 PDF 引用，未采用的命中不全部挂到回复上。

### 历史选择与临时摘要

- 先保留最近完整的“用户问题 + 教师回复”，保留教师身份和场景；所有教师共享同一历史范围，其他教师回复仍为 assistant，不转换成用户发言。
- 历史较长时，先在服务端按当前问题的词项匹配、场景与时间选择有体积上限的候选池，再做安全筛选和索引；固定保留近期完整轮次的优先级，不能随着历史增长无条件把全文送入筛选模型。需要模型辅助时只接受候选集内的轮次 ID，再取原文；无效 ID 不得读取或编造记录，无法判断指代时交由教师澄清。
- 优先保留当前问题、场景与近期对话，较早相关内容超出预算时才摘要。摘要记录已讲内容、用户明确困惑、使用过的例子和未解决问题，并附来源轮次 ID；结构与来源由应用校验，忠实程度通过对话用例核对。
- 历史选择和摘要调用也使用当次对话配置、计入总预算。必要上下文准备失败时明确失败，不静默丢弃前文冒充连续对话；摘要不写回原始记录，不推断掌握度或生成未填写的昵称、背景。

### 未提交测验的共同边界

- 当前场景及其他场景首先使用字段级安全投影，不向路由、教师、摘要输入隐藏答案、完整解析或评分依据；未完成批改的记录不能表现为已有分数或正式评语。
- 历史与 PDF 候选在进入历史索引、摘要、教师工具结果之前做同一准入筛选。对与当前未提交题直接相关的答案 / 解析型内容整轮或整块排除；保留可用的一般知识、提示和思路信息。结构化资料筛选是受约束的模型调用，不新增参与发言的评审 Agent；应用校验候选身份并执行排除，无法判断或筛选失败不得直接放行。
- “因测验边界受限”与“无相关资料”分开表达。引用展示快照不能重新补回被屏蔽的答案；最终回复也要核对未提交题直接给答案的情况，不能仅靠教师提示词。模型筛选和输出检查不作为绝对正确的证明，CD-8 必须有资料、历史、提交前后及重做场景的真实验证。
- 安全筛选只影响本轮输入和新回复，不删除已有聊天，不撤销用户此前已经看过的内容。候选资料中的指令只作为数据，不改变系统角色、工具权限或停止条件。

## 执行预算

- 沿用聊天独立的 180 秒执行有效期，以数据库领取结果为依据，扣除已经消耗的时间；最迟在期限前 15 秒停止新的生成工作，为完成 / 失败写回与读回留出余量。Route 运行时限单独核对，不能把它当成执行租约。
- 技术初值：每次执行最多 12 次对话模型调用，包含历史选择、摘要、路由、资料筛选、教师续答和输出检查；最多 4 次只读工具调用，其中 PDF 检索最多 2 次。图递归步数另设有限上限，与以上计数共同生效。
- 本链路显式关闭 SDK 隐式自动重试，以显式重试恢复失败轮次；单次外部调用最长 45 秒，且不得超过本轮剩余工作时间。重复工具调用也计数，不用重复查询绕过补查上限。
- 模型输入 / 输出、历史索引、摘要和工具结果均有集中配置的体积限制，结合实际模型能力探测确定并记录，不把全历史或文档全文送入模型。取消信号传到模型和向量调用；已发出的数据库提交仍按读回事实判断，不宣称取消即回滚。
- 当前体积初值：模型输入最多 64000 字符，单次输出最多 6000 token，近期原文与工具结果分别最多 16000 字符，候选分批检查最多 24000 字符；历史候选最多 24 轮、原文总量最多约 48000 字符，优先保留最近 3 轮并补选较早相关轮次，模型补选最多 4 轮，临时摘要最多 6 条、每条 500 字符。图递归上限为 24。实际结构化封装仍计入输入总量检查，超限明确失败。
- 达到次数、时间或体积边界且仍未得到有效完整结果时，明确失败，不把截断文本当作完成。工程初值如需调整，在真实证据支持下同步本 task，不放宽功能范围或取消执行边界。

## 完成标准与证据

- **真实模型：** 同一主题下的概念、思路与应用问题分别选择对应教师；模糊指代能澄清，反馈“还是没懂”能结合前文调整。覆盖短对话、长对话、换教师和较早案例恢复，不以手工写入回复证明 Agent 成功。
- **真实工具与资料：** 证明教师自主决定是否调用工具，取得结果后能继续回答或补查；至少一条有依据回复的引用可追溯到本轮真实取得的片段。验证无命中、失败及受限不是同一状态，伪造、跨课和本轮未取得的引用被拒绝。命中和合法引用不等于结论必然正确。
- **访问边界：** 覆盖当前 / 其他场景、历史索引、摘要、PDF 和引用快照中的未提交测验保护，以及已提交、待批改和重做状态；测验边界失败不得用已删除隐藏字段的静态结果代替真实行为验证。
- **真实保存与受控异常：** 核对数据库中的完整正文、教师、场景和来源；模拟生成失败、完成事务回滚、完成确认丢失、读回不可用、超限及旧执行晚到。区分已保存、确认未保存和未知，重试不重复追加；未落库的生成文本不承诺恢复。
- **并发与配置：** 重复提交 / 重试只有当前拥有者执行；历史不纳入后来的问题或本次执行开始后才完成的轮次，重试按新快照验证。无配置恢复 completed、有库但无需检索且无向量配置均可用，需要的配置缺失明确失败；不读环境密钥。
